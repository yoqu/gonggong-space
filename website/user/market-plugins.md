# Skill 市场与插件

本页讲怎么给 Bot 加能力：在市场里挑选、发布和审核 Skill 与插件，把它们引入到个人、群、仓库或团队；「我的 Skill」；各层的 Skill 与 MCP 管理；插件能带什么、怎么启用，以及插件代码的授权。

- **Skill**：一个含 `SKILL.md` 的文件夹，告诉 Agent 某类任务怎么做，随运行下发给 Agent。
- **插件**：一个含 `gonggong-plugin.json` 的文件夹，可以带 Skill，也可以带创作模板与设计系统、MCP 服务、斜杠命令、画布指令、供应商预设，或接入一种新的 Agent。

Skill 和插件改动后，相关 Bot **下一轮**起生效，不打断正在运行的任务。

## 市场

点左侧栏的「市场」打开（拥有机器或 Bot、担任团队或群管理员的用户才显示这个入口）。

![Skill 市场](/screenshots/web/market.webp)

顶部有几个页签：

| 页签 | 内容 |
| --- | --- |
| 全部条目 | 你能看到的、已审核通过的 Skill 和插件 |
| 引入申请 | 「待我处理」的申请，以及「我的申请」 |
| 我的发布 | 你发布的条目，见下文 |
| 待审核 | 只有审核人能看到，见下文 |

在「全部条目」里可以：

- 按「类型」筛选：全部、Skill、创作、工具、Agent、供应商预设；
- 按「来源」筛选：官方、本团队、公开；
- 按「最近更新」或「引入最多」排序，或搜索名称、描述。

点条目查看详情：说明、文件、版本历史（每个版本的更新说明，可「查看变更」对比上一版），插件还会列出它要的权限和 MCP 服务。已引入的条目标「已引入」，并写明「已引入到：…」。

### 引入

1. 在条目详情点「引入到…」。
2. 在「引入到」里选「我的 Skill」「群」「团队」或「仓库」，再选具体目标。插件不能引入到「我的 Skill」。
3. 在「版本」里选「跟随最新」或「锁定当前版本 rN」。
4. 点「引入」。

| 引入到 | 生效范围 |
| --- | --- |
| 我的 Skill | 只在你发起的运行里生效，跟着你进入所有群；优先于群、仓库、团队的同名 Skill |
| 群 | 这个群的所有 Bot |
| 仓库 | 以它为主仓库的群；优先于团队层，群层可再覆盖 |
| 团队 | 团队里所有群 |

目标旁的标记：

- 「需申请」：你不是这里的管理员，引入会先向管理员提交申请，可填「申请说明」。
- 「同名冲突」：这里已有同名的 Skill，先在那里的设置中移除它再引入。
- 「已申请」：已有待处理的申请，等管理员处理即可。
- 「已引入」：已经引入过了。

管理员在「引入申请 → 待我处理」里通过或拒绝（可写「拒绝原因」，申请人会看到）；申请人可在「我的申请」里撤回。

### 管理已引入的条目

每个引入位置的设置里都有「已引入」列表：「设置 → 我的 Skill」、群设置的「Skill」和「插件」、团队设置等。

- 跟随最新的显示「跟随最新 · rN」；锁定的显示「锁定 rN」，有新版本时提示「有新版本 rN」，可点「升级到 rN」。
- 条目被封禁时提示「已封禁，下一轮起停止加载，建议移除」；被下架时继续使用当前版本，不会再有新版本。
- 「移除」只移除在这里的引入，条目本身保留；「从已有条目引入…」可以不进市场直接引入。

## 我的 Skill

在头像菜单的「设置 → 我的 Skill」里管理。这些 Skill 只在**你自己发起的运行**里生效，跟着你进入所有群，优先级高于群、仓库、团队的同名 Skill。用到时运行卡片上显示「使用了 N 个「我的 Skill」」。

## 发布与审核

### 发布

1. 在「我的发布」里点「发布…」。
2. 选择来源：「选择文件夹…」「选择 zip…」「粘贴 SKILL.md」或「GitHub 链接」。文件夹或 zip 的根目录要有 `SKILL.md`（Skill）或 `gonggong-plugin.json`（插件）。
3. 选可见范围：「公开」或「仅本团队」；填写「更新说明」，审核人和引入者都会看到。
4. 发布前会检查并提醒「请确认没有泄露密钥或本机路径」；和最新上传的版本完全一样时不会生成新版本。
5. 「保存草稿」后「提交审核」，审核通过才会出现在市场。

同一团队里同名即发布为新版本（r1、r2…）。在「我的发布」里还可以：

- 查看每个版本的状态：草稿、待审核、已通过、已驳回（附驳回原因）；
- 「下架」「重新上架」，「设为公开」「设为仅本团队」；
- 从 GitHub 导入的条目可「检查上游更新」，上游有新提交时生成新草稿，或「同步上游更新」。

### 审核

公开条目由平台管理员审核，仅本团队可见的条目由团队管理员审核。审核人在「待审核」页签里：

- 打开版本，查看说明、文件和「对比 rN 的变更」；
- 填写「审核意见」（驳回时必填），点「通过」或「驳回」。

审核人也可以在条目详情里「封禁」（要填原因，维护者会看到）：封禁后所有引入下一轮起停止加载，市场不再显示，也不能新引入。「解封」恢复封禁前的状态。

市场的新版本、审核结果、申请和封禁都会推送通知。

::: tip 桌面端
桌面端的「市场」页可以只读浏览条目、版本与封禁状态，操作时跳到网页端，见 [桌面端功能页面](/desktop/pages)。
:::

## 各层的 Skill 与 MCP

除了市场，Skill 和 MCP 服务还可以按层直接配置，同名时下层覆盖上层：

| 层 | 在哪里配置 | 谁能改 |
| --- | --- | --- |
| 平台层 | 管理后台「配置中心」，见 [配置中心](/admin/config) | 系统管理员 |
| 团队层 | 团队设置 | 团队管理员 |
| 群层 | 群设置的「MCP」「Skill」 | 群管理员（其他成员只读） |
| 个人 | 设置 →「我的 Skill」 | 自己 |

### Skill

群设置 →「Skill」：

- 「添加 Skill…」：上传 `SKILL.md` 所在的文件夹或 zip，名称与描述取自 `SKILL.md` 开头的 frontmatter。文本文件可以在线编辑，每次保存生成一个新版本，可查看历史并「回滚到此版本」。
- 「继承自团队/平台」的 Skill 内容只读；在本群关闭只影响本群。
- 与仓库自带的同名 Skill 冲突时跳过团队版，运行卡片会提示。

### MCP

群设置 →「MCP」：

- 仓库自带的 MCP 配置是基线，平台层、团队层、群层依次叠加，不修改仓库文件。
- 「添加 MCP…」：填名称和传输方式。命令行方式填「命令」「参数」（每行一个）「环境变量」；网络方式填 URL（`http://` 或 `https://` 开头）和「请求头」。
- 环境变量和请求头的值只能引用密钥，写成 `${secret:NAME}`，运行时替换为实值，见 [知识库与密钥](/user/knowledge-secrets)。
- 每个服务可单独启用或停用，继承来的也可以只在本群关闭。
- 共工空间自带的 gonggong 工具（提问、聊天记录、群信息等）始终注入，不受层级影响。
- 保存后，相关 Bot 下一轮**新会话**生效；勾选「强制相关 Bot 下一轮开新会话」可让已有会话立即换用新配置，卡片会提示原因。

Bot 也可以用内置工具帮你查看和修改 Skill、MCP；需要密钥时会发「填写密钥」卡片请发起人填写。

## 插件

![插件](/screenshots/web/plugins.webp)

### 插件能带什么

| 内容 | 用在哪里 |
| --- | --- |
| Skill | 和普通 Skill 一样随运行下发 |
| 创作模板与设计系统 | 输入框的「创作」面板，见 [原型、画布与作品库](/user/artifacts) |
| 斜杠命令 | 输入框的 `/` 候选 |
| 画布指令 | 这个插件做出的作品里，画布「生成」菜单和 `/` 菜单 |
| MCP 服务 | 运行时提供给 Agent，名称为「插件名-服务名」 |
| 供应商预设 | 新增供应商时可选的厂商预设，见 [Agent 工具与供应商](/user/agents-providers) |
| Agent | 接入一种新的 Agent |

内置插件随服务端自动安装：

- 「产品原型」「幻灯片」：创作插件。
- 「Gemini CLI」「CodeBuddy（WorkBuddy）」「pi」「DeepSeek Harness」：Agent 插件，让机器可以运行这些 Agent。
- 「官方供应商预设」：厂商预设随服务端更新下发到所有机器，不用等客户端发版。

### 开启与启用

1. 系统管理员在 [系统参数](/admin/params) 打开「插件」开关（默认关闭）。关闭时不显示任何插件入口，也不向机器下发插件；已上传的插件保留。
2. 插件分三层：平台插件（管理后台「配置中心 → 插件」，对所有团队可见）、团队插件（团队设置，对本团队所有群可见）、群插件（只对本群生效）。同名时群层优先于团队层，团队层优先于平台层。
3. 群管理员在「群设置 → 插件」的「本群插件」里打开开关启用，之后群成员可以在「创作」和 `/` 候选里使用。也可以在这里「上传文件夹…」「上传 zip…」，只对本群生效。

「Bot 可用性」列出本群每个 Bot 能用几个插件。插件下发前会检查 Bot 的机器版本和 Agent 种类，不满足的不下发，并写明原因，如「不支持」「需升级」「缺密钥」。

上传的文件夹或 zip 根目录要有 `gonggong-plugin.json`，同名插件再次上传生成新版本。上传按路径白名单收紧，机器上会清除插件目录里的 hooks、`.mcp.json`、commands 与 agents。

### 插件代码与机器主人授权

带本地 MCP 服务等需要在机器上**运行代码**的插件，还要满足两个条件：

1. 系统管理员在系统参数里打开「插件代码」开关；
2. 机器主人在自己的机器上逐个授权：插件第一次在这台机器上运行代码时，机器主人收到通知，可「允许」或「拒绝」；插件出新版本要重新确认。

授权前，创作面板里这个 Bot 显示「待授权」。机器主人可在机器详情的「插件授权」页签里查看每个插件版本请求的权限（运行代码、访问网络）和 MCP 服务，随时「撤销」，撤销后下次用到时会重新请你确认，见 [我的机器与 Bot](/user/machines)。
