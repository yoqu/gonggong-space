# 审批与提问

本页讲运行中需要人拍板的两种情况：Bot 的权限请求（审批），以及 Bot 向群成员提问；还有决定哪些操作要审批的「审批方式」。

## 权限请求

Bot 要做的操作没有被规则放行时，运行暂停，卡片上出现权限请求，状态变为「等待审批」。

![权限审批卡片](/screenshots/web/approval.webp)

卡片内容：

- 标题「权限请求 · 类型」，类型包括：执行命令、访问网络、写入文件、删除文件、移动文件、读取文件、搜索、其他操作。
- 要执行的**完整命令**或操作对象。超过 400 字或 8 行时折叠，点「展开全部（N 字）」看全文。
- 说明行先写原因，再写倒计时，如「需要写入或修改文件 · 29:41 后自动拒绝，agent 自行绕路」。倒计时圆环在最后 30 秒变橙色。
- 开启了 AI 预审时，附上风险标签（低风险 / 中风险 / 高风险 / 极高风险）和「AI 预审：理由」。
- Agent 同时发了多个请求时，下方列出「还有 N 个请求在等待：」，可以一次「全部批准（N）」。

原因有以下几种：

| 原因 | 说明 |
| --- | --- |
| 高危命令，必须由主人确认 | 命中高危底线，见下文 |
| 可能修改受保护的基准分支 | 群开了「禁止直推基准分支」，命令可能推送到基准分支 |
| 需要访问网络 | 访问网络的请求 |
| 需要写入或修改文件 | 写入、删除、移动文件 |
| 命令较复杂，无法确认是否只读 | 命令解析不了 |
| 未被只读规则或已保存的允许规则覆盖 | 其他没有被放行的命令 |
| AI 预审认为有风险 / AI 预审超时 / AI 预审没有给出结论 / AI 预审未能运行 | 开了 AI 预审，但它没有放行 |

### 谁能批

**只有 Bot 主人**能处理，卡片上写「你是 Bot 主人」。其他人看到「仅 Bot 主人 某某 可操作，你只能查看」。群管理员也不能代批。

| 按钮 | 效果 |
| --- | --- |
| 批准 | 允许这一次 |
| 本次会话不再问 | 允许这一次，并在这个会话结束前不再问同类操作（悬停可看规则） |
| 批准，不再询问 | 允许这一次，并把卡片上「不再询问：…」列出的规则记到这个 Bot 上，之后都自动批准 |
| 本次运行免审批 | 这一轮剩下的请求都不再询问，见下文 |
| 拒绝 | 拒绝这一次，Agent 会自己想别的办法 |
| 全部批准（N） | 有多个请求排队时出现，逐个批准 |

处理后卡片显示结果，如「某某 已批准 · 14:32」「某某 已拒绝 · 14:32 · agent 将自行绕路」。

Bot 主人也可以在运行详情顶部的「待处理」里、通知里直接处理，见 [运行过程](/user/runs#运行详情)。

### 批准，不再询问

只在 Agent 提供该选项、且共工能算出要记住的规则时显示；按钮下方写明范围，如「不再询问：npm run build、tail」。

记住的范围尽量小：

- 命令记**前缀**：取开头最多 3 个普通词，遇到 `-` 开头的参数、路径、引号或 `=` 就停。例如 `npm run build -- --watch=false` 记为 `npm run build`，之后 `npm run build` 加任意参数都自动批准。
- `rm`、`mv`、`sudo`、`sh`、`bash`、`python`、`node`、`curl`、`wget`、`ssh`、`chmod`、`kill` 等危险或能执行任意代码的程序，记**整条命令原文**，参数变了要重新审批。
- 只读命令、工作区内的 `cd` 本来就免审，不会记。
- 非命令的请求（如 MCP 工具、访问网络）记为 `tool:工具名`，只有同名工具自动批准。
- 高危底线和推送受保护的基准分支永远不会被记住。

规则存在 **Bot 上**，对这个 Bot 所在的所有群生效。Bot 主人可在 Bot 设置的「已允许的命令」里查看、删除或手动添加（如 `go build`），删除后再次询问，见 [Bot 设置与权限](/user/bot-settings)。

### 本次会话不再问

和「批准，不再询问」类似，但只在当前会话里有效，会话结束（如 `/new`、开新会话）后失效，不记到 Bot 上。范围稍宽：

- 用 `python`、`node` 等解释器运行**工作区内的脚本**：之后这个解释器运行工作区内任何脚本都不再问。
- `curl`、`wget` 访问某个网站：之后访问同一个主机不再问。
- 其他命令与「批准，不再询问」的规则相同。

### 本次运行免审批

把这一轮临时改为「完全允许」，后续请求都不再询问；下一轮自动恢复原来的审批方式。适合确认这一轮要做的事都没问题、不想一个个批的时候。

- 只有 Bot 主人能用。
- 会写入审计记录。
- 演示模式下不显示这个按钮。

### 超时自动拒绝

权限请求默认等待 **30 分钟**，没人处理就自动拒绝，显示「超时未处理，已自动拒绝」，Agent 会自行绕路。

- 群管理员可在群级参数「权限审批等待（分钟）」里为本群调整（1–1440 分钟），见 [群与私聊](/user/groups)。
- 全站默认值由系统管理员在「权限审批等待 · 群默认」里设置，见 [系统参数](/admin/params)。

运行被停止、接力链被终止、或使用「打断并追加」时，未处理的请求自动作废，显示「运行已停止，请求作废」等。

## 审批方式

哪些操作要审批，由 Bot 的「审批方式」决定。Bot 主人在 Bot 设置里选，见 [Bot 设置与权限](/user/bot-settings)：

| 审批方式 | 说明 |
| --- | --- |
| 每次问我 | 只读命令自动放行，其余操作都发审批卡片 |
| 帮我审批 | 构建、测试、lint、格式化、本地 git 和工作区内改文件直接放行；其余发审批卡片，开了 AI 预审时先由 AI 评估 |
| 完全允许 | 不再询问，Bot 可以执行任何操作 |

早期设为「只读」的 Bot 仍显示「只读」：Bot 只能读取，其余操作都要审批。

除了「完全允许」，高危命令、推送受保护的基准分支和客户端发版始终需要 Bot 主人确认。

::: tip 只在某个群里换审批方式
Bot 主人可在「群设置 → Bot」里点 Bot 的菜单，在「本群审批方式」里选「跟随全局」「只读」「需要审批」或「完全允许」，只影响这个群。改动对运行中的轮次立即生效。
:::

::: warning
审批方式为「完全允许」时，能触发这个 Bot 的人发起的任务都不会被拦截，包括危险命令，建议只给自己用的群或 Bot 开启。此时即使触发范围设为「任何群成员」，Bot 也只允许指定名单触发。演示模式下不能使用「完全允许」。
:::

### 一次请求怎么判定

1. 共工空间自带的工具（如向群成员提问、读取群消息）总是允许。
2. 审批方式是「完全允许」（含「本次运行免审批」）：自动允许。
3. 命中高危底线，或可能推送受保护的基准分支：请 Bot 主人审批（不经过 AI 预审）。
4. 读取、搜索工具的路径都在工作区或附加目录内：自动允许；软链接指向目录外时仍会审批。
5. 整条命令只由只读命令（如 `cat`、`ls`、`rg`、`git status`、读取用的 `sed`、不带删除或执行的 `find`、`jq`、`ps`、`diff`、`stat`、`du`、`which`）和工作区内的 `cd` 组成，且不读取工作区外的路径：自动允许。
6. 符合「已允许的命令」或「本次会话不再问」的规则：自动批准。
7. 审批方式是「帮我审批」，且是开发常用命令或工作区内的文件改动：自动批准。
8. 开了 AI 预审：先由 AI 评估，它放行就自动批准，否则交给 Bot 主人。
9. 否则请 Bot 主人审批。

自动批准的命令在过程里显示为「已按命令审批规则自动批准」，多条合成「自动批准 N 条命令」。

### 帮我审批

「帮我审批」下直接放行的开发常用命令包括：`npm`、`pnpm`、`yarn`、`bun` 运行项目脚本和测试，`cargo build`／`test`／`clippy`／`fmt` 等，`go build`／`test`／`vet` 等，`make`，常见的格式化、lint、测试工具，以及本地 git 操作。这等于信任仓库里的脚本，所以以下情况不放行：

- 命令带有工作区外的路径，或加载外部配置、插件、钩子的参数；
- 本轮已经改过影响构建和测试命令的文件（如脚本配置），之后的开发命令改回需要审批；
- 写入 `.git` 目录里的文件。

**内置审核**：Claude Code 官方登录、Codex 官方 ChatGPT 登录时，「帮我审批」改由 Agent 自带的自动审核把关（Claude 用 auto 模式，Codex 用 agent 模式），共工不再预审，几乎不会打扰你；被它拦下的操作会让 Agent 换个做法，不发卡片。第三方供应商或不支持的模型用不了内置审核，按共工的规则审批。运行开头会注明本次由谁审，如「审批由 Claude 内置审核（auto 模式）把关」「第三方供应商用不了内置审核，审批由共工规则把关」。

**AI 预审**：默认关闭。Bot 主人在 Bot 设置「AI 预审」里选一个模型即开启，之后规则没放行、内置审核也没接手的请求先由这个模型评估：

- AI 只能放行，拿不准的连同风险和理由交给你，卡片上显示风险标签和「AI 预审：理由」。
- 同一条命令在本轮已被 AI 放行过，再次出现时直接批准。
- 高危底线、受保护的基准分支和客户端发版不交给 AI。
- 每次评估都消耗 token，请选小模型（如 haiku、mini、flash）。评估在空目录、无工具的精简会话里进行，每次约几千 token。
- Bot 所在机器还没上报可选模型时不能开启。

### 高危底线

以下命令无论选哪种审批方式（「完全允许」除外），也不管「已允许的命令」里写了什么，**都要 Bot 主人审批**：

- 用 `sudo`、`su`、`doas` 执行的命令；
- `rm` 带 `-r`、`-f` 类参数，且目标是 `/`、`/*`、`~`、`~/…`、`$HOME…`、`..`、`.` 或 `*`；
- `git push` 带 `-f`、`-d`、`--force`、`--force-with-lease`、`--mirror`、`--delete`，或以 `:`、`+` 开头的 refspec；
- `git reset --hard`；`git clean` 带 `-f`；
- 管道下游是从标准输入读脚本的 `sh`、`bash`、`zsh`、`python`、`node`（如 `curl … | sh`）；
- `chmod -R`、`chown -R`；`dd of=…`；`mkfs…`。

命令解析不了时，原文含 `sudo `、`rm -rf /`、`| sh`、`| bash` 也按高危处理。

::: tip 想少点审批
- 只读命令已经免审，不必加规则。
- 日常开发选「帮我审批」，构建、测试类命令不再询问。
- 对常用命令点一次「批准，不再询问」，之后所有群都不再问。
- 一轮里要做很多确定没问题的操作时，点「本次运行免审批」。
:::

## Bot 向群成员提问

Bot 拿不准时，会用「向群成员提问」发出一张提问卡片，状态变为「等待回答」。

![Bot 提问卡片](/screenshots/web/question.webp)

- 卡片标题「向群成员提问 · N 个问题」，每张最多 4 题（系统参数「提问卡片每张题数上限」可调低）。
- 题型：

| 题型 | 作答方式 |
| --- | --- |
| 单选 | 选一个选项，或在「其他，我来补充」里填写 |
| 多选 | 选多个选项，也可以补充文字 |
| 是/否 | 二选一 |
| 自由文本 | 在「自由作答」里填写 |

- Bot 可以把某个选项标为「推荐」。选项可以带说明、色板或预览图，方便比较设计方向。
- 可以点「附图片或附件…」附上文件，最后点「提交回答」。
- 带说明或图片的选项下有「倾向」按钮，任何人都可以点，表明自己倾向哪个；卡片注明「其他人的倾向仅供参考，不算投票」。

### 谁能答

**触发人、Bot 主人，以及提问里 @ 到的群成员**可以回答。卡片上写明「触发人 某某 或 Bot 主人 某某 可回答」，Bot 指定了成员时另显示「指定：@某某」。其他人只能查看。

### 超时

提问的等待时间与权限请求相同（默认 30 分钟）。卡片显示「mm:ss 后超时，按推荐项继续」。

超时后 Agent 按推荐项或自己的最佳判断继续，并在最终回复里列出所做的假设。卡片显示「无人回答，agent 已按推荐项继续」。

回答后卡片收起为简要结果，列出每题的回答，显示「某某 已回答 · 已写入审计记录」；点「查看提问」可展开原题。回答也会出现在运行详情的过程里。

## 通知提醒

- 有权限请求时，**Bot 主人**收到通知。
- 有提问时，触发人、Bot 主人和被指定的成员收到通知。
- 处理完成、超时或作废后，相关通知自动标为已处理。
- 开启浏览器通知后，审批和提问也会推送到系统通知。
- 群里开了「消息免打扰」，这些提醒仍然会到。

通知中心的用法见 [通知](/user/notifications)。
