# 审批与提问

本页讲运行中需要人拍板的两种情况：Bot 的权限请求（审批），以及 Bot 向群成员提问。

## 权限请求

Bot 要做的操作超出了它当前的权限档位时，运行暂停，卡片上出现权限请求，状态变为「等待审批」。

![权限审批卡片](/screenshots/web/approval.webp)

卡片内容：

- 标题「权限请求 · 类型」，类型包括：执行命令、访问网络、写入文件、删除文件、移动文件、读取文件、搜索、其他操作。
- 具体内容，如要执行的命令。
- 说明行，如「超出「工作区写入」档位 · 29:41 后自动拒绝，agent 自行绕路」。倒计时圆环在最后 30 秒变橙色。

### 谁能批

**只有 Bot 主人**能处理。其他人看到「仅 Bot 主人 某某 可操作，你只能查看」。群管理员也不能代批。

| 按钮 | 效果 |
| --- | --- |
| 批准 | 允许这一次 |
| 始终允许 | 把卡片上「将始终允许：…」列出的规则记到这个 Bot 上，之后命中的请求自动批准（见下文） |
| 拒绝 | 拒绝这一次，Agent 会自己想别的办法 |

### 始终允许

「始终允许」只在 Agent 提供该选项、且共工能算出要记住的规则时显示；按钮旁写明范围，如「将始终允许：npm run build、tail」。算不出规则时只有「批准」和「拒绝」。

记住的范围尽量小：

- 命令记**前缀**：取开头最多 3 个普通词，遇到 `-` 开头的参数、路径、引号或 `=` 就停。例如 `npm run build -- --watch=false` 记为 `npm run build`，之后 `npm run build` 加任意参数都自动批准。
- `rm`、`mv`、`sudo`、`sh`、`bash`、`python`、`node`、`curl`、`ssh`、`chmod`、`kill` 等危险或能执行任意代码的程序，记**整条命令原文**，参数变了要重新审批。
- 只读命令、工作区内的 `cd` 本来就免审，不会记。
- 非命令的请求（如 MCP 工具、访问网络）记为 `tool:工具名`，只有同名工具自动批准。

规则存在 **Bot 上**，对这个 Bot 所在的所有群生效，daemon 重启后仍然有效。Bot 主人可在 Bot 设置「命令审批」下的「始终允许」列表里查看、删除或手动添加，删除后再次需要审批，见 [Bot 设置与权限](/user/bot-settings)。命令审批为「全部自动」时这份列表不显示，也不需要。

处理后卡片显示结果，如「某某 已批准 · 14:32」「某某 已拒绝 · 14:32 · agent 将自行绕路」。

### 超时自动拒绝

权限请求默认等待 **30 分钟**，没人处理就自动拒绝，显示「超时未处理，已自动拒绝」，Agent 会自行绕路。

- 群管理员可在群级参数「权限审批等待 · 分区（分钟）」里为本群调整（1–1440 分钟），见 [群与私聊](/user/groups#群级参数)。
- 全站默认值由系统管理员在「权限审批等待（分区模式）· 群默认」里设置，见 [系统参数](/admin/params)。

运行被停止、接力链被终止、或使用「打断并追加」时，未处理的请求自动作废。

### 档位与审批的关系

Bot 的权限档位决定哪些操作需要审批：

| 档位 | 说明 |
| --- | --- |
| 只读 | 只能查看，写文件、执行有副作用的命令都要审批 |
| 工作区写入 | 可以直接改工作区里的文件，执行命令等超出范围的操作要审批 |
| 完全访问 | 全部自动允许，不再弹出审批 |

一次请求按以下顺序决定：

1. 共工空间自带的工具（如向群成员提问、读取群消息）总是允许。
2. 档位是「完全访问」：自动允许。
3. 命中高危底线（见下文）：一律请 Bot 主人审批。
4. 整条命令只由只读命令（如 `cat`、`ls`、`git status`）和工作区内的 `cd` 组成：在「每次询问」「白名单自动」下都自动批准。
5. 符合 Bot 的「命令审批」规则（白名单、始终允许、全部自动）：自动批准，过程里显示「已按命令审批规则自动批准」。
6. 否则请 Bot 主人审批。

「命令审批」是 Bot 主人在 Bot 设置里配置的，可选「每次询问」「白名单自动」「全部自动」，见 [Bot 设置与权限](/user/bot-settings)。

### 高危底线

以下命令无论命令审批选哪种模式（包括「全部自动」），也不管白名单、始终允许里写了什么，**都要 Bot 主人审批**：

- 用 `sudo`、`su`、`doas` 执行的命令；
- `rm` 带 `-r`、`-f` 类参数，且目标是 `/`、`/*`、`~`、`~/…`、`$HOME…`、`..`、`.` 或 `*`；
- `git push` 带 `-f`、`--force`、`--force-with-lease`、`--mirror`、`--delete`，或以 `:` 开头的 refspec（删除远端分支）；
- `git reset --hard`；`git clean` 带 `-f`；
- 管道下游是 `sh`、`bash`、`zsh`、`python`、`node`（如 `curl … | sh`）；
- `chmod -R`、`chown -R`；`dd of=…`；`mkfs…`。

命令无法解析时，「全部自动」仍会放行，但原文含 `sudo `、`rm -rf /`、`| sh`、`| bash` 时同样转主人审批。档位为「完全访问」时 Agent 不发权限请求，不受底线约束。

::: tip 想少点审批
- 只读命令已经免审，不必加白名单。
- 对常用命令点一次「始终允许」，之后所有群都不再问。
- Bot 主人可以在「命令审批」里开启白名单，把常用命令前缀（如 `pnpm test`）加进去。
- 或在「群设置 → Bot」里把本群档位调高。档位改动对运行中的轮次立即生效；调到「完全访问」时，正在等待的请求会自动批准。
:::

::: warning
档位为「完全访问」时，Bot 只允许指定名单触发，即使触发范围设为「任何群成员」。
:::

## Bot 向群成员提问

Bot 拿不准时，会用「向群成员提问」发出一张提问卡片，状态变为「等待回答」。

![Bot 提问卡片](/screenshots/web/question.webp)

- 卡片标题「向群成员提问 · N 个问题」，每张最多 4 题（系统参数「提问卡片每张题数上限」可调低）。
- 题型：

| 题型 | 作答方式 |
| --- | --- |
| 单选 | 选一个选项，或在「其他，我来补充」里填写 |
| 多选 | 选多个选项，也可以补充文字 |
| 是/否 | 二选一 |
| 自由文本 | 在「自由作答」里填写 |

- Bot 可以把某个选项标为「推荐」。
- 可以点「附图片或附件…」附上文件，最后点「提交回答」。

### 谁能答

**触发人或 Bot 主人**可以回答，卡片上会写明「触发人 某某 或 Bot 主人 某某 可回答」。其他人只能查看。

### 超时

提问的等待时间与权限请求相同（默认 30 分钟）。卡片显示「mm:ss 后超时，按推荐项继续」。

超时后 Agent 按推荐项或自己的最佳判断继续，并在最终回复里列出所做的假设。卡片显示「无人回答，agent 已按推荐项继续」。

回答后卡片显示「某某 已回答 · 已写入审计记录」。

## 通知提醒

- 有权限请求时，**Bot 主人**收到通知。
- 有提问时，**触发人和 Bot 主人**各收到一条通知。
- 处理完成、超时或作废后，相关通知自动标为已处理。
- 开启浏览器通知后，审批和提问也会推送到系统通知。
- 群里开了「消息免打扰」，这些提醒仍然会到。

通知中心的用法见 [通知](/user/notifications)。
