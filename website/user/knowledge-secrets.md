# 知识库与密钥

本页讲两件事：让本群所有 Bot 都记住的**知识库**，以及把 Token、密码安全交给 Bot 使用的**密钥**。

## 知识库

每个群有一个知识库，放需要所有 Bot 记住的事实和约定，如发布流程、接口命名约定。Bot 每次运行都能读到，也会自己补充。

![知识库](/screenshots/web/knowledge.webp)

### 在哪里看

- 群设置侧栏 →「知识库」（私聊的「私聊设置」里也有）。
- 也可以把某条知识挂到群顶部的标签栏，见 [群标签栏](/user/groups#群标签栏)。

列表里置顶的条目排在最前（标「置顶」），其余按更新时间排序。每条显示标题、摘要、标签、最后编辑人和时间，Bot 改过的标「Bot」。顶部「搜索知识库」按标题、正文和标签搜索。

### 新建与编辑

1. 点「新建条目」。
2. 填「标题」，如「发布流程」。
3. 在「标签」里回车添加标签（最多 10 个）。
4. 写「正文」，支持 Markdown，可以切换「编辑 / 预览」。
5. 点「保存」，提示「已保存，本群 Bot 下一轮读到」。

| 限制 | 数量 |
| --- | --- |
| 每个群的条目 | 200 条 |
| 标题 | 100 字 |
| 正文 | 20000 字 |
| 标签 | 每条 10 个 |

已有条目从「更多」菜单点「编辑」。两人同时改一条时，后保存的人会看到「这条知识已被他人更新」，可以先复制正文再「载入最新版本」。

### 存入知识库

群里的消息可以直接存进知识库：在消息的「更多」菜单里点「存入知识库」，会打开「新建条目」，标题取消息第一行，正文是整条消息并附上来源。确认后点「保存」。

### 历史版本

每次修改都保留一个版本。在条目的「更多」菜单点「历史版本」：

- 每个版本显示 v 号、动作（创建 / 编辑 / 回滚）、修改人和时间，当前版本标「当前」。
- 点「查看」可在「改动」（与上一版的差异）和「内容」之间切换。
- 「回滚到此版本」把旧内容存成一个新版本，提示「已回滚到 vN」。

### 谁能做什么

| 操作 | 谁 |
| --- | --- |
| 查看、新建、编辑、回滚 | 任何群成员 |
| 置顶 / 取消置顶、删除 | 群管理员 |

删除后无法恢复，本群 Bot 下一轮起不再读到这条知识。知识库的每次变动都会在群里发一条提示。

### Bot 怎样使用

- 每次运行开始时，**置顶条目的全文**直接放进 Bot 的上下文（约 4000 token 以内，超出部分截断，Bot 需要时自己去读全文）；其余条目只列标题和标签，Bot 需要时按需读取。
- 续接的会话只会收到「群知识库自你上次读取后有变化」的部分。
- Bot 可以自己新建和更新条目；只有发起这一轮的人是群管理员时，Bot 才能删除条目。
- 所以重要、每次都要遵守的约定建议**置顶**。

::: warning
不要把密钥、密码写进知识库。需要交给 Bot 的凭据请用下面的「密钥」。
:::

## 密钥

密钥用来把 Token、密码等交给 Bot 使用：值加密保存在服务器，Bot 运行时以**同名环境变量**注入，输出里出现时会被打码，任何人都看不到明文。

![密钥](/screenshots/web/secrets.webp)

### 四个层级

| 层级 | 在哪里管理 | 谁能改 |
| --- | --- | --- |
| 平台层 | 管理后台「配置中心」→「密钥」 | 系统管理员 |
| 团队层 | 团队设置 →「密钥」 | 团队管理员 |
| 群层 | 群设置 →「密钥」（私聊没有） | 群管理员 |
| 我的值 | 头像菜单 →「设置…」→「我的密钥」 | 自己 |

- 同名时群层优先于团队层，团队层优先于平台层。群设置里能看到继承来的团队、平台密钥（只读），被覆盖的标「已被本群覆盖」或「已被团队层覆盖」。
- 改动下一轮生效。

### 新建密钥

管理员在对应层级点「新建密钥…」：

| 字段 | 说明 |
| --- | --- |
| 名称 | 环境变量名，如 `FEISHU_DEVOPS_TOKEN`。只能用大写字母、数字和下划线，以字母开头；建好后不能改名 |
| 用途 | 做什么用，怎么申请 |
| 模式 | 见下表 |
| 可用 Bot | 「全部 Bot」或「指定 Bot」 |
| 到期时间 | 留空则不过期 |
| 启用 | 停用后不再注入 |
| 统一值 | 可稍后填写；存入后不再显示明文 |
| 我的值 | 新建「每人自填」或「统一值可个人覆盖」时可以顺手填自己的值 |

| 模式 | 说明 |
| --- | --- |
| 统一值 | 所有人用同一个值，个人不能覆盖，适合团队共用的服务 token |
| 统一值可个人覆盖 | 有统一值；成员填了自己的值就用自己的 |
| 每人自填 | 没有统一值，每人填自己的，适合个人账号的 token |

- 值至少 8 个字符。
- 不能用系统保留的名称，例如以 `ANTHROPIC_`、`CLAUDE_`、`CODEX_`、`OPENAI_`、`GG_`、`GONGGONG_`、`GIT_` 开头的，会提示「… 是系统保留的环境变量名，请换一个名称」。
- 行菜单里可以「编辑…」「清除统一值」「删除」。删除会把定义、统一值和成员填的个人值一并删除，不可恢复。

### 运行时用哪个值

每次运行，按**发起这一轮的人**取值：

1. 模式不是「统一值」、他填了自己的值，并且 Bot 在他自己的机器上（或他打开了「允许在他人机器上的 Bot 使用」）：用他自己的值。
2. 否则用统一值（「每人自填」没有统一值）。
3. 都没有就不注入。

停用、已过期、或不允许这个 Bot 用的密钥都会跳过。运行详情里能看到「本次注入的密钥」及各自来源（个人 / 群 / 团队 / 平台）。

::: warning 他人机器
机器主人能读到自己机器上 Bot 进程的环境变量。所以你的个人值默认只注入到**你自己机器上**的 Bot；要给别人机器上的 Bot 用，需要打开「允许在他人机器上的 Bot 使用」。
:::

MCP 配置里可以用 `${secret:名称}` 引用密钥，运行时替换成实际值；缺值的 MCP 服务本轮不启用。

### 填写自己的值

需要你填自己值的地方有三处：

- **我的密钥**：头像菜单 →「设置…」→「我的密钥」，列出团队里所有「每人自填」「统一值可个人覆盖」的密钥，按来源分组。每行可以「填写…」/「更新…」、「清除」，并单独设置「允许在他人机器上的 Bot 使用」。
- **群设置 → 密钥**：普通成员打开是只读的，但在「每人自填」「统一值可个人覆盖」的行上可以「填写我的值…」或「更新我的值…」。
- **Bot 发来的填写卡片**，见下文。

同一个名称填一次，对团队里所有同名定义都生效。

### Bot 请你填写密钥

Bot 干活时发现缺密钥，会在群里发一张卡片：

- 缺的是「每人自填」或「统一值可个人覆盖」的值：卡片发给发起这一轮的人，如「后端助手 请 王磊 填写自己的密钥：…」。
- 缺的是「统一值」：卡片发给管理员，如「后端助手 请管理员填写密钥：…」。只有这个密钥所在层级的管理员能填。

1. 点卡片上的「填写密钥」。其他人看到「等待填写」。
2. 在「填写密钥」对话框里输入值（至少 8 个字符）。Bot 在别人机器上时，对话框里会有「允许在他人机器上的 Bot 使用」，默认勾选。
3. 保存后卡片变为「已填写」。这一轮是你直接发消息触发的，Bot 会自动继续（群里提示「已填写密钥，某某 继续处理」）；否则提示「已填写密钥，重新 @某某 即可继续」。

有你没填的卡片时，群顶部会显示「你有 N 个密钥待填写」，点「填写密钥」即可。

::: tip 飞书里的卡片
群绑定了飞书并开启同步时，卡片也会发到飞书群并 @ 你。点「去填写」打开共工的填写页（只有发起人本人能填），值不会在飞书里输入。填完飞书卡片也变为「已填写」。
:::

### 谁能看到什么

- 值存入后任何人都看不到明文，管理员也不行，只能覆盖或清除。列表只显示「已填写 · 末 4 位 … · 修改人 · 时间」。
- 管理员能看到哪些人填了个人值（「已填个人值：…」），看不到值本身。
- Bot 只能看到密钥名称和状态，按环境变量读取已注入的值。
