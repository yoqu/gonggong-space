# 指令参考

本页列出输入框里输入 `/` 后能用的内容：共工空间自带的系统命令、Skill、插件命令，以及 Agent 自己提供、原样转交的 Agent 命令。

![输入 / 弹出指令候选](/screenshots/web/composer-commands.webp)

## 怎么输入指令

- 在输入框开头输入 `/`，或点工具栏的「命令」，弹出候选列表。
- 也可以先 @ Bot 再输入指令，如 `@后端助手 /compact`，两种写法等价。
- 用 ↑ / ↓ 选择，Enter 或 Tab 插入，Esc 关闭。
- 指令名区分大小写。

候选列表按来源分组：

| 分组 | 内容 |
| --- | --- |
| 系统命令 | 共工空间自带，见下文 |
| 插件 | 本群启用的插件：选插件名打开创作面板；插件提供的 `/` 命令也列在这里 |
| 我的 Skill（个人引入） | 你自己引入的 Skill，只在你发起的运行里生效 |
| 团队 Skill（配置中心） | 本群可用的其他 Skill（群、团队等层级配置或引入的） |
| AGENT 命令（ACP 上报） | 消息里 @ 到的 Bot 所用的 Agent 提供的命令 |

::: tip 看不到 Agent 命令？
Agent 命令只对 @ 到的 Bot 列出。先输入 `@Bot名`，再输入 `/`。另外 Bot 要在这个群里跑过至少一轮，它的 Agent 命令才会出现。
:::

系统命令消息不会触发普通运行，也不会作为背景上下文补给 Bot，执行结果以一条群提示显示。

## 系统命令

| 指令 | 界面说明 | 写法 | 谁能用 |
| --- | --- | --- | --- |
| `/stop` | 停止运行（未 @ Bot 时停止本群全部） | `/stop` 或 `/stop @Bot …` | 群成员 |
| `/new` | 开新会话 | `/new @Bot …` | 群成员 |
| `/cd` | 绑定本机目录（仅分区） | `/cd @Bot /绝对路径` 或 `/cd @Bot --reset` | Bot 主人 |

### /stop

停止运行中和排队中的轮次。

```text
/stop @后端助手
/stop
```

- 带 @：只停这些 Bot 的未完成轮次。
- 不带 @：停本群全部 Bot 的未完成轮次。
- 涉及 Bot 接力链时，整条链一起终止。
- 群里提示如「王磊 /stop · 停止 后端助手 的 1 个轮次」；没有可停的显示「没有运行中的轮次」。
- 操作会写入审计记录。

### /new

让 Bot 下一轮开一个全新会话，不再带上此前的对话。

```text
/new @后端助手
```

- 必须 @ 至少一个 Bot，否则提示「/new 需要同时 @ 一个 Bot，如 /new @后端助手」。
- 群里提示「后端助手 下一轮将开新会话」，下一张运行卡片显示「已按要求开启新会话」。
- 在话题里发 `/new`，只重置这个 Bot 在该话题里的会话，不影响群里的主会话。
- 群头部上下文占用面板里的「开新对话」发出的就是这条指令，见 [上下文占用与压缩](/user/chat#上下文占用与压缩)。

### /cd

让 Bot 直接在它所在机器上的某个本机目录里干活，而不是在托管工作区里。

```text
/cd @后端助手 /Users/wanglei/code/todo-app
/cd @后端助手 --reset
```

- 只有 Bot 主人能用，只在分区模式的群里可用。
- 必须且只能 @ 一个 Bot；路径必须是 Bot 所在机器上的绝对路径。
- 路径是群里某个附加仓库的克隆时，用作这个附加仓库的本机目录；否则替换 Bot 的主工作区。
- `--reset`：回到托管工作区。
- 成功提示「✓ 后端助手 已绑定到 /Users/…（本机目录）」或「✓ 后端助手 已使用托管工作区」。
- 之后目录被删除，运行会失败并提示「/cd 目录不存在」。

常见报错：

| 提示 | 原因 |
| --- | --- |
| /cd 仅分区模式可用；强制同步群里非托管工作区的 Bot 为「不参与」 | 群是强制同步模式 |
| /cd 需要 @ 一个 Bot，如 /cd @… /本机/绝对路径，或 /cd @… --reset 回到托管 | 没 @ Bot、@ 了多个，或没写路径 |
| 只有 Bot 主人可以使用 /cd | 你不是这个 Bot 的主人 |
| /cd 需要本机绝对路径，如 /Users/me/code/repo | 写了相对路径 |
| 某某 离线，无法执行 /cd | Bot 所在机器不在线 |
| 某某 绑定工作区失败：… | 目录不存在、范围过大或是系统目录等 |

在界面里更换工作区更直观，见 [仓库与工作区](/user/repos-workspaces#更换工作区)。

## Skill

候选里的「我的 Skill」「团队 Skill」是当前可用的 Skill。选中后把 Skill 名插入消息，和 @ Bot 一起发出，Bot 就会按这个 Skill 干活。

- Codex 用 `$名称` 引用 Skill，Claude Code 用 `/名称`；@ 的都是 Codex Bot 时，输入框会自动用 `$` 写法。
- 「我的 Skill」只在你自己发起的运行里生效，并优先于群、仓库、团队里的同名 Skill。

Skill 的来源、引入与市场见 [Skill 市场与插件](/user/market-plugins)。

## 插件命令

群里启用的插件可以带自己的 `/` 命令，列在「插件」分组里，说明后面标注插件名。发送后，共工把插件定义的指令交给 Bot 执行。插件命令不能与系统命令重名。详见 [Skill 市场与插件](/user/market-plugins)。

## Agent 命令

Agent 命令是 Bot 使用的 Agent（Claude Code、Codex 等）自己上报的命令，如 `/compact`。有哪些命令、各自做什么，以 Agent 本身为准，候选里的说明文字也来自 Agent。

```text
@后端助手 /compact
```

- 发送后，指令文字**原样**交给 Agent 执行，不附带群上下文。
- 必须 @ Bot，且 @ 到的每个 Bot 都支持这条命令，才会作为 Agent 命令执行。
- 只有一个 Bot 的私聊里可以不写 @。
- 不满足以上条件的 `/xxx` 按普通消息处理。例如 `/path/to/file @后端助手 看下` 会作为一条普通任务发给 Bot。

### 与系统命令重名

Agent 命令与系统命令同名时，候选里显示为 `/Bot名:命令`，并标注「与系统命令重名」。直接输入 `/new` 执行的是系统命令；要执行 Agent 的同名命令，用带前缀的写法：

```text
/后端助手:new
```

Bot 名里的空格要去掉。
