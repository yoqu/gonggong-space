# 核心概念

本页解释共工空间里反复出现的几个概念，以及它们之间的关系。读完再看其他页面会顺畅很多。

## 关系一览

```text
账号（王磊）
 ├─ 机器（wanglei-mbp）── 运行 daemon（gg 后台服务或桌面端）
 │    ├─ Bot「王磊的 Claude Code」── Agent：Claude Code
 │    └─ Bot「后端助手」── Agent：Codex
 │         └─ 每进一个群或私聊 → 一个工作区（群 × Bot）
 └─ 群「todo-app」── 主仓库 todo-app（基准分支 main），可再挂附加仓库
      ├─ 成员：王磊、李娜、陈晨
      ├─ Bot：后端助手（王磊的）、前端助手（李娜的）
      ├─ 知识库、密钥、定时任务、话题
      └─ 消息 ──@Bot──→ 运行（run）──→ 过程 / diff / 审批 / 提问 / 预览
```

| 概念 | 属于谁 | 一句话 |
| --- | --- | --- |
| 账号 | — | 登录 Web 的身份，角色为系统管理员或普通成员 |
| 机器 | 某个账号 | 装了 daemon 并绑定到该账号的一台机器 |
| daemon | 某台机器 | 机器上的常驻程序，接活并调用本机 Agent |
| Bot | 某个账号（归属人） | 群里可 @ 的 AI 成员，固定跑在归属人的某台机器上 |
| 群 / 私聊 | 群成员 | 人和 Bot 一起干活的地方；私聊只有你和一个 Bot |
| 工作区 | 某个 Bot 在某个群 | Bot 干活的目录，每个「群 × Bot」一个 |
| 运行（run） | 某个 Bot 在某个群 | @Bot 触发的一轮工作 |

## 账号与角色

- **系统管理员**：可进入「管理后台」，管理账号、全部 Bot 与群、机器、配置中心、系统参数等。首次启动服务器时自动创建账号 `admin`。
- **普通成员**：登录后绑定自己的机器、创建自己的 Bot、发起群聊和私聊。

默认不开放自助注册（系统参数可开启），账号由系统管理员创建；首次登录必须修改初始密码。详见 [登录与账号](/user/login)、[账号与角色（管理后台）](/admin/users)。

在群内，成员分为**群管理员**（管理群设置、成员与 Bot）和普通成员。每个 Bot 的归属人也称 **Bot 主人**，只有他能处理该 Bot 的审批卡片。

## 机器与 daemon

**机器**是成员用来跑 Bot 的 Mac、PC、Linux 服务器或 Docker 容器。机器上运行共工空间的 daemon，绑定到你的账号后就归属于你。

绑定最省事的方式是「发给你的 Agent」：在「绑定新机器」里复制一句话，粘贴给这台机器上的 Claude Code 或 Codex，它会自己下载安装 `gg`、完成绑定、装成后台服务，并自动建好 Bot 和与它的私聊（支持 macOS 和 Linux）。也可以用桌面端打开接入链接、在终端执行 `gg login`，或在 Docker 中运行。详见 [绑定机器](/user/bind-machine)。

**daemon** 有两种形态，功能相同：

- 命令行 `gg`（macOS、Linux）：`gg run` 运行，`gg service install` 装成开机自启的后台服务，见 [命令行 gg](/cli/)。
- 桌面端（macOS、Windows）：自带 daemon，关掉窗口仍在后台运行，见 [桌面端](/desktop/)。

daemon 会向服务器上报机器名、系统、CPU、内存以及本机可用的 Agent 版本。daemon 断开后，机器显示「离线」，发给它上面 Bot 的任务会排队等待。

在「机器与 Bot」页，你可以按机器查看名下的 Bot，管理 Agent 工具、供应商、Git 访问，查看工作区占用并清理空间，在网页上升级 daemon，以及在机器上打开终端。详见 [我的机器与 Bot](/user/machines)。

## Bot

Bot 是群里可以 @ 的 AI 成员。它由以下几项决定：

| 属性 | 说明 |
| --- | --- |
| 归属人 | Bot 属于谁。成员只能为自己创建；系统管理员可为任何人创建，此时需归属人在通知中确认后才能触发 |
| 执行机器 | 归属人名下的一台机器，Bot 的所有工作都在这台机器上进行 |
| Agent | Claude Code、Codex、Gemini CLI、CodeBuddy、pi 或 DeepSeek Harness，使用执行机器上的 CLI |
| 角色 | 头像与性格形象：默认跟随 Agent，也可选共字君或 12 个性格角色 |
| 系统提示词 | 告诉 Bot 它的职责，同时作为群内简介 |
| 触发范围 | 谁能 @ 它干活：任何群成员 / 指定名单 / 仅本人 |
| 审批方式 | 需要把关的操作怎么处理：每次问我 / 帮我审批 / 完全允许，只有 Bot 主人能改 |
| 并发上限 | 同时运行的轮次，超出的在本机排队 |

用「发给你的 Agent」接入时，服务器会自动建一个名为「你的名字 + 的 + Agent 名」的 Bot（如「王磊的 Claude Code」）。之后可以在同一台机器上再「新建 Bot」，换不同的 Agent、角色和提示词。Bot 主人还可以把 Bot 共享给团队成员私聊。详见 [创建 Bot](/user/create-bot)、[Bot 设置与权限](/user/bot-settings)。

## 群与私聊

- **群**：成员和 Bot 一起干活的地方。可以绑定 git 仓库，也可以不绑定；可以设为公开频道，让团队成员在「浏览频道」里找到并自行加入。
- **私聊**：只有你和一个 Bot，适合个人使用；私聊里不用 @，直接发消息就会触发它。

在群里 `@Bot名 需求` 才会触发 Bot；没有 @ 的消息不会触发，只作为上下文带给 Bot。在消息上「回复话题」可以把一段讨论收进**话题**，不刷主群；Bot 也可以开话题，指派另一个 Bot 在话题里接手。详见 [群与私聊](/user/groups)、[在群里指挥 Bot](/user/chat)、[定时任务与话题](/user/schedules-threads)。

## 仓库、工作区与模式

- **仓库**：群可以绑定一个主仓库和多个附加仓库，各自指定**基准分支**（默认 `main`）。每个 Bot 用**归属人机器上自己的 git 凭据**克隆，服务器不替成员保管仓库凭据。
- **工作区**：Bot 干活的目录，每个「群 × Bot」一个，互相隔离。分两种：
  - **托管工作区**：daemon 自动创建和管理，位于机器上的 `~/gonggong/workspaces/<群名>/<Bot名>/<仓库名>`；未绑定仓库的群和私聊里也会有一个空的托管目录，Bot 进群后第一条 @ 就能执行。
  - **本机目录**：Bot 主人可以让 Bot 改用自己机器上已有的目录（`/cd @Bot /绝对路径`，或在 Bot 菜单里更换工作区），`/cd @Bot --reset` 回到托管工作区。
- **同步模式**：默认是**分区模式**，每个 Bot 在自己的工作区里独立改动；也可以切到**强制同步**，让不同机器上的 Bot 共用一份工作区，冲突自动三方合并。

群头部的 Git 条显示分支与改动状态；Git 面板里可以提交、看日志、贮藏、处理冲突。详见 [仓库与工作区](/user/repos-workspaces)、[Git 管理](/user/git)。

## 运行（run）

每次 @Bot 触发一轮**运行**，群里出现一张运行卡片。运行的状态有：

| 状态 | 含义 |
| --- | --- |
| 排队中 | 本群该 Bot 的上一轮未结束、工作区还在准备，或 Bot 的并发已满 |
| 离线等待 | Bot 所在机器离线，等待上线（默认最多 30 分钟，群设置可调） |
| 无权触发 | 触发人不在这个 Bot 的触发范围内 |
| 运行中 | Agent 正在干活 |
| 等待审批 / 等待回答 | 需要有人处理审批或回答提问 |
| 已完成 / 已中断 / 已作废 | 终态；超时未执行的请求会作废 |

运行中可以追加消息打断并补充要求，也可以用 `/stop` 停止。Bot 可以通过内置的「交给其他 Bot」工具把任务**接力**给群里另一个 Bot，形成接力链；Bot 在回复里写 @ 只是提及，不会触发。

除了人 @，运行也可以由**定时任务**到点发起：群和私聊都能挂定时任务，每次在独立的新会话里执行。详见 [运行过程](/user/runs)、[指令参考](/user/commands)、[定时任务与话题](/user/schedules-threads)。

## 审批与提问

- **审批**：Bot 想做需要把关的操作（如执行命令、推送代码）时，按 Bot 的审批方式处理：
  - 「每次问我」：只读命令自动放行，其余都发审批卡片；
  - 「帮我审批」：构建、测试、本地 git、工作区内改文件等直接放行，其余发卡片；Claude Code 与 Codex 在官方登录下改由 Agent 内置的审核把关，也可以开启「AI 预审」先由小模型评估，只把风险操作交给你；
  - 「完全允许」：不再询问，只能由触发名单里的人触发。

  高危命令、推送受保护的基准分支等始终需要确认。审批卡片**只有 Bot 主人**能批准或拒绝；默认等待 30 分钟，超时视为拒绝。
- **提问**：Bot 拿不准时会向群成员出选择题或问答题，**触发人、Bot 主人或被 @ 的成员**可以回答。

详见 [审批与提问](/user/approvals)。

## 预览与作品

Bot 可以把它启动的网页服务、静态页面、桌面应用画面或小程序发布为**预览**，群里出现预览卡片，成员在浏览器里直接打开；需要给外部看时可以生成有期限的公开链接。流量经 daemon 与服务器之间的隧道转发，机器上只有已发布的端口可被访问。

开启创作插件后，Bot 做的原型会成为托管的**作品**：在多屏画布上摆放、批注、看版本，交给 Bot 改整屏或某个元素，所有作品汇总在「作品」页。详见 [结果预览](/user/previews)、[公开分享](/user/shares)、[原型、画布与作品库](/user/artifacts)。

## 团队的积累：Skill、插件、知识库与密钥

- **Skill 市场**：上传或从 ZIP、SKILL.md、GitHub 导入 Skill，审核后引入到个人、群、仓库或团队，随运行下发给 Agent。
- **插件**：可以带 MCP 服务、斜杠命令、画布指令与供应商预设，由系统管理员开启插件功能后在团队或群里启用。
- **知识库**：群内的 markdown 条目，本群所有 Bot 都能读，成员和 Bot 都能维护，带版本历史。
- **密钥**：平台、团队、群、个人四层，运行时只以环境变量注入，过程和回复里按值打码。

详见 [Skill 市场与插件](/user/market-plugins)、[知识库与密钥](/user/knowledge-secrets)。

## 上下文

每个「群 × Bot」对应一个持续的 Agent 会话，Bot 会记得本群之前的对话；闲置超过 6 小时（系统参数可调）会自动开新会话。群头部的 Bot 条会显示每个 Bot 的**上下文占用**，快用满时可以：

- 「压缩上下文」：把此前的对话总结后保留；
- 「开新对话」：不再带上此前的对话（等同 `/new`）。

运行详情的「上下文」页签可以看到这一轮的上下文窗口用量、提示词缓存命中与构成估算。
