# 共工Bot 是什么

本页介绍共工Bot 的定位、适用场景、与直接使用 Claude Code / Codex 的区别，以及名字的由来。

## 一句话定位

共工Bot 是面向小团队的 AI 协作平台：**在 Web 群里 @ 一个 Bot，它就在某位成员自己的机器上调用 Claude Code 或 Codex 真正动手**——读代码、改文件、跑命令，每一步实时回到群里；多个 Bot 在各自的工作区里干活，接力完成同一个 git 仓库。

![群消息全景](/screenshots/web/chat.webp)

整套系统由四部分组成：

| 部分 | 作用 |
| --- | --- |
| Web | 大家登录、聊天、@ Bot、看过程和改动的地方 |
| 服务器 | 保存账号、群、消息，把任务派给对应的机器 |
| daemon（命令行 `gg` 或桌面端） | 装在成员机器上，接活并调用本机的 Claude Code / Codex |
| Bot | 群里可以 @ 的 AI 成员，归属某位成员，固定跑在他的某台机器上 |

详细关系见 [核心概念](/guide/concepts) 和 [系统架构](/guide/architecture)。

## 适合什么场景

- **小团队共用 AI 编程助手**：每人把自己的 Claude Code / Codex 接成 Bot，拉进项目群，谁有需求谁 @。
- **分工接力**：前端 Bot 改完页面，交给后端 Bot 补接口；一个 Bot 可以把任务交给群里另一个 Bot 继续做，接力链长度可在群设置里限制。
- **需求讨论与执行在一处**：群里没 @ 的讨论会作为上下文带给 Bot，不必再复制粘贴背景。
- **过程需要被看见、被把关**：思考、工具调用、命令输出、diff 实时可见；越权操作要 Bot 主人批准。
- **结果需要给人看**：Bot 起的网页、服务、桌面应用或小程序可以直接在浏览器里预览，还能生成公开链接。

## 与直接用 Claude Code / Codex 的区别

| | 直接在终端里用 | 通过共工Bot 用 |
| --- | --- | --- |
| 谁能指挥 | 只有坐在这台机器前的人 | 群里被允许的成员都能 @（触发范围由 Bot 主人设定） |
| 过程可见性 | 只在本人终端里 | 实时推送到群，所有群成员可看过程与 diff |
| 多人 / 多 Agent 协作 | 各干各的，手动同步 | 同一个群、同一个仓库，Bot 之间可以接力 |
| 权限把关 | 本人当场确认 | 三档权限（只读 / 工作区写入 / 完全访问）+ Bot 主人审批，操作留审计记录 |
| 工作目录 | 自己管理 | 每个「群 × Bot」自动一个托管工作区，互不干扰 |
| 运行位置 | 本机 | 仍然是成员本机：用本机已登录的 CLI、本机的 git 凭据 |

共工Bot 不替代 Claude Code / Codex，而是把它们接进团队的群。Agent 本身的能力、模型与登录方式都沿用本机 CLI。

## 名字由来

「共工」取自上古神话中的水神共工。「共」字在甲骨文里是双手合力托举一物的样子，正对应「大家一起把事情托起来」。Logo 是两道浪尖托起一枚玉。

品牌 IP「共字君」是一个扁平的「共」字小人，也是新建 Bot 时的默认角色形象；另外还有 12 个性格角色可选，见 [创建 Bot](/user/create-bot)。
