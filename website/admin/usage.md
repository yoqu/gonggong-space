# 用量与会话统计

本页介绍管理后台「观测」组里的「用量」和「会话统计」两个页面：前者汇总 token 用量，后者看会话、消息与运行的整体情况。

两个页面的工具栏都有团队筛选，默认「全部团队」。团队管理员在「团队设置」里也有同样的「用量」「会话统计」页签，只看本团队。

## 用量

![管理后台 · 用量](/screenshots/web/admin-usage.webp)

「用量」页按 Bot、触发人或群汇总近 30 天的 token 用量。

### 查看方式

顶部三个标签切换汇总维度：

- **按 Bot**：每个 Bot 消耗了多少。
- **按触发人**：谁 @ Bot 触发的运行消耗了多少。
- **按群**：每个群消耗了多少。

标签下方依次是：

- **汇总数字**：token 合计、运行轮次、未上报轮次、参与统计的 Bot / 触发人 / 群数，并与前一个 30 天比较（「较前 30 天」或「持平」）。
- **每日趋势**：可切换看 token 或轮次，标出峰值。
- **token 分布**：各项占比。
- **用量明细**：

| 列 | 说明 |
| --- | --- |
| Bot / 触发人 / 群 | 随所选维度变化 |
| 占比 | 该行 token 占最高一行的比例条 |
| token | token 合计；没有任何上报时显示「未上报」 |
| 轮次 | 运行轮数 |
| 未上报 | 适配器没有上报用量的轮数 |

统计窗口固定为近 30 天，趋势图的日期按浏览器所在时区划分。

### 注意事项

- 用量只做统计，**不做配额限制**，超用不会被拦截。
- 用量来自 Agent 适配器的上报。适配器未上报用量的轮次（如部分 Codex 轮次）计为「未上报」，不计入 token 合计，因此这类 Bot 的 token 数可能偏低。
- 上下文占用不计入用量。
- 成员在头像菜单「我的用量」里看到的是同一套统计，但只包含自己的 Bot。

## 会话统计

「会话统计」页是全站会话、消息与运行概览，只统计数量，不含消息内容。顶部可选时间范围：近 7 天 / 近 30 天 / 近 90 天。

页面由上到下：

- **概览数字**：会话总数（群与私聊各多少）、活跃会话、新建会话、用户消息、Bot 回复、活跃成员、运行轮次、成功率、平均耗时，并与前一个同样长度的时段比较。
- **每日趋势**：可切换用户消息、Bot 回复、运行轮次、活跃成员、活跃会话。
- **运行状态分布**：各状态的运行轮数。
- **运营**：留存（前一时段活跃的成员有多少回访）、新成员激活（新加入的成员有多少已发起运行，及中位用时）、失败率（不含手动停止）、使用者占比，以及失败原因排行。
- **会话明细**：可「按会话」「按成员」「按 Bot」「按团队」查看，列出消息数、参与会话、活跃成员、运行轮次、成功率、最近活跃等。

口径说明：消息为成员与 Bot 的发言，不含系统事件；运行轮次按发起时间计入；成功率 = 已完成 / 已结束；「搭建者」指系统管理员、团队管理员、机器或 Bot 的主人、群管理员，其余为「使用者」。
