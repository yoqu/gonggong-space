# 配置中心

本页说明配置中心的分层叠加规则，以及系统管理员能在这里配置的平台层 MCP、Skill、插件、密钥和市场审核。

![管理后台 · 配置中心](/screenshots/web/admin-config.webp)

## 分层叠加

Bot 干活时，Agent 实际用到的配置由几层叠加而成，从低到高：

| 层 | 在哪里配置 | 优先级 |
| --- | --- | --- |
| 仓库基线 | 群绑定仓库里的 `.mcp.json`、`.claude/`、`AGENTS.md` 等 | 低 |
| Bot 系统提示词 | 各 Bot 在 Bot 页设置，见 [Bot 设置与权限](/user/bot-settings) | — |
| 平台层 | 管理后台 · 配置中心（本页） | 中 |
| 团队层 | 团队管理员在「团队设置」中配置 | 中 |
| 群层 | 群管理员在群设置中配置 | 高 |

同名时下层覆盖上层（群层优先于团队层，团队层优先于平台层）。群也可以单独关闭从平台层、团队层继承来的 MCP 和 Skill。配置中心**不修改仓库文件**：

- 合并在 daemon 内存中完成。
- MCP 在新建会话时经 ACP 注入 Agent，不写入磁盘。
- Skill 由 daemon 缓存在本机：Claude Code 以插件方式注入；Codex 在工作区建软链，并加入 `.git/info/exclude`，不会被提交。

页面右侧「合并预览 · 全部 Bot」按层列出当前生效的内容。

## 能配置什么

顶部左侧的层级切换里只有「平台层」可选（团队层、群层在各自的设置里管理）；右侧的类型切换有以下几项：

| 类型 | 内容 |
| --- | --- |
| MCP | 平台层 MCP 服务，见下文 |
| Skill | 平台层 Skill：上传 `SKILL.md` 所在的文件夹或 zip，在线编辑，版本历史与回滚 |
| 插件 | 平台插件：内置插件与自己上传的插件，对所有团队可见 |
| 指令 | 暂不支持 |
| 密钥 | 平台层密钥：Bot 运行时以同名环境变量读取 |
| 待审核 | Skill 市场中等待平台审核的公开条目 |

链接 `/admin/config?type=plugin` 会直接打开「插件」类型，[系统参数](/admin/params#插件) 页的「管理插件」按钮就指向这里。

### 内置 gonggong

MCP 列表最后一项是内置的 `gonggong` MCP，标记为「内置」，说明为「系统内置 · 始终注入，不受层级影响」，不能关闭，也不能用 `gonggong` 作为自定义 MCP 的名称。它为 Agent 提供向群成员提问、读取与检索聊天记录、群信息与成员、查看运行记录等工具，见 [系统架构](/guide/architecture#内置-mcp)。

### 添加 MCP

1. 点击「添加 MCP…」。
2. 选择**传输方式**：
   - **Stdio**：填写「命令」（如 `npx`）和「参数」（每行一个）。
   - **HTTP**：填写「URL」，必须以 `http://` 或 `https://` 开头。
3. 填写**名称**（如 `wiki-search`），不能与已有 MCP 重名。
4. 可选：展开「环境变量」（Stdio）或「请求头」（HTTP），点「添加一项」填写名称和值。**值只能引用密钥**，写成 `${secret:名称}`，运行时替换为实值；密钥在本页「密钥」或团队、群设置的「密钥」里维护。
5. 点击「添加」，新条目带「未保存」标记。
6. 确认无误后点击列表下方「保存」。

![「添加 MCP」对话框](/screenshots/web/admin-config-mcp.webp)

每个 MCP 右侧有开关（启用 / 停用）和删除按钮，改动同样要点「保存」才生效。

### Skill

点「添加 Skill…」，用「导入文件夹…」或「导入 zip…」上传，名称与描述取自 `SKILL.md` 开头的 frontmatter；每次保存生成一个新版本，可在历史版本里查看或「回滚到此版本」。与仓库自带的同名 Skill 冲突时跳过这里的版本，运行卡片会提示。成员「我的 Skill」只在自己发起的运行里生效，并优先于群、仓库、团队的同名 Skill。保存后相关 Bot 下一轮即可使用。

团队、群里也可以从 [Skill 市场](/user/market-plugins) 引入 Skill。

### 插件

插件需要先在 [系统参数](/admin/params#插件) 打开「插件」总开关。点「上传文件夹…」或「上传 zip…」上传含 `gonggong-plugin.json` 的插件；同名插件再次上传即生成新版本，下一轮任务生效。

- 内置插件随服务端自动安装，标记「内置」，不能覆盖或删除；要替换可以上传到团队或群里。
- 每个插件显示支持的 Agent、需要的密钥、最低机器版本、权限和带的 MCP 服务。
- 需要在机器上运行代码的插件（如本地 MCP 服务），还要打开「插件代码」开关，并由机器主人在自己的机器上逐个版本授权。

插件在群里的使用见 [市场与插件](/user/market-plugins)。

### 密钥

点「新建密钥…」，填写：

- **名称**：环境变量名，只能用大写字母、数字和下划线，以字母开头，如 `FEISHU_DEVOPS_TOKEN`。
- **用途**：做什么用，怎么申请。
- **模式**：「统一值」（所有人用同一个值）、「统一值可个人覆盖」（成员填了自己的值就用自己的）或「每人自填」（没有统一值，每人填自己的）。
- **可用 Bot**：「全部 Bot」或「指定 Bot」。
- **到期时间**：留空则不过期。
- **统一值**：至少 8 个字符，可稍后填写。

值加密保存，存入后任何人都看不到明文，只能覆盖或清除。运行时只以环境变量注入，输出里出现的密钥值会被打码。团队层、群层的同名密钥会覆盖平台层。更多见 [知识库与密钥](/user/knowledge-secrets)。

### 待审核

Skill 市场里的公开条目由平台管理员审核，仅本团队可见的条目由团队管理员在团队设置的「待审核」里审核。点某个版本的「审核」，可以看更新说明和与上一版本的文件差异，然后「通过」或「驳回」（驳回时必须填写审核意见）。

条目详情里，审核人还可以「封禁」已上架的条目（需填写封禁原因）：封禁后所有引入下一轮起停止加载，市场不再显示，也不能新引入；「解封」后恢复封禁前的状态。市场里也有同样的「待审核」页签，见 [市场与插件](/user/market-plugins)。

## 何时生效

MCP 保存后提示「已保存，全员下一轮新会话生效」：

- 默认情况下，运行中的轮次不受影响，已有会话继续使用旧配置，Bot 下次开新会话时才用上新配置。
- 勾选「强制相关 Bot 下一轮开新会话」再保存，受影响的 Bot 下一轮会放弃已有会话、按新配置重开，运行卡片会提示原因。代价是 Bot 会丢失之前会话里的上下文。

Skill、插件、密钥的改动在相关 Bot 的下一轮生效，不打断正在运行的任务。

添加、修改、删除平台层 MCP、Skill、插件、密钥都会写入 [审计记录](/admin/audit)。
