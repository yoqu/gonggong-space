# 配置中心

本页说明配置中心的分层叠加规则，以及目前能在这里配置什么。

![管理后台 · 配置中心](/screenshots/web/admin-config.webp)

## 分层叠加

Bot 在群里干活时，Agent 实际用到的配置由几层叠加而成，从低到高：

| 层 | 来源 | 优先级 | 状态 |
| --- | --- | --- | --- |
| 仓库基线 | 群绑定仓库里的 `.mcp.json`、`.claude/`、`AGENTS.md` 等 | 低 | 由仓库自身决定 |
| Bot 系统提示词 | 各 Bot 在 Bot 设置里填写 | — | 见 [Bot 设置与权限](/user/bot-settings) |
| 服务器全局层 | 配置中心里配置，对全部 Bot 生效 | 中 | 可用 |

冲突时服务器层优先。配置中心**不修改仓库文件**：

- 合并在 daemon 内存中完成。
- MCP 在新建会话时经 ACP 注入 Agent，不写入磁盘。

页面右侧「合并预览 · 全部 Bot」按层列出当前生效的内容。

## 能配置什么

顶部左侧的层级切换里只有「服务器全局层」可选；右侧的类型切换有「MCP」「Skill」「指令」「团队密钥」四项，目前可配置 MCP 与 Skill，其余类型显示「暂不支持」。团队层与群层的 Skill 在团队设置、群设置里管理，Agent 也可经内置 gonggong 的 `skill_*` 工具代发起人维护。

### 内置 gonggong

列表最后一项是内置的 `gonggong` MCP，标记为「内置」，始终注入，不受层级影响，也不能关闭。它为 Agent 提供向群成员提问、读取与检索聊天记录、群信息与成员、查看运行记录、提问卡片历史等工具，见 [系统架构](/guide/architecture#内置-mcp)。

### 添加 MCP

1. 点击「添加 MCP…」。
2. 选择**传输方式**：
   - **Stdio**：填写「命令」（如 `npx`）和「参数」（每行一个）。
   - **HTTP**：填写「URL」，必须以 `http://` 或 `https://` 开头。
3. 填写**名称**（如 `wiki-search`），不能与已有 MCP 重名。
4. 可选：展开「环境变量」（Stdio，每行一个 `KEY=VALUE`）或「请求头」（HTTP，每行一个 `Key: Value`）。
5. 点击「添加」，新条目带「未保存」标记。
6. 确认无误后点击页面底部「保存」。

![「添加 MCP」对话框](/screenshots/web/admin-config-mcp.webp)

每个 MCP 右侧有开关（启用 / 停用）和删除按钮，改动同样要点「保存」才生效。

::: warning 明文保存
MCP 的环境变量和请求头以**明文**保存在服务器配置中，只在新建会话时经 ACP 注入。不要在这里放高权限的个人密钥。
:::

## 何时生效

保存后提示「已保存，全员下一轮新会话生效」：

- 默认情况下，运行中的轮次不受影响，已有会话继续使用旧配置，Bot 下次开新会话时才用上新配置。
- 勾选「强制相关 Bot 下一轮开新会话」再保存，受影响的 Bot 下一轮会放弃已有会话、按新配置重开，运行卡片会提示原因。代价是 Bot 会丢失之前会话里的上下文。

添加、修改、删除全局层 MCP 都会写入 [审计记录](/admin/audit)。
