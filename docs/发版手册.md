# 发版手册

服务端怎么上线、客户端怎么发版，按当前流程写。细节与历史见 `docs/plan/发布与平台说明.md`。发版、数据库迁移前先在群里确认（CLAUDE.md 规则）。

## 服务端

### 正式环境 ai.ludoukj.com（自动）
- 推送 `gitlab main` 即触发 Jenkins 任务 `prod-gonggong-main`：server95（同机跑线上 `gonggong.service`）做 typecheck、lint、Rust 测试、web 构建，同时 master 跑 TS 测试 → 全绿后备份数据库、切换 release、重启服务、检查公网。约 3.5 分钟。
- 任一阶段失败就不部署；部署出错自动回滚代码和静态文件，**数据库迁移不回滚**（服务启动时自动迁移），带迁移的改动推送前先确认。
- 挂了由提交人立即修。查看状态：Jenkins 页面需登录，用 ego-browser 打开 `https://jenkins.crm.luxelakes.com/job/prod-gonggong-main/api/json?tree=builds[number,result]{0,3}`，日志在 `/<号>/consoleText`。
- 流水线脚本存在 Jenkins 任务配置里，不在仓库。

### 演示环境 gg.uyoqu.com（手动）
`root@124.220.45.104`，源码目录 `/srv/gonggong` + systemd `gonggong`：`git archive` 上传 → 先 `pg_dump` 备份到 `~/backups/` → 解压覆盖、写 `REVISION` → 以 gonggong 用户跑构建脚本（`sed '/git clone/d' /srv/gonggong-build.sh > /tmp/gg-build.sh && su -s /bin/bash gonggong -c 'bash /tmp/gg-build.sh'`）→ `systemctl restart gonggong` → 验 `https://gg.uyoqu.com/api/health`。

## 客户端（gg、gg-cast、桌面端）

### 发版前
1. 审查 `v<上一版>..main` 的改动，确认 `prod-gonggong-main` 最近一次构建全绿。
2. 写 `docs/release-notes/v<v>.md` 和 CHANGELOG 的 `## v<v> — <日期>` 条目。
3. 改过 `crates/gg-cast` 或 `scripts/release/cast.Dockerfile` 时，gg-cast 缓存失效：先在 Mac 上本地完整构建一次（下文「本机流程」），补齐缓存。

### 发版（Jenkins，默认）
在共字君这台 Mac 的仓库主工作区、`main` 分支上：
```bash
bash scripts/release/ship.sh <v>
```
- 本机只做：改版本号（两个 Cargo.toml、tauri.conf.json、Cargo.lock）、和说明一起提交、打 tag，推送 gitlab 与 origin。然后用钥匙串 `gonggong-jenkins` 里的令牌触发 Jenkins 任务 `gonggong-client-release`。
- Jenkins 两路并行构建：Mac 节点 `mac-yoqu` 打 macOS gg、桌面端 dmg（签名 + 公证）；master 打 Linux/Windows gg 和 Windows 安装包（cargo-xwin 交叉编译）。然后在 Mac 上汇总，发 GitHub Release，用凭据 `gonggong-release-admin` 上传 ai.ludoukj.com，最后 `ship.sh verify`。约 15 分钟。
- 盯任务：`https://jenkins.crm.luxelakes.com/job/gonggong-client-release/`。失败修好后可在 Jenkins 上用同一 `REF=v<v>` 重跑（上传会覆盖）；只想重试发布可只勾 `PUBLISH_*`，但构建两路必须都勾才会汇总。
- 前提：这台 Mac 开机、已登录、联网（Jenkins 节点 LaunchAgent `~/Library/LaunchAgents/com.luxelakes.jenkins-agent.plist`）。

### 只升级 daemon
`bash scripts/release/ship.sh <v> --daemon-only`：本机构建 5 个平台的 gg、复用 gg-cast 缓存，不打桌面端、不发 GitHub。之后用 MCP `client_release_publish`（`dir: "dist/<v>", kind: "daemon"`）上传，`ship.sh verify <v> <空间地址> --daemon-only` 校验。

### 本机流程（备用）
`GONGGONG_RELEASE_LOCAL=1 APPLE_NOTARY_PROFILE=lingji-material GONGGONG_SKIP_DOCKER_CAST=1 bash scripts/release/ship.sh <v>`（需开 Docker）：本机构建，Windows 安装包走 GitHub Actions，结束后用 `client_release_publish` 的 `dir: "dist/<v>"` 上传、`ship.sh verify` 校验。

### 发版后
- `bash scripts/release/ship.sh verify <v> https://ai.ludoukj.com`（Jenkins 已自动跑过；手动发布时自己跑）。
- 首次用新构建方式出的 Windows 安装包，要在 Win10/11 真机上装一次：安装、启动无黑窗、绑定跑一轮、「设置 → 版本」检查更新。

### 常见问题
- Bot 环境的代理让 `git push`、`gh` 失败：脚本已自行去掉代理，手动操作时先 `unset HTTPS_PROXY HTTP_PROXY https_proxy http_proxy`。
- Mac 节点离线：`launchctl kickstart -k gui/$(id -u)/com.luxelakes.jenkins-agent`，日志在 `~/jenkins-agent/agent.log`。
- master 上 Docker 拉镜像卡住：基础镜像要用 master 本地已有的固定版本 tag（如 `node:24.15.0-bookworm-slim`），浮动 tag 经镜像源重拉常卡死。
