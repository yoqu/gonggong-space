# 发版手册

服务端怎么上线、客户端怎么发版，按当前流程写。细节与历史见 `docs/plan/发布与平台说明.md`。发版、数据库迁移前先在群里确认（CLAUDE.md 规则）。

内部环境的地址、主机、Jenkins 任务与凭据名称不写在公开仓库里：完整手册在 GitLab 内部仓库 `tools/gonggong-ops`。发版前把那里的 `release.env.example` 复制为本仓库根目录的 `.env.release`、`internal-patterns.example` 复制为 `.internal-patterns`（两者都不入库）。

## 服务端

### 正式环境（自动）
- 推送 `gitlab main` 即触发 Jenkins 部署任务：typecheck、lint、Rust 测试、web 构建与 TS 测试并行，全绿后备份数据库、切换 release、重启服务、检查公网。约 3.5 分钟。
- 任一阶段失败就不部署；部署出错自动回滚代码和静态文件，**数据库迁移不回滚**（服务启动时自动迁移），带迁移的改动推送前先确认。
- 挂了由提交人立即修。任务地址与查看方法见内部手册。流水线脚本存在 Jenkins 任务配置里，不在仓库。

### 演示环境 gg.uyoqu.com（手动）
`git archive` 上传源码 → 先 `pg_dump` 备份 → 解压覆盖、写 `REVISION` → 以服务用户跑构建脚本 → 重启服务 → 验 `https://gg.uyoqu.com/api/health`。主机与命令见内部手册。

## 客户端（gg、gg-cast、桌面端）

### 发版前
1. 审查 `v<上一版>..main` 的改动，确认正式环境部署任务最近一次构建全绿。
2. 写 `docs/release-notes/v<v>.md` 和 CHANGELOG 的 `## v<v> — <日期>` 条目。
3. 改过 `crates/gg-cast` 或 `scripts/release/cast.Dockerfile` 时，gg-cast 缓存失效：先在 Mac 上本地完整构建一次（下文「本机流程」），补齐缓存。

### 发版（Jenkins，默认）
在发版 Mac 的仓库主工作区、`main` 分支上：
```bash
bash scripts/release/ship.sh <v>
```
- 本机只做：改版本号（两个 Cargo.toml、tauri.conf.json、Cargo.lock）、和说明一起提交、打 tag，推送 gitlab 与 origin。然后用钥匙串 `gonggong-jenkins` 里的令牌触发 Jenkins 任务 `gonggong-client-release`（地址取 `.env.release`）。
- Jenkins 两路并行构建：Mac 节点打 macOS gg、桌面端 dmg（签名 + 公证）；Linux 节点打 Linux/Windows gg 和 Windows 安装包（cargo-xwin 交叉编译）。然后在 Mac 上汇总，发 GitHub Release，上传到正式环境，最后 `ship.sh verify`。约 15 分钟。
- 失败修好后可在 Jenkins 上用同一 `REF=v<v>` 重跑（上传会覆盖）；只想重试发布可只勾 `PUBLISH_*`，但构建两路必须都勾才会汇总。
- 前提：发版 Mac 开机、已登录、联网（Jenkins 节点由本机 LaunchAgent 连接）。

### 只升级 daemon
`bash scripts/release/ship.sh <v> --daemon-only`：本机构建 5 个平台的 gg、复用 gg-cast 缓存，不打桌面端、不发 GitHub。之后用 MCP `client_release_publish`（`dir: "dist/<v>", kind: "daemon"`）上传，`ship.sh verify <v> <空间地址> --daemon-only` 校验。

### 本机流程（备用）
`GONGGONG_RELEASE_LOCAL=1 APPLE_NOTARY_PROFILE=<公证配置> GONGGONG_SKIP_DOCKER_CAST=1 bash scripts/release/ship.sh <v>`（需开 Docker）：本机构建，Windows 安装包走 GitHub Actions，结束后用 `client_release_publish` 的 `dir: "dist/<v>"` 上传、`ship.sh verify` 校验。

### 发版后
- `bash scripts/release/ship.sh verify <v> <正式环境地址>`（Jenkins 已自动跑过；手动发布时自己跑）。
- 首次用新构建方式出的 Windows 安装包，要在 Win10/11 真机上装一次：安装、启动无黑窗、绑定跑一轮、「设置 → 版本」检查更新。

### 常见问题
- Bot 环境的代理让 `git push`、`gh` 失败：脚本已自行去掉代理，手动操作时先 `unset HTTPS_PROXY HTTP_PROXY https_proxy http_proxy`。
- Mac 节点离线、Linux 节点 Docker 拉镜像卡住：处理方法见内部手册。
