# 团队分区与入群申请 开发计划

在已上线的侧栏 Slack 式分区（星标 / 个人分区 / 频道 / 私信，`4544e7d3`）之上，加一层**团队分区**：管理员预设分区，群被归入后全团队可见，没进群的人能直接加入（公开群）或申请加入（私有群）。

## 已定决策（姜维川 2026-11-08）

| 问题 | 决定 |
|---|---|
| 谁能把群归入团队分区 | 群管理员管自己的群；团队管理员（admin / owner）管所有群 |
| 未加入的群在哪里看到 | 侧栏团队分区里直接显示（灰色），点开即可加入或申请 |
| 私有群的入群申请谁审批 | 该群任一群管理员；站内通知 + 飞书卡片 |
| 与个人分区并存 | 侧栏顺序：星标 → 团队分区 → 个人分区 → 频道 → 私信；个人可把已加入的群挪到自己的分区，只影响自己 |

团队分区的增删改、排序只有团队管理员能做。

## 可见范围

- 群归入团队分区后，同团队成员都能看到它的**目录信息**：名称、头像、公告、人数、公开 / 私有、群管理员。消息、文件、运行一律仍需入群（团队管理员已有的只读查看 `requireReader` 不变）。
- 从团队分区移出后，私有群对非成员立即消失；已提交的申请自动取消。
- 私聊（DM）不能归入团队分区。

## 数据（一次迁移）

- `team_sections`：`id, team_id, name, position, created_by, created_at`。
- `groups.team_section_id`：可空，外键 `on delete set null`（删除团队分区后群回到各自的「频道」）。
- `group_join_requests`：`id, group_id, user_id, note, status(pending|approved|rejected|cancelled), decided_by, decided_at, created_at`；部分唯一索引 `(group_id, user_id) where status = 'pending'`，同一人同一群只能有一条待处理申请。
- 个人覆盖沿用 `group_members.section_id`：已加入的群放进个人分区时优先显示在个人分区。星标仍最优先。

## 接口

协议先改 `packages/protocol`：

- `GroupDto.teamSectionId`；新增 `TeamSectionDto`、`DirectoryGroupDto { id, name, avatar, notice, memberCount, visibility, teamSectionId, admins, myRequest: 'pending' | null }`、`JoinRequestDto`。
- 通知类型新增 `join_request`（给群管理员）、`join_decided`（给申请人）。

| 接口 | 权限 | 说明 |
|---|---|---|
| `GET /api/team-sections` | 团队成员 | 按 position 排 |
| `POST / PATCH /:id / DELETE /:id / PUT /order` | 团队管理员 | 审计 `team.section.*` |
| `PUT /api/groups/:id/team-section { teamSectionId \| null }` | 群管理员或团队管理员 | 群内事件「{user} 将本群归入团队分区「{section}」」/「移出团队分区」，审计；推送给全团队（目录变了） |
| `GET /api/team-directory` | 团队成员 | 团队分区里我**没加入**的群 |
| `GET /api/groups/:id/preview` | 团队成员，且群在团队分区里 | 未入群时打开群看到的预览数据 |
| `POST /api/groups/:id/join` | 已有接口，放宽为：公开群，或归入团队分区的公开群 | 直接加入 |
| `POST /api/groups/:id/join-requests { note? }` | 团队成员，私有且在团队分区 | 通知全部群管理员（站内 + 飞书卡片「同意 / 拒绝」） |
| `DELETE /api/join-requests/:id` | 申请人 | 撤回 |
| `GET /api/groups/:id/join-requests` | 群管理员 | 待处理列表 |
| `POST /api/join-requests/:id/approve` · `/reject` | 群管理员 | 同意即入群，发群内事件「{admin} 同意 {user} 加入群」；通知申请人；其他管理员的通知标为已处理（`resolveNotifications`） |

审批流程照 Bot 共享申请（`bot_share_request` / `bot_share_decided`）的现成写法：通知、飞书卡片回调、重复处理时提示「已被 {name} 处理」。

实时：归入或移出团队分区、入群后，向全团队推送 `directory.changed`，客户端重新拉取 `/team-directory`。申请状态变化推给申请人和群管理员。

## 前端

- **侧栏**：团队分区在星标下面，标题带「团队」小标。里面先列我已加入的群（正常样式），再列未加入的（灰色，标签「未加入」或「已申请」）。只有团队管理员看到标题右侧的「…」（重命名 / 上下移 / 删除）。「＋ 新建分区」对团队管理员弹出两个选项：个人分区 / 团队分区。
- **未加入的群点开**：`/g/:id` 显示预览页：头像、名称、公告、人数、群管理员；公开群显示「加入」，私有群显示「申请加入」（可附一句说明），已申请显示「已申请 · 撤回」。被拒绝后可以再次申请。
- **归类入口**：会话右键新增「归入团队分区 ▸」（有权限才出现）；群设置「成员」页加「团队分区」下拉。个人的「移到分区」不变。
- **审批入口**：通知面板的申请条目可直接同意 / 拒绝；群设置「成员」页顶部显示「入群申请 · N」列表；飞书卡片按钮。
- 拖拽：会话拖到团队分区等同「归入团队分区」（需权限，没有权限时不接收拖放）。

## 分步与验收

每步 TDD：服务端集成测试 → web 组件测试，最后补一条 e2e。

1. **团队分区 + 归类**（含迁移）：管理员建分区；群管理员 / 团队管理员归入、移出；侧栏显示已加入的群；个人分区覆盖与星标优先级正确。
   - 测试：普通成员不能建团队分区（403）；非群管理员不能归类自己不管的群；删除分区后群回到「频道」；DM 不能归入。
2. **目录与预览**：侧栏显示未加入的群（灰色）；预览页；公开群直接加入。
   - 测试：非团队成员看不到目录；目录不含消息；移出团队分区后私有群从别人的侧栏消失。
3. **入群申请与审批**：申请、撤回、同意、拒绝；站内通知 + 飞书卡片；重复处理提示。
   - 测试：同一人只能有一条待处理申请；非群管理员审批 403；同意后成为成员并有群内事件；移出团队分区时待处理申请自动取消。
4. e2e：管理员建分区 → 群管理员归类 → 另一成员在侧栏看到灰色群 → 申请 → 群管理员同意 → 成员进群。

涉及数据库迁移，推送前需确认。
