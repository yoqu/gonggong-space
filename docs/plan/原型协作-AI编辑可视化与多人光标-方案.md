# 原型协作：AI 编辑可视化 + 多人光标 · 方案

> 提出：姜维川 2026-11-19。状态：方案待拍板，未开工。现状见 `docs/domains/产物与原型编辑器.md`。

## 一、现状与问题

| # | 现象 | 根因（代码） |
|---|------|------|
| 1 | AI 不知道该改哪个原型 | 自然语言 @Bot 时 `RunStart.artifacts` 最多下发 20 个产物（`runArtifacts`），模型只能猜；只有画布指令/批注/上下文芯片才带明确产物 |
| 2 | 用户看不出 AI 在改哪里 | `ArtifactDto.running` 只表示「被检出」，粒度=整个产物；跑完才上传新版本，画布才变 |
| 3 | 过程生硬 | 结束时整屏 iframe 换新版本，无过渡、无改动标记 |
| 4 | 看原型的人彼此不可见 | 无 presence；web WS 客户端消息只有 focus/visible（≤1KB），分享页访客无连接 |

已有可复用的底座：
- daemon 已从 ACP `tool_call` 的 `kind=edit|delete|move` + `locations` 收集改动文件（`turn.rs` `tool()`、`session.rs` `changes_steering`），**与 Agent 种类无关**；Codex 的 shell 改动无 locations，靠文件扫描兜底。
- 桥接已上报 `anchors`、`rect`、`covers`、滚动位置（`BridgeToShell`），屏内元素可按 `data-gg-anchor` / `data-section` 定位。
- 服务端内存总线 `ctx.bus` + `/ws/web`，单实例。

## 二、核心思路：AI 是一个特殊的「在场者」

人和 AI 共用一套在场（presence）模型：谁、在哪个产物、哪一屏、哪个区域、在做什么。人显示为光标，AI 显示为「正在编辑」的粒子区域 + 头像标签。只做一套渲染层和传输通道。

信号三层，从可靠到精细：

1. **事实层（被动，必做）**：daemon 把 edit 类工具调用的路径映射到 `design/<slug>/screens/<id>.html` → 产物 + 屏，发 `RunEvent::ArtifactActivity { artifactId, file, phase: editing|done }`。Codex 等无 locations 的，用已检出产物目录的文件变动兜底（防抖 500ms）。不依赖 Agent 配合，所有 ACP Agent 都生效。
2. **意图层（主动，MCP）**：新增 gonggong 工具 `artifact_focus({ artifact, screens?, anchors?, intent })`，Agent 开改前声明「改哪个产物、哪几屏、哪些区块、要做什么」；产物不明确时返回候选列表让 Agent 反问用户，不再瞎猜。web-prototype SKILL.md 加硬规则「动手前先调 artifact_focus」。所有接入 gonggong MCP 的 Agent 可用（与 #17182「扩充非 Claude/Codex Agent」并行，互不阻塞）。
3. **内容层（区块级）**：daemon 写入屏文件后防抖推送「草稿差异」：按 `data-section` / `data-gg-anchor` 比对 head 与当前文件，只上报变了的区块 id（不传整份内容）。画布用桥接的 rect 把粒子效果精确落到这些区块上。

## 三、交互设计

### AI 编辑中
- **入口定位**：群输入框 @Bot 时，若工作台正开着某产物，自动带上该产物的上下文芯片（可移除）——这是解决「改哪个原型」成本最低、收益最大的一步。
- **群聊运行卡片**：显示「正在改 · 《外卖小程序》› 登录页 › 底部按钮区」，点击打开画布并定位。
- **画布**：
  - 屏级：被改的屏边框流光 + 右上角 Bot 头像胶囊「Claude 正在改 · 调整按钮样式」；未被改的屏不动。
  - 区块级：被改区块覆盖粒子波浪（Canvas 2D 粒子沿区块轮廓流动，Bot 主题色），画在 iframe 上层的覆盖层，不进屏内 DOM。
  - 「跟随 AI」开关：视口自动平移到正在改的屏（类 Figma follow），用户手动拖动即退出跟随。
- **完成过渡**：新版本到达时旧截图 → 新屏做波纹式擦除（约 600ms），改动区块描边闪 1.5s 后淡出，屏标题旁「改了 3 处」可逐处跳转。
- 性能与无障碍：只给视口内的屏跑动画，≤30fps，离屏暂停；`prefers-reduced-motion` 改为静态虚线框 + 文字。

### 多人光标
- **范围**：画布、原型预览、分享页（访客）。
- **身份**：登录用户用昵称 + 头像色；访客随机名（「匿名的水獭」这类形容词+动物），存 localStorage，同一浏览器保持不变；颜色按 id 哈希。
- **坐标**：画布用世界坐标；屏内用「屏 id + 最近锚点/元素 + 元素内相对位置」，各自缩放、滚动、设备宽度不同也能落在同一元素上；找不到元素时退回屏内百分比。
- **呈现**：箭头 + 名字胶囊，30s 无动作淡出；顶栏头像堆「3 人在看」，点头像跟随此人视口；原型预览的屏幕列表上挂小头像点表示谁在哪一屏；对方选中的元素用其颜色描边。
- **传输**：`/ws/web` 增加 `presence` 客户端消息（发送节流 20Hz、接收端插值平滑）；服务端按产物分房间内存转发，不落库；分享页新增 `/ws/share/:token` 只读通道（校验分享令牌与密码），访客只能发自己的光标。房间内最多显示 30 个光标。
- **设置**：「隐藏我的光标」开关；私有档产物（`private`）不广播。

## 四、分期

| 期 | 内容 | 端 | 迁移 |
|---|---|---|---|
| P1 | 输入框自动带当前产物芯片；daemon `ArtifactActivity`（事实层）；运行卡片与画布屏级「正在改」+ 完成过渡 + 跟随 AI | web + server + daemon + protocol fixture | 无 |
| P2 | MCP `artifact_focus` + SKILL 规则；区块差异上报；区块级粒子动效 | server + daemon + web + 插件 | 无 |
| P3 | 成员多人光标（画布 + 原型预览），头像堆、跟随、选中描边 | web + server | 无 |
| P4 | 分享页访客光标与随机名；可选：AI 写一半的实时草稿预览 | web + server | 无 |

全程不需数据库迁移（在场信息与活动都是临时的，走运行事件和内存总线）。P1/P2 改 daemon 协议，需要发新版客户端（按约定交共字君codex 发版）；旧 daemon 只有 `running`，界面退回现在的产物级状态。

## 五、验收标准

- 同群 3 个产物，在画布开着 A 时 @Bot「把按钮改成圆角」：消息自动带 A 的芯片，Bot 只改 A。
- 不带芯片且有歧义时，Bot 调 `artifact_focus` 收到候选，反问用户而非直接改。
- Claude Code、Codex、其他 ACP Agent 各跑一轮：画布在 2s 内标出正在改的屏；P2 后标到区块。
- 完成后改动区块闪烁标记，「改了 N 处」可逐处跳转；减少动效模式无动画。
- 两个浏览器（一成员、一分享页访客）同看一个产物：彼此光标在同一元素上，访客显示随机名且刷新不变；成员关掉「显示我的光标」后对方看不到。
- 画布 20 屏、5 人在线时滚动保持 60fps（Performance 面板验证）。
