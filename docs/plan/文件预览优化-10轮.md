# 文件预览优化（10 轮）

范围：网页里所有文件预览与入口。参考 macOS Quick Look、Google Drive、Dropbox、飞书：点开即看、看不了就明确给下载/外部打开、全屏看图、同目录前后切换、手机端触屏可用。

代码：`features/files/`（FileViewer、OfficeView、files.css）、`features/attachments/`（MessageAttachments、AttachmentViewer、ComposerAttachments）、`features/workbench/tabs/`（FilesTab、FileTab）、`features/market/ListingFiles.tsx`、`ui/lightbox.*`、`ui/im/cards.tsx`（FileAttachment）。

## 盘点（第 1 轮，按严重度）

| # | 严重度 | 类型 / 入口 | 问题 |
|---|---|---|---|
| 1 | 高 | 视频、音频、图片 / 全部入口 | 浏览器播不了的格式（mkv、avi、heic，服务端不在 inline 白名单的 aac 等）只剩黑框/破图，无任何提示与下载入口 |
| 2 | 高 | 灯箱 / 消息图片、输入框图片 | 第 9 轮启用 `viewport-fit=cover` 后，灯箱顶栏（含关闭键）被刘海/状态栏遮挡；图片高 `100vh-80px` 在手机 Safari 上被底部横条截断 |
| 3 | 高 | PDF / 文件 Tab、文件树、市场 | iOS Safari 的 iframe 只显示 PDF 首页且不能滚，无「在浏览器中打开」兜底 |
| 4 | 高 | PDF / 消息附件 | 附件路由把 PDF 当下载返回，预览页显示「暂不支持预览」（需服务端 inline + sandbox） |
| 5 | 中 | 图片 / 文件 Tab、文件树、市场 | 预览里的图片不能点开全屏缩放，只能「适应 / 1:1」 |
| 6 | 中 | Word、Excel、PPT / 消息附件 | 卡片写「文件 · 12 KB」，不说是什么、也不提示可预览（实际能预览） |
| 7 | 中 | 音频、视频 / 消息附件 | 音频要打开工作台才能播；视频缩略图点开也进工作台，手机上跳转重 |
| 8 | 中 | 全部 / 文件预览工具栏 | 窄屏按钮挤占文件名，触控热区 28px；没有文件大小/类型信息 |
| 9 | 中 | 文件树 / 工作区、市场、搜索结果 | 所有文件同一个灰色文档图标，看不出类型 |
| 10 | 中 | Word、PPT / 预览 | 暗色主题下仍是浅灰底大白框；PPT 宽度只在首次渲染时计算，拖宽面板不跟随 |
| 11 | 中 | Excel / 预览 | 行号列横向滚动不固定（缺 sticky 角格/层级）；sheet 多时标签溢出 |
| 12 | 中 | 文本、代码 / 预览 | 长行只能横向滚（手机上难读），无自动换行开关、无「复制内容」 |
| 13 | 低 | Markdown / 预览 | 宽屏行宽无上限；相对路径图片不显示 |
| 14 | 低 | 全部 / 文件 Tab | 不能在同目录前后切换文件（Quick Look 的 ←/→） |
| 15 | 低 | 音频 / 预览 | 只有一根播放条贴在顶部，没有文件名/图标，空旷 |
| 16 | 低 | 全部 | 切换文件内容硬切；图片加载过程无过渡 |
| 17 | 低 | 输入框附件 | 非图片附件发送前无法预览；只有图片能放大 |

## 新发现（各轮补充）
- 第 1 轮：`viewKind` 把 heic/mkv/avi 视作可预览类型，实际多数浏览器不支持——已由失败兜底覆盖，暂不按浏览器能力区分。
- 第 2 轮：网上有「`CSP: sandbox` 让 Chrome PDF 查看器被拦截（ERR_BLOCKED_BY_CLIENT）」的报告；用本机 Chrome 实测仅 `sandbox` 时 iframe 与新标签页都能正常显示 PDF，故保留 sandbox。若日后加 `default-src 'none'` 等更严 CSP，需对 PDF 单独放行。
- 第 2 轮：消息里视频格子只有 16:10 小尺寸，竖屏视频就地播放时两侧留黑，需全屏靠原生控件；可在第 9 轮考虑点开放大的弹层。
- 第 2 轮：PDF 附件仍进工作台预览（手机上是全屏右栏）；手机 iframe 只显示首页的问题由第 6 轮的「在浏览器中打开」主按钮卡片处理。
- 第 3 轮：从聊天里的路径直接打开的工作区媒体文件（不经文件树）不知道大小，元信息只显示类型；如需补齐可对 raw 发 HEAD 读 Content-Length。
- 第 3 轮：只有 viewBox、没有 width/height 的 SVG 在预览里渲染成 0×0（看不见），建议第 10 轮给适应模式加最小尺寸。
- 第 3 轮：手机上 Markdown 的「预览/源码」切换仍占约 1/3 宽，长文件名只能显示十来个字；可在第 5 轮考虑改成图标切换。
- 第 4 轮：所有 `.ui-btn` 没有 `aria-pressed` 的视觉状态，宽屏「注解」按下后看不出来；本轮只在预览工具栏内补了底色，其他处的切换按钮可在第 10 轮统一。
- 第 4 轮：不换行时长行的高亮行（`pv-line--hit`）、注解底色只铺到可视宽度，横向滚动后右侧没有底色；换行模式下无此问题。
- 第 4 轮：自动换行的续行与行首对齐，不保留代码缩进（GitHub/VS Code 同）；如需悬挂缩进需逐行计算，暂不做。
- 第 5 轮：历史版本（`rev`）里的 Markdown 相对图片取的是工作区当前文件（git 路由只给文本），旧版本图片已删时会显示兜底文字。
- 第 5 轮：相对链接里的 `other.md#小节` 只打开文件，不跳到小节；如需要可给文件标签页加锚点参数。
- 第 5 轮：消息附件里的 Markdown 没有「所在目录」，相对图片/链接仍不可用（无从解析）。
- 第 5 轮：代码行高亮 `pv-line--hit` 用的是实色 `--accent-fill`，与文字对比偏强，可在第 10 轮统一为浅色底。
- 第 6 轮：Chrome 内嵌查看器标题栏显示的是 URL 末段（raw 路由为 `raw`/附件 id），无法从页面控制；如需显示文件名，可让 raw 路由支持 `/raw/<文件名>?path=` 形式的路径。
- 第 6 轮：触屏判断按 `pointer: coarse` 一次性取值；带触控板的 iPad 视为精确指针仍会内嵌（iPadOS Safari 内嵌可整页滚动，可接受）。
- 第 6 轮：触屏卡片与工具栏都有「在浏览器中打开」，略重复；工具栏保持各类型一致，暂不隐藏。
- 第 7 轮：手机上 Word 按页宽缩到约 0.42 倍，字偏小（与 Google Drive 手机端一致，可双指放大整页）；如需「重排为单栏阅读」需要放弃分页，暂不做。
- 第 7 轮：Excel 只取单元格值（read-excel-file），不还原合并单元格、列宽、冻结窗格、颜色与公式；需要时可换 SheetJS（体积约 +400KB），先观察反馈。
- 第 7 轮：PPT 渲染依赖 pptx-preview，图表/SmartArt/动画不支持；幻灯片无页码，后续可在每页角上加「n / N」。
- 第 7 轮：Office 框是 about:blank（quirks 模式）；如再遇到继承类样式问题，可改为写入带 doctype 的 srcdoc。
- 第 8 轮：PDF/Word/PPT 在 iframe 里，焦点进框后 ←/→ 由框内处理（翻页失效），需先点框外或用按钮；无法也不应跨框监听。
- 第 8 轮：翻页后文件重新挂载，键盘焦点落回页面（不停在翻页按钮上），继续按 ←/→ 不受影响；读屏用户按按钮翻页需重新定位，可在第 10 轮考虑把焦点移到新文件标题。
- 第 8 轮：手机上未做左右滑动翻文件（与代码/表格横向滚动、系统返回手势冲突），只用底部按钮；消息附件（非图片）之间不能翻，每个附件各占一个标签页。
- 第 8 轮：文件树 ↑↓ 只移动焦点不自动预览（避免连按时逐个请求），回车打开；如需 Finder 式跟随预览可加防抖。
- 第 8 轮：行号只能用鼠标/触摸点选，键盘用户靠「复制路径」；所选行不写进标签页状态，刷新后消失。
