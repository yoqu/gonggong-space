# 模型与推理强度：服务端配置 + 对话内切换

## 目标

模型、推理强度从 daemon 本机配置迁到服务端。daemon 只负责探测上报可选项、执行切换。

生效优先级（高 → 低）：

1. **单条临时**：输入栏下方为本条消息选择，只作用于这条消息直接触发的运行
2. **群内默认**：群 × Bot 粘性设置
3. **Bot 默认**：新建/编辑 Bot 时设置
4. **适配器默认**

## 决策

| # | 决策 |
|---|---|
| M1 | 可切换者：私聊 = 成员；群聊 = Bot 主人 + 群管理员；Bot 默认 = Bot 主人或系统管理员。其他人看到当前生效值，选择器只读 |
| M2 | 单条临时只通过输入栏下方的选择器，不提供命令或参数语法；选择器替代「未 @ 的消息…」提示 |
| M3 | 选项取被 @ 的 Bot 所在机器上报的目录；@ 多个 Bot 时每个 Bot 一个选择器 |
| M4 | 单条临时不传给接力链后续跳 |
| M5 | 运行中改群内默认，从下一轮生效 |
| M6 | 本机 `local.json` 的模型、推理强度字段删除，不迁移（旧字段读取时忽略）；CLI 路径、命令审批、白名单仍留本机（D15） |
| M7 | 服务端校验取值在目录内；目录为空时只允许「跟随默认」 |
| M8 | 推理强度按模型不同（两个适配器均如此，已核实源码与实测）：目录按模型带档位和起始档位；服务端解析时推理强度不属于该模型则退回该模型的起始档位，并总是下发具体值，避免单条临时指定残留到下一轮 |

## 协议

- `AgentInfo.catalog: { models: [{ value, name, description?, efforts, effort }], current, efforts, effort } | null`，随 hello / `agents.update` 上报；适配器的 `default` 行不入目录（null 即表示适配器默认）
- `RunStart.bot.model / effort`：服务端解析后的值
- `d2s session.config { runId, model, effort }`：本轮实际生效值
- `SendMessageReq.runOptions: Record<botId, { model?, effort? }>`；`PUT /api/groups/:id/bots/:botId/config { model, effort }`
- `BotDto / GroupBotStateDto / RunDto` 增加 `model / effort`，`BotDto.catalog`

## 实现要点

- **daemon**：启动时及 CLI / 适配器版本变化时，开临时会话读取配置项，逐个切换模型读取推理强度档位（不发 prompt，不写用户设置），结果缓存到 `<home>/models.json`（按 CLI+适配器版本作键）；每轮 `configure()` 按下发值切换，切换模型后清除已应用记录，然后回报 `session.config`
- **服务端**：`bots / group_bots / runs` 增加 `model / effort`（迁移 0015）；`modules/bots/config.ts` 负责鉴权、目录校验与解析；派发时写入 `runs`，`session.config` 回写实际值；改群内默认时发系统消息「X 将 Bot 在本群的模型设为 Opus · 高」
- **Web**：新建/编辑 Bot 的「模型」「推理强度」；输入框底栏每个被 @ 的 Bot 一个选择器（选中后标「仅本条」，可「设为本群默认」）；运行侧栏显示本轮模型
- **桌面端 / CLI**：移除模型与推理强度设置，Agent 页只读展示可用模型
