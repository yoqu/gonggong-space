# 模型与推理强度：服务端配置 + 对话内切换

## 目标

模型、推理强度从 daemon 本机配置迁到服务端。daemon 只负责上报可选项、执行切换。

生效优先级（高 → 低）：

1. **单条临时**：输入栏下方为本条消息勾选，只作用于这条消息直接触发的运行
2. **群内默认**：群 × Bot 粘性设置
3. **Bot 默认**：新建/编辑 Bot 时设置
4. **适配器默认**

## 决策

| # | 决策 |
|---|---|
| M1 | 可切换者：私聊 = 本人；群聊 = Bot 主人 + 群管理员；Bot 默认 = Bot 主人。其他人看到当前生效值，不可改 |
| M2 | 单条临时只通过输入栏下方的选择器，不提供命令或参数语法 |
| M3 | 选项按被 @ 的 Bot 的 agent 类型与所在机器的目录（catalog）给出；@ 多个 Bot 时每个 Bot 一个选择器 |
| M4 | 单条临时不传给接力链后续跳；接力按各 Bot 自身的群内默认 / Bot 默认 |
| M5 | 运行中改群内默认，从下一轮生效 |
| M6 | 本机 `local.json` 的模型、推理强度字段直接删除，不迁移；CLI 路径、命令审批、白名单仍留本机（D15） |
| M7 | 服务端校验取值在目录内；目录为空（机器未上报）时只允许「跟随默认」 |

## 协议（`packages/protocol` + fixtures + `protocol.rs`）

- `AgentInfo.catalog: { models: Choice[], current, efforts: Choice[] 按模型 } | null`，随 `agents.update` 上报。`Choice = { value, name, description? }`；推理强度随模型变化，结构为 `models[].efforts`
- `RunStart.bot` 增加 `model: string | null`、`effort: string | null`（服务端按优先级算好）
- 新增 `d2s session.config { runId, model, effort }`：本轮实际生效值，供界面显示与用量统计

## 服务端

- `bots.model / bots.effort`、`group_bots.model / group_bots.effort`、`runs.model / runs.effort`（可空）
- Bot DTO 带 `model / effort / catalog`（catalog 取绑定机器 `agents` 中对应类型）
- `PATCH /api/groups/:gid/bots/:bid/agent-config { model, effort }`：群内默认，M1 鉴权，写系统消息「王磊 将 小王的 Claude 切换为 Opus · 高」并审计
- 发消息请求增加 `runOptions: Record<botId, { model?, effort? }>`：M1 鉴权、M7 校验，写入对应 run
- 创建运行时按优先级解析写入 `runs`，`run.start` 从 run 取值；`session.config` 回写实际值
- 用量按模型汇总

## daemon

- 检测到 agent 后探测：临时新建会话读取配置项，逐个模型读取推理强度档位，关闭进程，结果随 `agents.update` 上报；适配器升级后重新探测
- `configure()` 改读 `req.start.bot.model/effort`；失败仍回报运行步骤；成功后发 `session.config`
- 删除 `AgentSettings.default_model/effort`、`BotSettings.model`、`models.json`、`gg config agent --model/--effort`、`gg config bot --model`

## Web

- **输入栏下方选择器**：草稿中每个被 @ 的 Bot（私聊为对方 Bot）一个芯片「小王的 Claude · Opus · 高」
  - 弹层分「模型」「推理强度」两组单选，推理强度随所选模型刷新；底部「设为本群默认」开关（打开即调 PATCH）
  - 默认显示群内生效值；改动仅作用于本条，发送后复位
  - 无权者芯片只读；目录为空时显示「跟随默认」并提示机器未上报
- **新建/编辑 Bot**：增加「模型」「推理强度」选择器；未绑定机器时仅「跟随默认」
- 运行卡片显示本轮模型（取 `session.config`）

## 桌面端
