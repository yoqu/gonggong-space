# 发布与平台说明

## 产物（`bash scripts/release.sh`，输出到 `dist/<版本>/`）
| 平台 key（daemon 上报的 `<os>-<arch>`） | 文件 | 构建方式 |
| --- | --- | --- |
| macos-aarch64 / macos-x86_64 | `aiws-<v>-macos-<arch>` | 本机 rustup 工具链交叉编译 |
| linux-x86_64 / linux-aarch64 | `aiws-<v>-linux-<arch>` | Docker `rust:1.98-bullseye` 交叉编译（glibc ≥ 2.31：Ubuntu 20.04+、Debian 11+、RHEL 9+） |
| windows-x86_64 | `aiws-<v>-windows-x86_64.exe` | 同一容器内 mingw-w64（`x86_64-pc-windows-gnu`） |
| 桌面端（仅 macOS） | `AIWS Daemon_<v>_<arch>.dmg` | `tauri build --bundles app,dmg`（`apps/desktop`） |

另有 `SHA256SUMS` 与 `manifest.json`（D17：`{version, builds: {<os>-<arch>: {url, sha256}}}`）。版本号取自 `crates/aiws/Cargo.toml`。容器只构建 `-p aiws`，不需要 webkit；Linux / Windows 桌面安装包不在 P1 范围。TLS 继续用 rustls + aws-lc-rs：所有目标都用 cc 编译 aws-lc，Windows 用 `prebuilt-nasm`，不需要 cmake / nasm / clang，所以没有换成 ring。`--only macos-aarch64,desktop` 这类参数可以只构建部分产物。

## 发布
```bash
AIWS_DATA_DIR=<服务器数据目录> AIWS_ADMIN_PASSWORD=… bash scripts/release.sh --publish https://aiws.example.com
```
脚本会把产物复制到 `$AIWS_DATA_DIR/downloads`（由服务器的 `GET /downloads/:file` 提供下载），再以管理员身份 `PUT /api/admin/daemon-release`。自签证书时加 `AIWS_CACERT=cert.pem`；产物放在 CDN 时设 `AIWS_DOWNLOAD_BASE=https://cdn/...`。在线的 daemon 连上后，下载与自己平台匹配的新版本并校验 sha256，没有运行中的轮次时替换自身并重启。ACP 适配器的版本锁定在 daemon 里（D19），随 daemon 一起升级。

## 成员机器要求
- git；Node.js ≥ 22 和 npm（首次运行时把 ACP 适配器装到 `~/.aiws/adapters/`）；Claude Code 和/或 Codex CLI 由成员自己安装并登录。
- Windows：用的是 `node.exe`、`claude.exe` 或 npm 生成的 `*.cmd` 启动脚本，查找路径包括 PATH、`%APPDATA%\npm` 和 `~/.local/bin`；自升级时先把正在运行的 exe 改名，再替换新文件。

## 验证方式（D16）
- **macOS**：全量 E2E 在真机上跑，沿用 M5。发布演练 `bash scripts/release/rehearse.sh` 已通过：构建全部产物 → 发布到本地服务器 → 用同一份源码打的 0.0.1 旧版 daemon 绑定后自动下载 macos-aarch64 产物，校验、替换、重启，然后以 0.1.0 上线；替换后的文件 sha256 与 manifest 一致。
- **Linux**：`bash scripts/release/cross-test.sh linux` 在 bullseye 容器里跑 `cargo test -p aiws`，全部通过（和 macOS 的测试集相同，包括 mock agent、git、TLS）。`bash scripts/linux-e2e.sh` 已通过：服务器跑在本机（新建数据库，开发用 TLS 证书）；Linux 版 aiws 跑在 bookworm 容器里（带 Node 22 和 mock ACP agent），用绑定码加 `--fingerprint` 经 https 绑定，证书固定生效。通过 API 触发两轮：无仓库群，回复含 `Linux` 和 Node 版本；仓库群，从 `file://` 裸仓库克隆，回复含 README 内容和提交信息。两轮状态都是 completed。容器里不跑真实 Claude Code，因为容器内没有登录。
- **Windows**：没有真机。`bash scripts/release/cross-test.sh windows` 能交叉编译出全部测试二进制（`cargo test --no-run`）和 release exe，但都没有运行过：尝试在模拟的 amd64 容器里装 Wine，apt 安装一直失败，已放弃。集成测试依赖 git、node 和 sh，Windows 上没有运行过；适配器在 Windows 上的实际运行（包括 `.cmd` 启动脚本）也没有验证。

## 注意
脚本通过 `docker cp` 把源码传进容器，不用目录挂载。本机 Docker Desktop 的 API 代理启动容器时会卡住，这次是临时把 `DOCKER_HOST` 指向 `~/Library/Containers/com.docker.docker/Data/docker.raw.sock` 跑的，脚本本身不依赖这个设置。
