# 浅色主题开发计划

目标：新增浅色主题，**默认浅色**；保留现有深色主题，用户可切换。Web 与 Daemon 桌面端（复用 `@web/styles`）同时生效。

## 1. 现状

| 项 | 现状 |
| --- | --- |
| 色彩 token | `apps/web/src/styles/colors.css` 单一 `:root`，`color-scheme: dark`，macOS 深色调色板 |
| 阴影 | `styles/shadows.css` 按深色背景调的高不透明度黑影 |
| CSS 硬编码色 | 约 150 处，集中在 `ui/ui.css`(40)、`chat.css`(15)、`admin.css`(15)、`shell.css`(14)、`bots.css`(12)、`runs.css`(11) 等；多为 `rgba(255,255,255,x)` 白色叠加，浅色下不可见 |
| TSX 硬编码色 | 9 个文件约 28 处：`toast.tsx`、`Sidebar.tsx`、`bots/model.ts`、`NewBotDialog.tsx`、`NewGroupDialog.tsx`、`ConfigPage.tsx`、`BindMachineDialog.tsx`、`NotificationPanel.tsx`、`controls.tsx` |
| 桌面端 | `apps/desktop/src` 约 29 处硬编码（`desktop.css` 17 处 + labels/页面） |
| 偏好存储 | 无主题相关代码、无用户偏好字段 |
| 原型 | 只有深色；P1 决策 D10「一期只做深色」本计划将其替换 |

## 2. 决策

| # | 项 | 结论 |
| --- | --- | --- |
| T1 | 可选项 | 浅色（默认）· 深色 · 跟随系统 |
| T2 | 切换机制 | `<html data-theme="light\|dark">`；`colors.css` 中 `:root` 放浅色，`[data-theme="dark"]` 覆盖为深色 |
| T3 | 偏好存储 | 本机 `localStorage`（键 `gonggong.theme`），不入库、不改协议；多设备同步需求出现再迁到服务端 |
| T4 | 首屏闪烁 | `index.html` 内联脚本在 React 挂载前写 `data-theme` |
| T5 | 切换入口 | Web：`AccountMenu` 增加「外观」三选一；桌面端：设置页同样三选一 |
| T6 | 浅色调色板 | 取 macOS 浅色系统色与深色一一对应（如 system blue `#007aff`、red `#ff3b30`、green `#34c759`、orange `#ff9500`）；状态色、强调色通过 token 引用，不再写死 |
| T7 | 业务色常量 | TSX 里的颜色一律改为 `var(--color-*)` 字符串，由 CSS 按主题解析 |

## 3. 切片（TDD，每片测试全绿 + typecheck + lint）

### S1 token 分层与主题基础设施
- `colors.css`：拆成浅色 `:root` + `[data-theme="dark"]`；`color-scheme` 随主题；补齐缺失语义 token：`--color-overlay-hover`、`--color-scrollbar`、`--color-on-accent`（按钮上的白字）、`--color-selection`、`--color-status-offline` 等，覆盖现有硬编码用途。
- `shadows.css`：阴影强度随主题分两套。
- 新增 `src/app/theme.ts`：`getTheme / setTheme / resolveTheme`，监听 `prefers-color-scheme`（仅「跟随系统」时）。
- `index.html` 内联脚本（T4）。
- 测试：`theme.test.ts` 覆盖默认浅色、持久化、跟随系统随媒体查询变化、非法值回落浅色。

### S2 清除 CSS 硬编码
- 按文件逐个把 `#hex` / `rgba()` 替换为 token（`ui.css` → `shell.css` → 各 feature）。
- 仅窗口红绿灯这类固定品牌色可保留，其余一律 token 化。
- 验收：`grep -rE "#[0-9a-fA-F]{3,8}\b|rgba?\(" apps/web/src --include='*.css'` 只剩 `styles/` 下定义行与白名单。

### S3 清除 TSX 硬编码
- `bots/model.ts` 状态色、`toast.tsx` 图标色、通知/确认图标色、在线点等改为 `var(--color-success)` 等。
- `controls.tsx` 描边改用 `currentColor` 或 token。
- 测试：更新受影响的快照/断言（`bots.test.tsx`、`notifications.test.tsx`、`ui.test.tsx`）。

### S4 切换入口
- `AccountMenu` 增加「外观：浅色 / 深色 / 跟随系统」。
- 测试：`auth` 相关测试新增切换后 `document.documentElement.dataset.theme` 变化、刷新后保持。

### S5 桌面端
- `apps/desktop/src` 硬编码色 token 化；设置页加入主题选择。
- Tauri 窗口原生外观（标题栏/红绿灯区域）跟随主题：实现前先查 Tauri v2 官方文档确认窗口主题 API，不凭记忆编码。

### S6 视觉验收
- `UiGallery` 双主题逐一检查组件：按钮、输入、弹窗、下拉、toast、运行卡片、审批/提问卡、代码块、滚动条、选区、焦点环。
- 对比度：正文 ≥ 4.5:1，次要文字 ≥ 3:1（WCAG AA）。
- e2e：`m0-skeleton` 增加一条断言——首次访问为浅色，切到深色刷新后仍为深色。

## 4. 风险

| 风险 | 对策 |
| --- | --- |
| 白色半透明叠加在浅色下消失 | S1 统一用 `--color-bg-hover` 等语义 token，浅色映射为黑色半透明 |
| 代码高亮 / markdown 渲染自带配色 | S2 顺带检查 chat 渲染依赖，必要时按主题切换高亮样式 |
| 深色回归 | 深色 token 原样迁到 `[data-theme="dark"]`，S6 双主题对照截图 |
| 并行分支改同一批 CSS | S2 按文件拆提交，冲突面小 |

## 5. 完成标准
- 新用户首次打开 Web / 桌面端为浅色；三种模式可切换并持久化，无首屏闪烁。
- 全量 `pnpm -r test`、`pnpm typecheck`、`pnpm lint`、`pnpm e2e` 通过。
- 除白名单外无硬编码色值。
