# 预览工作台设计：多标签的网页 / 改动 / 文件预览

> 状态：已定稿（2026-09-28），待按切片开发。界面以 Pane 设计系统为准。

## 1. 现状与问题

| 能力 | 现在 | 问题 |
|---|---|---|
| 网页预览 | `PreviewCard` 点「内嵌预览」在消息卡片里展开一个小 iframe | 宽度受聊天气泡限制，几乎不可用；滚动聊天就丢失位置 |
| 改动 | `DiffWindow` 模态弹窗（1080px） | 遮住聊天，不能边看改动边说话；一次只能看一个 |
| 附件 | `PreviewPanel` 占右侧栏 | 只看附件，不能浏览工作区 |
| 运行过程 / 群信息 | `RunRail`、`useInspector` 占右侧栏 | 与附件预览互斥，后开的挤掉先开的 |
| 工作区文件 | 无，daemon 只有 `files.list`（@ 补全用的模糊搜索） | 看不到 Bot 产出的图片、视频、报告 |

右侧现在是三套互斥机制（`useInspector` / `useRunRail` / `usePreview`），宽度 280px 到窗口的 60%，本质是「窄面板」，不适合承载网页和代码。

## 2. 核心决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | 新增「工作台」列，放在聊天右侧，是**独立于 inspector 的第四列** | 工作台是宽的内容区，inspector 是窄的信息面板，两者职责不同 |
| D2 | 运行过程改为工作台的标签页；只剩群信息仍是 inspector，工作台打开时它**浮在工作台右侧的抽屉**里，不卸载工作台 | 卸载会导致 iframe 重新加载、登录态和滚动位置丢失 |
| D3 | 标签页类型：网页、运行、改动、文件浏览器、单文件；桌面推流（gui）预留 | 覆盖需求，且都是「看 Bot 在做什么、做出了什么」 |
| D4 | 标签页**按群保存**，切群时整组切换；回到该群时恢复（存 localStorage，属于单个浏览者的便利项） | 不同群对应不同仓库和服务，混在一起没有意义 |
| D5 | 同一对象只开一个标签页（按身份键去重），再次打开就是切过去 | 避免重复的 iframe 和请求 |
| D6 | 取消卡片内嵌 iframe，「内嵌预览」改为「在工作台打开」；`DiffWindow` 弹窗由改动标签页取代 | 只保留一套预览体系 |
| D7 | 工作区文件内容不经主站 origin 执行：文本以 JSON 返回、在界面里渲染；媒体走带 `CSP: sandbox` 的只读路由；HTML 走现有预览 origin | 防止 Bot 产出的 HTML/SVG 在主站执行脚本 |

## 3. 布局与空间档位

```
┌──┬──────────┬────────────┬──────────────────────────────────────────┐
│N │ 会话列表  │ 聊天（窄）  │ [● 管理端] [± 改动·CC] [▤ 文件·CC] [+]  ⤢ │
│a │          │            │ ───────────────────────────────────────── │
│v │          │            │ ‹ ↻  /dashboard                   ↗  🔗  │
│  │          │            │ ┌──────────────────────────────────────┐ │
│R │          │            │ │                                      │ │
│a │          │            │ │          iframe / diff / 文件         │ │
│i │          │            │ │                                      │ │
│l │          │ [输入框]    │ └──────────────────────────────────────┘ │
└──┴──────────┴────────────┴──────────────────────────────────────────┘
```

三个档位，在工作台标题栏右侧切换，记住上次的选择：

| 档位 | 会话列表 | 聊天 | 工作台 | 进入方式 |
|---|---|---|---|---|
| 分栏 | 展开 | 窄栏，默认 380px（320–560 可拖） | 其余空间 | 打开改动 / 文件标签页时的默认档位 |
| 专注 | 折叠成图标条（只显示头像和未读） | 窄栏 | 其余空间 | **打开网页标签页时自动进入**；窗口宽度小于 1100px 时也强制进入 |
| 全屏 | 隐藏 | 折叠成 40px 竖条（显示未读数和 @ 我提醒，点击展开为浮层） | 除 NavRail 外全部 | 点 ⤢ 或按快捷键；Esc 退回上一档 |

- 聊天与工作台之间的分隔条可拖动，沿用 `ChatLayout` 现有的 ARIA separator 写法。宽度按档位保存。
- 折叠后的聊天竖条上，有新消息 @ 我时闪一下提示，不自动展开。
- 快捷键（仅在焦点不在 iframe 内时生效）：`⌘\` 切换会话列表，`⌘⇧\` 切换聊天栏，`⌃Tab` / `⌃⇧Tab` 切换标签页，`⌥W` 关闭当前标签页（`⌘W` 会关掉浏览器页签，所以不用）。

**窄屏**：宽度小于 768px 时，工作台是一个全屏页面，顶部返回聊天，一次只显示一个标签页，标签列表收进下拉菜单。

## 4. 标签页体系

### 4.1 模型

```ts
type WorkbenchTab =
  | { kind: 'web'; previewId: string; path: string }
  | { kind: 'run'; runId: string; view: 'process' | 'diff'; file: string | null }
  | { kind: 'diff'; botId: string; scope: DiffScope; file: string | null }
  | { kind: 'files'; botId: string; dir: string; selected: string | null }
  | { kind: 'file'; source: { botId: string; path: string } | { attachmentId: string } }
```

| 类型 | 身份键（去重） | 图标 / 标题 |
|---|---|---|
| web | `web:<previewId>` | desktop + 预览标题，带在线状态点 |
| run | `run:<runId>` | Bot 头像 + 「Bot 名 · 第 N 轮」，运行中显示转圈 |
| diff | `diff:<botId>` | 改动 · Bot 名 |
| files | `files:<botId>` | 文件 · Bot 名 |
| file | `file:<botId>:<path>` 或 `att:<id>` | 文件图标 + 文件名 |

- 状态放在 `app/workbench.ts`（zustand）：`tabs`、`active`、`mode`，按 groupId 分别保存。持久化只存身份和路径，不存内容。
- 最多 12 个标签页，超出时提示关闭。**同时加载的 iframe 最多 4 个**：超出后最久未用的进入「休眠」（卸载 iframe，标签页上显示休眠标记），切回来时重新加载。其他类型的标签页隐藏时保持挂载。
- 标签栏：可横向滚动，右端有「⌄ 全部标签页」列表；拖动排序、中键关闭、右键菜单（关闭其他 / 关闭右侧 / 在新窗口打开）。
- 「+」菜单：列出本群在线的预览（来自 `usePreviews`）；改动…、文件…（二级菜单选 Bot，只列有工作区的 Bot）。

### 4.2 网页标签页

- 顶栏：`↻ 刷新`（通过重新挂载 key 重载）、路径输入框（回车后用新 path 调 `/api/previews/:id/open?path=` 重新进入）、`↗ 新窗口打开`、`🔗 公开链接…`（有管理权限时显示）、在线状态。
- iframe 是跨源的，拿不到内部的前进后退和当前 URL，所以地址栏只表示「进入路径」，不和页面内跳转同步。这一点要在界面上标清楚，不做假的前进后退。
- 预览离线或已关闭时，内容区显示空状态（「服务已停止 · 等待 Bot 重新发布」），恢复在线后自动重载。
- 视口尺寸切换：自适应 / 1440 / 1024 / 768 / 390（手机），固定尺寸时居中并按比例缩放。这是用户检查响应式时的高频操作。

### 4.3 运行标签页

- 把 `RunRail` 的内容整体移进来，保留「过程 / 改动」两个子视图，`useRunRail.open(runId, view, file)` 改为打开或切到对应的运行标签页。
- 本轮改动在这个标签页的「改动」子视图里看，不再单独生成 diff 标签页。
- 运行中的标签页实时滚动；结束后标签上的转圈变成完成或失败标记。
- 工作台关闭时从聊天里点开运行，会打开工作台（分栏档）并定位到这个标签页。

### 4.4 改动标签页

- 直接复用 `DiffParts`（`DiffScopeBar`、`DiffFileList`、`DiffView`、`DiffLayoutToggle`）和 `useWorkspaceDiff`，本质是把 `DiffBody` 从 Dialog 移进标签页。
- 工作台宽度足够（≥ 900px）时文件列表在左、diff 在右；更窄时文件列表收成顶部下拉。
- 每个文件行增加「在文件浏览器中定位」，跳到该 Bot 的 files 标签页并选中这个文件。

### 4.5 文件浏览器标签页

```
┌ 文件 · CC专家 ─────────────────────────────────────────────┐
│ new-luke-plus-admin / src / assets            🔍  ⟳  ☐ 显示忽略的 │
├──────────────────┬─────────────────────────────────────────┤
│ ▸ public         │                                         │
│ ▾ src            │           查看区（见 4.6）                 │
│   ▾ assets       │                                         │
│     logo.svg  M  │                                         │
│     demo.mp4     │                                         │
│   main.ts     M  │                                         │
└──────────────────┴─────────────────────────────────────────┘
```

- 左侧目录树懒加载（每次列一层）。默认隐藏 `.git` 和被 `.gitignore` 忽略的文件，可切换显示。`M` / `A` / `?` 标记未提交状态（沿用 `files.result` 的 `uncommitted`）。
- 顶部面包屑可以点；搜索复用 `files.list` 的模糊匹配。
- 右侧查看区按类型渲染（4.6），带工具栏：复制路径、下载、「在新标签页打开」（生成一个 file 标签页）、「在聊天中引用」（往输入框插入 `@路径`，与现有 @ 候选的格式一致）。
- 只读，不提供编辑、删除、重命名。改文件是 Bot 的事。

### 4.6 查看区：单文件渲染规则

files 的右半边和 file 标签页共用一个 `FileViewer`，附件的 `PreviewPanel` 也迁到这里。

| 类型 | 判断 | 渲染 | 上限 |
|---|---|---|---|
| 代码 / 文本 | 扩展名，否则嗅探前 8KB 是否为 UTF-8 | 带行号的代码视图（复用 `pv-lines`），语言高亮 | 2MB，超过只提供下载 |
| Markdown | `.md` | 默认渲染后的效果（复用 chat `Markdown`），可切换查看源码 | 2MB |
| 图片 | png/jpg/gif/webp/avif/bmp/ico；svg | `<img>` 加缩放、适应窗口 / 1:1、棋盘格透明背景，复用 `Lightbox` 的交互；svg 只用 `<img>` 显示，不内联 | 50MB |
| 视频 | mp4/webm/mov(h264) | 原生 `<video controls>`，需要支持 Range 拖动进度 | 不设上限（流式） |
| 音频 | mp3/wav/ogg/m4a/flac | 原生 `<audio controls>` 加文件信息 | 不设上限（流式） |
| PDF | `.pdf` | 浏览器内置查看器（`<iframe>` 指向 sandbox 路由） | 100MB |
| HTML | `.html` | 默认显示源码；按钮「作为网页预览」对所在目录调用现有 `preview_static`，然后打开一个 web 标签页 | — |
| 其他二进制 | — | 文件信息加下载 | — |

| 入口 | 现在 | 改为 |

## 6. 后端与协议（新增）

改动和网页都复用现有能力；**只有文件浏览器需要新协议**：

| 消息 / 路由 | 说明 |
|---|---|
| s2d `files.tree` `{requestId, groupId, botId, workspace, path, showIgnored}` → d2s `files.tree.result` `{entries: [{name, dir, size, mtime, uncommitted, ignored}], truncated, error}` | 列一层目录，路径限制在工作区根目录以内（canonicalize 后校验，拒绝符号链接逃逸），每层最多 1000 项 |
| s2d `files.read` `{requestId, …, path, maxBytes}` → d2s `files.read.result` `{text \| null, size, binary, mime, error}` | 文本内容，最多 2MB；二进制只返回元信息 |
| `GET /api/groups/:g/bots/:b/files/tree?path=`、`/files/text?path=` | 群成员可读（与改动的读权限一致） |
| `GET /api/groups/:g/bots/:b/files/raw?path=` | 媒体和 PDF 的原始字节。通过现有**预览隧道**开一条流，访问 daemon 进程内的只读文件服务（与 `static_site.rs` 同一套实现，补上 Range / 206 支持），server 原样转发 Range 请求头和响应 |

- 协议按惯例先改 `packages/protocol`，同时补 fixture 并同步 `crates/gonggong/src/protocol.rs`。
- 隧道的 `TunnelOpen` 需要新增一种目标「工作区文件」，不占用 loopback 端口。**这一点待验证**：需要看 `TunnelOpen` 现有字段能不能加变体，还是要换一种帧。

## 7. 安全

- iframe：网页标签页的 iframe 只加载预览 origin（端口模式或独立域名），与主站不同源。沿用现有 `/__gg/auth` 一次性 code。
- `files/raw` 响应头固定为 `Content-Security-Policy: sandbox`、`X-Content-Type-Options: nosniff`。只有白名单里的 MIME（图片、音视频、pdf）用 `inline`，其余一律 `attachment`。svg 只允许通过 `<img>` 显示。
- 文本内容在前端当作纯文本或 Markdown 渲染，Markdown 渲染沿用聊天现有的消毒规则。
- 权限：群成员可以看群内所有 Bot 的工作区文件，与改动的可见范围一致。强制同步群和分区群的处理相同。

## 9. 不做

- 在工作台里编辑、保存文件或提交 git。
- iframe 内的前进后退、同步地址栏（跨源拿不到）。
- 把工作台拖成独立浏览器窗口（「↗ 新窗口打开」已经够用）。
- 多个群的标签页混在一起。
