# 未读、通知与稍后处理（P0 其余项）开发计划

话题之后的 P0：未读体验、侧栏提醒分级、通知粒度、稍后处理 + 提醒。对标 Slack。

## 现状

- 未读：`group_members.last_read_seq`；进群即把已加载的消息全部标为已读（`useMarkRead`），不看是否滚到；已有「以下为新消息」分隔线；没有跳到首条未读、标为未读、Esc 快捷键、全部未读视图。
- 侧栏：所有未读都显示数字；@我 只在预览前加「[有人@我]」，没有计数。
- 通知：`muted` 只影响客户端徽标颜色，服务端建通知时不看它；普通消息不发通知；没有勿扰；`@所有人` 能在选择器里选，但服务端不识别，谁也不通知。
- 稍后处理：只有群级「标记」（`flagged`），没有消息级。

## 已定决策（姜维川 2026-11-08）

| 问题 | 决定 |
|---|---|
| 侧栏提醒 | 普通未读只加粗；@我 和私信显示数字 |
| 通知三档默认值 | 群默认「仅@」，私信默认「全部」 |
| 本期通知范围 | 修通 @所有人、暂停通知 N 小时、免打扰时段；关键词提醒和用户组不做 |
| 谁能 @所有人 | 仅群主和管理员 |

## 1. 侧栏提醒分级

- 群：有未读时名称加粗，不显示数字；有 @我 时显示 @我 的条数（红色数字）。
- 私信：显示未读条数。
- 通知「关闭」的群：名称置灰、不加粗，@我 数字为灰色。
- 应用栏总数 = 各群 @我 条数 + 各私信未读（「关闭」的不计）。
- 服务端：`GroupDto.mentionCount`（`last_read_seq` 之后提到我或 @所有人 的消息数，上限 99），替代布尔 `mentioned`；实时事件按同样规则累加。

## 2. 未读体验

- **跳到首条未读**：进群时如果未读超过一屏，定位到分隔线而不是底部；顶部浮条「N 条新消息 · 跳到首条」，点开或滚过即消失。
- **按可见标已读**：只标到已滚入视口的最后一条，替代「进群即全部已读」。
- **从这里标为未读**：消息悬停菜单 / 右键。`PUT /api/groups/:id/unread { seq }` 把 `last_read_seq` 设为 `seq - 1`（可回退），已结清的 @ 通知不恢复；之后在本次停留中不自动标已读，离开再进入才恢复。
- **快捷键**：`Esc` 当前群全部已读；`Shift+Esc` 所有群全部已读（`POST /api/groups/read-all`，先弹确认）。只在没有浮层、输入框为空时生效。
- **全部未读** `/unreads`：侧栏入口放在「话题」下方；按群列出未读消息（每群最多 20 条，更多给「去群里看」），每组可「标为已读」，可直接回复。

## 3. 通知三档 + @所有人

- 迁移：`group_members.notify_level text`（`all | mentions | off`），由 `muted` 迁过来（`muted = true` → `off`，否则群 → `mentions`、私信 → `all`），然后删除 `muted`。协议 `muted` 换成 `notifyLevel`。
- 入口：侧栏群菜单和群设置里的「通知」三选一，替代「免打扰」开关。
- **全部**：每条新消息（不含事件、自己的消息、只在话题里的回复；Bot 只在最终回复时）推送和桌面提醒，**不写进通知列表**，只走实时事件和 Web Push。
- **仅@**：现状（@我、@所有人、话题里 @我）。
- **关闭**：不推送、不写通知，包括 @；侧栏 @ 数字照常计数（灰色）。
- **@所有人**：`protocol/mentions.ts` 识别「@所有人」，仅当作者是群主或管理员时写 `meta.mentionsAll = true`；非管理员的选择器里不出现「所有人」，手打也只当普通文字。效果等同 @ 每个成员（作者除外），按各自档位决定是否通知；不触发 Bot。飞书出站映射为 `<at user_id="all">`。

## 4. 勿扰

- 存 `users.notify_prefs jsonb`：`{ pausedUntil?, quietHours?: { start: 'HH:mm', end: 'HH:mm', timezone } }`。
- **暂停通知**：侧栏头像菜单「暂停通知」→ 30 分钟 / 1 小时 / 2 小时 / 到明天 9 点 / 自定义；暂停中头像带铃铛划线标记，可「恢复通知」。
- **免打扰时段**：设置 › 通知，每天固定时段，可跨零点。
- 生效：勿扰期间通知照常写进列表、侧栏照常计数，只是不推送（Web Push、飞书通知、桌面提醒都不发）。判断集中在 `notifications/suppress.ts`。

## 5. 稍后处理 + 提醒

- 表 `saved_messages`：`user_id, message_id, group_id, remind_at, reminded_at, done_at, created_at`，主键 `(user_id, message_id)`；索引 `(remind_at) where done_at is null and reminded_at is null`。
- 消息悬停菜单「稍后处理」（书签图标），子菜单设提醒：20 分钟 / 1 小时 / 3 小时 / 明天 9 点 / 下周一 9 点 / 自定义 / 不提醒。已收藏的消息右上角显示书签标记。
- 侧栏「稍后处理」入口（在「全部未读」下方）：有到期提醒时显示数字，否则不显示。
- 页面 `/later`：「进行中 / 已完成」两栏；每条显示所在群、消息摘要、提醒时间；可完成、改提醒、移除、跳到原消息（话题消息打开话题）。
- 提醒：服务端每 30 秒扫一次到期项，`notify(type 'reminder')`（加入推送类型），点开直达消息；受勿扰约束（照常写通知，不推送）。
- 群级「标记」保留不变。

## 数据（一次迁移）

`group_members.notify_level`（删 `muted`）、`users.notify_prefs`、`saved_messages`。

## 分步与验收

每步 TDD：服务端集成测试 → web 组件测试，最后 e2e。

1. **侧栏分级**：`mentionCount`、加粗 / 数字规则、应用栏总数。
2. **未读体验**：跳到首条未读、按可见标已读、标为未读、Esc / Shift+Esc、全部未读页。
   - 测试：标为未读后 `last_read_seq` 回退且本次停留不被自动推进；read-all 只动自己的成员行。
3. **通知三档 + @所有人**：迁移、设置入口、「全部」推送、「关闭」静默、@所有人 权限与计数、飞书映射。
   - 测试：非管理员的 @所有人 不生效；「关闭」的成员收不到 @ 通知但 `mentionCount` 增加；「全部」不写通知行。
4. **勿扰**：暂停、免打扰时段（含跨零点、时区）、推送抑制。
5. **稍后处理**：表、接口、菜单、侧栏入口、页面、到期提醒。
6. **e2e**：管理员 @所有人 → B 侧栏出现 @ 数字 → B 把消息设「稍后处理 · 20 分钟」→ 时钟到期收到提醒 → 在 `/later` 完成。

涉及数据库迁移，推送前需确认。
