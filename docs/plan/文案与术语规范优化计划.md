# 文案与术语规范优化计划

范围：面向终端用户的软件内文案与工程规范（`apps/web`、`apps/desktop`、`apps/server`、`packages/protocol`、`crates/gonggong`、`crates/gg-cast`），以及写作/翻译基线文档（`website/WRITING.md`、`website/TRANSLATING.md`）。  
**暂不处理（延后单列）**：官网 `website/` 帮助文档长文案改写、`README.md` / `README.en.md` 营销结构精修。

## 1. 既定原则（2026-11-17 讨论确定）

| # | 项 | 结论 |
| --- | --- | --- |
| D1 | 核心载体词 | 一切以普通用户为准，全端用户可见界面统一用 **「电脑」**（英文 `computer`），取代「机器」「设备（指硬件时）」「本机执行端」。仅在协议字段、CLI 内部命令/环境变量（如 `machineId`、`Docker` 容器示例）或明确面向运维的底层参数中保留技术命名。 |
| D2 | 整体文风 | **简洁平实，像靠谱同事说话，尽量白话。** 清除源码/状态机/免责腔（「按非主动中断处理」「尽力而非保证」「指数退避」「未获准运行」「已作废」等）以及开发黑话（`daemon`、`gg-cast`、`LiveKit`、`ACP`、`reflog`、`frontmatter`、MCP 工具名、原始枚举值）。 |
| D3 | 报错与引导 | 每条报错说清「发生了什么 + 下一步怎么处理」，删掉「保存失败」「二进制文件」等无上下文名词报错与裸枚举调试输出（`{:?}`）。 |
| D4 | CLI 语言策略 | `gg --help`（`clap` 帮助文本）**不做双语**，保持全英文；修正混入的中文片段与过时描述。运行时通过 `t!()` 输出的终端文案随本计划一并白话化并对齐中英文词典。 |
| D5 | 翻译与协作规范 | 更新 `website/TRANSLATING.md` 与 `website/WRITING.md`：移除过时的「UI 仅中文」「权限档位（只读/工作区写入/完全访问）」描述，对齐「电脑」、`Connect link`、美式英语与实装 UI 标签；英文快速上手对中文接入指令补充英文说明。 |
| D6 | 实施顺序 | 优先修确定性 Bug 与词典冲突 → 统一术语与去黑话白话化 → 统一英文格式与拼写 → CLI `--help` 修正与规范文档同步。官网与 README 长文案留待后续阶段。 |

> 说明：以下两项在本次讨论中未单独展开，计划按当前产品最自然口径给出默认方案，实施前可随时调整：
> 1. **12 个 Bot 性格英文名**：以产品 UI（`apps/web/src/features/bots/en.ts` 的 `Ponder / Ironcode / Hermit / Baby Steps / Whitespace / Nope / Backtrack / Sentinel / Tumbler / Grayscale / Abacus / Retro`）为准。
> 2. **「群 / 私聊」与「频道 / 私信」**：日常群聊与设置统一用「群 / 私聊」（英文 `group` / `direct chat`）；仅公开群广场保留「公开频道」（`public channel`）区分可见性，避免侧栏「私信」与弹窗「私聊」两套叫法。

## 2. 权威术语表（改造后唯一基准）

### 2.1 核心名词与动作

| 中文标准词 | 英文标准词 | 替换掉的旧叫法 / 歧义词 |
| --- | --- | --- |
| 电脑 | computer | 机器（`machine`）、设备（指电脑时）、本机执行端（`runner`） |
| 共工客户端 / 客户端 | Gonggong client / client | `daemon`、`gg-cast`（仅在客户端发布/CLI 安装语境保留二进制文件名） |
| 接入链接 | connect link | `Join link`（`apps/desktop/src/i18n/en.ts`） |
| 接入申请 / 接入码 / 核对码 | connect request / connect code / check code | `hookup request`、`asks to be hooked up`、`接入代码` |
| 电脑离线 | Computer offline | 机器离线、`daemon 离线`、`daemon 已断开` |
| 群 / 公开频道 | group / public channel | 群聊（`WRITING.md` 规定用「群」） |
| 私聊 | direct chat | 私信（侧栏）、`direct message`、`Private chat`、`DM`（统一用 `direct chat`） |
| Bot（首字母大写） | Bot（首字母大写） | `bot`（212 处小写）、机器人（飞书模块除外如特指「飞书机器人」时标明） |
| Agent / Skill | Agent / Skill（首字母大写） | `agent` / `skill` / `AGENT`（如 `AGENT 命令`） |
| Bot 主人 | Bot owner | 归属人、主人（混用时收口为 `Bot 主人` / `Bot owner`） |
| 触发人 | requester | 发起人（仅保留一致场景）、`trigger user`、`initiator`、`who started it` |
| 系统管理员 | system admin | 平台管理员（`teams/routes.ts`） |
| 托管工作区 / 本机目录 | managed workspace / local folder | 托管目录、自带目录、`own directories`、`local directory`（英文统一 `folder` 或 `directory`，建议目录类固定 `folder`、路径报错用 `path`） |
| 审批方式 | Approval | 权限档位（已废弃旧称：只读 / 工作区写入 / 完全访问） |
| 拒绝 | Reject（审批/审核）/ Decline（入群/共享邀请） | `Deny`（混用） |
| 凭据 / 密钥 / 令牌 | credentials / secrets / token | `凭证`（Git/飞书统一「凭据」或明确区分：API/Git「凭据」，系统环境变量「密钥」，登录态「令牌/Token」） |
| 新会话 | new session | 新对话（指代 Agent 上下文重置时统一「新会话」，避免「会话/对话」混用） |
