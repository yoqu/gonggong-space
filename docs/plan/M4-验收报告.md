## M4 E2E 场景（`e2e/m4-interaction.spec.ts`）
1. 附件与引用：在仓库群里带图片 @bot → 消息内显示图片预览 → Claude 读图并完成 → 文件写入 `<工作区>/.gonggong/attachments/<消息ID>/shot-4.png`，`.git/info/exclude` 中包含 `.gonggong/` → 不带 @ 引用 bot 的回复，同一 bot 再次被触发并完成。
2. 提问卡片：agent 调用内置的「向群成员提问」工具 → 卡片进入「等待回答」，显示「向群成员提问 · 1 个问题」 → 触发人选择 Go 并提交 → agent 按回答继续，回复 Go → 卡片显示「已回答」。
3. 打断并追加 + 候选 + 搜索 + 通知：运行中点击「打断并追加」→ 横幅提示「打断并追加到 …」→ 追加消息后仍然只有一张卡片，最终回复为 appended → `@READ` 候选列出工作区文件并标注来源 → `/` 候选列出系统命令和 AGENT 命令 → ⌘K 搜到 appended → 把档位降为 workspace 后触发一次审批，通知中心出现「待审批」。
4. 全局 MCP：管理员添加 stdio MCP（`tools/mcp-echo`），并勾选「强制新会话」→ 真实 Claude 在新会话中调用 echo 工具，回复 `mcp-ok-42`。

## 切片内已验证的边缘场景（摘要）
- 候选：daemon 离线或 2 秒内未回复时，回落到基准分支镜像（标注「main 镜像 · N 分钟前更新」）；镜像 60 秒内最多 fetch 一次，fetch 慢时先返回上次的列表；只在镜像里的文件提示「该文件不在你的工作区，可能需要拉取」；agent 命令与系统命令重名时显示为 `/bot名:命令`；列出未提交文件和文件夹。
- 附件：单个超过 50 MB、每条超过 10 个，前后端都拒绝；非成员、他人或其他群的附件、已绑定的附件均被拒绝；引用人的消息不会触发 bot；daemon 下载附件时校验机器是否有权访问该群；文件名中的路径穿越在服务端和 daemon 两侧都被清理；附件写入后 `git status` 保持干净；修复了「`.gonggong/` 被加入 exclude 后本轮 patch 丢失」。
- 提问：四种题型、推荐项、「其他，我来补充」、回答附件；只有触发人（接力链上为发起人）和 bot 主人能回答，其他人只读；超时后 agent 按推荐项继续并列出假设（真实 Claude 实测等待超过 60 秒，工具调用未失败）；Codex 通过 HTTP MCP 同样可用，70 秒后回答仍被接收；run 结束或被 /stop 时作废卡片；写入审计和通知。
- 打断并追加：/stop 优先于追加；**集成期修复**：追加消息晚于 agent 收尾到达时原先会被静默丢弃，现在 daemon 在 `run.done.appendsApplied` 中上报实际应用了几条，服务端把没应用上的追加消息退化为同一 bot 排队的新一轮（spec §8.9）；被 /stop 的运行不会重新排队。
- 通知、搜索、MCP：只推送五类需要操作的事件，群级事件不推送；搜索只覆盖本人所在的群，运行过程已过期的只按卡片摘要匹配；MCP 名称唯一，`gonggong` 为内置保留名；勾选「强制新会话」后卡片提示「本轮因配置变更开启新会话」。
- 集成期统一文案：原型写「Codex 仅落盘」，现按 spec 改为按 agent 声明的能力发送 ACP 图片（两个适配器都声明支持图片）。
