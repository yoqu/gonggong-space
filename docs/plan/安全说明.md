# 安全说明（M5 · 需求 §13、D18、风险 6）

## 传输
- 配置 `AIWS_TLS_CERT` + `AIWS_TLS_KEY` 后，服务器只提供 HTTPS/WSS（同一端口不再接受明文）；此时会话 Cookie 自动带 `Secure`。开发用 `scripts/dev-cert.sh` 生成 localhost/127.0.0.1/本机局域网 IP 自签证书（网页开发服务器读取同一对环境变量，以 HTTPS 对外并转发到服务器，局域网 daemon 固定的就是这张证书），并打印 SHA-256 指纹供管理员公布。
- daemon 用长期 token 认证自己，并**固定服务器叶子证书的 SHA-256**（不依赖 CA 链，自签证书同样安全）：
  - `aiws login --server https://… --code X --fingerprint sha256:AB:…`：只接受该指纹。
  - 不带 `--fingerprint`：首次信任（TOFU），把指纹写入 `~/.aiws/config.json` 的 `certSha256` 并打印，请与管理员公布的值核对。
  - 之后所有 HTTP（reqwest）与 WebSocket（tokio-tungstenite）连接都校验指纹，不一致即拒绝连接并报错。
  - `AIWS_INSECURE_DEV=1` 关闭固定（会醒目警告），仅限本地开发。
  - `http://` 只允许连本机回环地址（localhost / 127.0.0.0/8 / ::1），其余一律要求 https。
- 服务器换证书 = 指纹变化：公布新指纹，各成员执行 `aiws login` 重新绑定。

## 静态加密
| 数据 | 方式 |
| --- | --- |
| 附件文件（`$AIWS_DATA_DIR/attachments/`） | AES-256-GCM 流式加密；文件格式 `AIWSv1\n` + IV + 密文 + Tag；Web 与 daemon 下载时解密，篡改会使下载中断 |
| `runs.patch`（本轮 diff） | 字符串信封 `v1:<iv>:<tag>:<密文>`（各段 base64） |
| `run_events.payload` 的自由文本（流式输出/思考 `delta`、工具 `detail`） | 同上；`kind`、状态、工具标题、步骤保持明文，供 ⌘K 搜索运行过程 |
| 基准分支镜像（`$AIWS_DATA_DIR/mirrors/`，git 仓库） | 不做逐文件加密，依赖服务器磁盘加密（FileVault / LUKS），部署时必须开启 |
| 权威副本 | 二期（P2）功能，届时同样依赖磁盘加密或同一密钥 |

不加密：消息正文、运行卡片（步骤/摘要）、审批与提问记录——它们需要全文搜索，且只含脱敏后的内容。

## 密钥
- `AIWS_DATA_KEY`：32 字节随机数的 base64（`openssl rand -base64 32`），只放在服务器环境变量/密钥管理中，**不要**与数据库、数据目录放在一起备份。
- 未设置时（开发）自动生成到 `apps/server/.aiws-dev/data.key` 并警告；生产环境必须显式设置。
- 密钥丢失 = 附件、diff 和运行过程无法解密（消息与卡片不受影响）。
- 轮换：信封带版本号 `v1`，当前没有自动重加密脚本；轮换需停机，用旧密钥解密、新密钥重加密（运行过程本身按保留期清理，等保留期过后再换钥可只处理附件）。
- 加密上线前写入的明文行/文件照常读取（不带信封即视为旧数据）。

## 脱敏
入库前统一脱敏（`modules/runs/redact.ts`）：已知密钥值（`AIWS_REDACT_VALUES`）+ 常见格式（私钥块、GitHub/GitLab/npm/OpenAI/Anthropic/AWS/Slack/Google/Stripe token、JWT、`Authorization`/`Bearer`/`X-Api-Key` 头、`password=`/JSON 密钥字段、关键字附近的 40+ 位十六进制）。覆盖：运行事件、diff、最终回复、失败信息、审批请求的标题与命令、附件文件名（不含内容）。

## 审计
管理员操作都写 `audit_logs`（category `admin`）：账号新建/修改、为他人建/改/删 bot、机器吊销、MCP 增删改、群管理（加/移成员、加/移 bot、换仓库）；审批、提问、/stop、/cd 等按各自类别记录。

## 残余风险
- 服务器进程内存与数据库连接内可见明文；拿到 `AIWS_DATA_KEY` + 数据库的人可解密全部。
- 消息、卡片、审批命令虽已脱敏但为明文存储；脱敏基于规则，非常规格式的密钥可能漏过。
- TOFU 首次绑定若恰遇中间人会固定错误证书——请务必核对指纹，或用 `--fingerprint` 绑定。
- 镜像目录依赖磁盘加密；未开启磁盘加密的部署中基准分支代码以明文落盘。
- 附件流式解密在读到末尾才校验完整性，篡改表现为下载中断而不是事先拒绝。
