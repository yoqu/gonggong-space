# Git 管理对标 IntelliJ IDEA — 五轮迭代

姜维川 2026-10-24 提出：持续迭代所有 Git 操作的界面、交互与细节，对齐 IDEA 的 Git 操作逻辑，至少五轮，用子 Agent 开发。第一期见 `Git管理-IDEA对标-开发计划.md`（v0.4.0 已上线）。

## 约定（姜维川 2026-10-24 拍板）

- 每轮 `pnpm check` 全绿 + 截图发群后直接推 `gitlab main` 与 `origin main`。
- daemon 新能力统一挂在 `gitOps4` 下，攒到最后发版，发版前再确认；旧客户端用到新能力时 409「版本过旧」。
- 第一期的决策（危险操作二次确认、非主人申请审批、群通告）不变。

## 审计要点（四路子 Agent 对照 IDEA，2026-10-24）

- **安全**：推送的 branch/remote 不校验，`+feat:main`、`HEAD`、`:main` 能绕过基准分支保护或删远程分支（已验证）。协议改为严格的分支/标签名与远程名，daemon 一律推显式 refs。
- **审批时状态漂移**：贮藏按序号、撤销提交按 `HEAD~1`、改说明按当前 HEAD，审批前状态变了会作用到别的对象。请求带 `expect`/`expectHead`。
- **缺陷**：提交说明草稿会丢；进行中合并时提交框必失败；多选还原顺序反了；子仓库独立差异找不到文件；重命名差异整片新增；检出远程分支时本地已有同名分支会停在旧提交；智能检出恢复冲突被记为失败；CRLF 冲突解析失败。
- **差距**：回滚对话框、多选与快捷键、逐块回滚、折叠未改动片段、分支弹窗键盘、Checkout Problem 对话框、推送对话框（目标分支、文件、被拒后更新）、交互式变基与改写历史、三栏合并工具、Git 控制台、注解着色等。

## 轮次

| 轮 | 内容 |
|---|---|
| R1 | 安全修复（名称校验、显式 refs、推送目标 `target` 与按目标判断基准分支、贮藏 `expect`）；提交窗口（草稿持久化、未跟踪默认不勾、合并中提交=完成合并、选中与打开分离、多选与快捷键、右键补齐：加入 VCS / .gitignore / 删除 / 复制为补丁 / 注解、回滚对话框、说明检查、提交后通知）；差异标签页工具条、F7 / 上下文件 / F4、折叠未改动片段；多选还原顺序 |
| R2 | 逐块回滚、重命名差异、空白与高亮模式、文件查看器行变更标记；分支弹窗键盘与飞出子菜单、动作补齐、Checkout Problem 对话框、更新默认合并 + 自动贮藏 + 结果通知、获取覆盖子仓库、新建/删除分支细节 |
| R3 | 推送对话框（提交与文件、目标可编辑、标签、强推下拉、被拒后更新再推）、推送到某提交为止、Pull 对话框；审批按 `expectHead` 校验；提交历史（双击筛选、可多开、多选与比较版本、详情文件右键、⌘F 转到、刷新保留选中、默认全部分支、比较页右键与详情） |
| R4 | 交互式变基与改写历史（改说明 / Fixup / Squash / Drop）、还原 / 优选所选文件、从修订获取；三栏合并工具（结果可编辑、逐处接受、非冲突改动、魔法解决、未解决提示、进度持久化）、冲突列表批量、变基两侧标注、zdiff3 / AA / CRLF |
| R5 | Git 控制台（命令与输出，`git_operations.log`）；注解着色、悬浮全文、注解上一修订；贮藏快捷恢复；视图选项与筛选补齐；e2e、规格同步；daemon 发版 |

每轮：先由共字君提交协议（C0），再按 daemon+服务端 / web 各区域派子 Agent 在独立 worktree 并行施工（TDD），合并后共字君跑 `pnpm check`、审 diff、截图、推送。
