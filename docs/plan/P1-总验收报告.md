## 已知限制（如实列出）
1. **Windows**：daemon 可以交叉编译，但没有在 Windows 上运行过（本机没有 Windows，容器里装 Wine 也失败了）。桌面端只打包了 macOS（.dmg），Linux / Windows 桌面包不在 P1 范围。
2. **Linux**：容器里用 mock ACP agent 跑通了全链路，没有在 Linux 上跑真实的 Claude Code / Codex（容器里没有登录账号）。
3. **消息可靠性**：协议没有应用层确认。daemon 断线期间产生的消息会缓存，重连后补发，`run.done` 不会丢；但 TCP 恰好在写出那一瞬间断开时，单条消息仍可能丢失。
4. **搜索**：运行过程加密存储后，⌘K 不再搜索 agent 的流式输出和思考内容（最终回复和工具步骤仍可搜）。
5. **加密**：基准分支镜像不逐文件加密，依赖服务器的磁盘加密。
6. **只存储、不生效的参数**：提问卡片题数上限在 daemon 里固定为 4；备份保留天数、归档保留天数、写锁释放时长、强制同步网络阈值只存储不生效（多数属于 P2）。
7. **账号停用**：会删除该成员的 bot。重新启用后，需要重新绑定机器、重新建 bot。
8. **daemon 升级发布**只有管理员接口，没有界面；协议被拒时立即升级（`apply_now`）没有做端到端验证。
9. **本机 Docker Desktop** 的 API 代理启动容器时会卡住，需要用 `DOCKER_HOST=unix://…/docker.raw.sock`（见发布说明）。
10. **你本机的 Codex 配置**：`~/.codex/config.toml` 里的 `model = "custom/gpt-6"` 在 ChatGPT 账号下不可用。测试时换了一个临时 `CODEX_HOME`，没有改你的配置。要让 Codex bot 真正干活，需要你自己改这个配置。

## 过程中发现并修复的主要集成问题（节选）
- agent 的结构化错误原先显示为「已完成」→ 改为「已中断」并附上原因（M1）
- 同一群内同一 bot 并发两轮；/new 之后仍复用进程里的旧会话（M2）
- 审批作废原因靠前端推断；离线倒计时写死 30 分钟（M3）
- 追加消息晚于 agent 收尾到达时被静默丢弃 → 改为退化成排队（M4）
- 系统默认参数没有接到运行模块；daemon 准备阶段重连时，本轮被误判为已丢失（M5）
- agent 检测结果变化后要等重连才上报；多个会话并发写模型目录时出现竞态（M6）
