# 工作区绑定开发计划

目标：bot 不再只能用托管克隆，可以直接使用主人机器上已有的目录，git 仓库自动识别；bot 有默认工作区；群内按 bot 分别绑定，分区模式下允许一个群涉及多个仓库。

## 1. 现状

| 项 | 现状 |
| --- | --- |
| 群 ↔ 仓库 | `group_repos` 一群一仓库；绑了仓库的群，bot 进群后自动托管克隆 |
| 无仓库群 | bot 自动得到托管空目录 `_empty` |
| /cd | 仅限分区群、仅限绑了仓库的群；目录必须是 git 仓库，且 remote 与群仓库一致（`workspace.rs::check_cd`） |
| bot 默认目录 | 无 |
| 每轮前 git | `git.rs::pre_turn`：先 fetch，工作树干净且能快进时自动快进，托管目录和 /cd 目录一视同仁 |
| 选目录 | 只能手动输入 `/cd @bot <绝对路径>`，没有目录浏览 |

## 2. 决策

| # | 项 | 结论 |
| --- | --- | --- |
| W1 | bot 默认工作区 | `bots.default_workspace`（本机绝对路径，可为空）。建 bot 时只有「创建者就是主人且机器在线」才可设置；其余情况由主人在 bot 设置里补 |
| W2 | 生效顺序 | 群内绑定 > 群仓库（见 W3）> bot 默认工作区 > 未绑定 |
| W3 | 群有仓库 | bot 默认工作区的 remote 与群仓库一致 → 自动绑定并在群里提示（可改绑）；不一致或没有默认 → 未绑定，由主人在聊天区横幅里选本机目录（remote 必须一致）或托管克隆。进群不再自动克隆 |
| W4 | 群无仓库 | 有默认工作区直接使用并提示可改绑；否则进入「未绑定」状态，聊天区出现绑定横幅。目录可以是任意仓库或普通目录，所以一个群可涉及多个仓库 |
| W5 | 未绑定 | @ 了也不执行，群里提醒主人去绑定；绑定后不补跑之前的消息。主人发起绑定后，daemon 回应前仍算未绑定。不再自动创建托管空目录，已有的空目录绑定保持不变 |
| W6 | 绑定快照 | 使用默认工作区时，把路径写入该群的绑定（`workspace_kind='cd'`）。之后改默认工作区只影响新加入的群，不牵连已有会话 |
| W7 | 权限 | 只做服务端主人校验：列目录、设默认工作区、群内绑定都只允许 bot 主人操作。daemon 不加本地白名单 |
| W8 | 路径合法性 | daemon 校验：绝对路径、存在、是目录，并且不是 `/`、主目录本身或系统目录。子目录按 `git rev-parse --show-toplevel` 识别仓库，工作目录仍用用户所选路径 |
| W9 | 每轮前 git | 本机目录只 fetch 不快进，只报告落后/领先和是否有未提交改动；托管目录保持现状 |
| W10 | 同一目录并发 | daemon 按规范化后的真实路径排队，同一目录同一时刻只跑一轮；排队中的运行显示「等待工作区空闲」 |
| W11 | 换目录 | 群内改绑即开新会话，并在群里说明原因 |
| W12 | 目录失效 | 下一轮报「失败：/cd 目录不存在」，不会偷偷退回托管目录；主人用 /cd 或横幅重新绑定（失效后自动回到「未绑定」留待后续） |
| W13 | 强制同步 | 仍要求群仓库 + 托管工作区；本机目录的 bot 为「不参与」（需求 4.3）。切换前列出受影响的 bot，由管理员确认 |
| W14 | 清理 | 移出群、吊销 token 时只删托管目录，永不删除本机目录 |
| W15 | 更换群仓库 | 所有 bot 重新走 W2：默认工作区与新仓库一致则自动绑定，否则回到未绑定 |

## 3. 切片（TDD，每片测试全绿 + typecheck + lint）

### S1 协议
- 新增 `s2d dir.list { requestId, path | null }` → `d2s dir.result { requestId, path, entries: {name, git}[], git: {root, remotes, branch} | null, unusable, error }`，供目录浏览和默认工作区校验共用。
- `WorkspaceCd.repo` 改为可空：为空时不做 remote 校验（群无仓库）。
- `workspace_state` 增加 `unbound`。
- 新增 fixture，同步修改 `crates/gonggong/src/protocol.rs`，TS 与 Rust 都要能往返。

### S2 daemon
- 处理 `dir.list`：只列子目录，跳过隐藏目录，最多返回 500 项；附带目标路径的 git 识别结果。
- `check_cd`：repo 为空时只做 W8 校验；repo 不为空时保留 remote 一致校验。
- `pre_turn` 增加参数，/cd 目录跳过快进（W9）。
- 按真实路径的运行锁（W10）。
- 测试：路径校验表驱动测试、子目录识别仓库、/cd 目录不快进、同路径两轮串行执行。

### S3 服务端
- `schema.ts` 增加 `bots.default_workspace`，执行 `db:generate`。
- `PUT /api/bots/:id/default-workspace { path | null }`：仅主人可调；daemon 校验通过后才写入。
- `GET /api/machines/:id/dirs?path=`：仅机器主人可调，转发 `dir.list`；daemon 离线直接报错。按机器而非 bot，新建 bot 时也能浏览。
- `PUT /api/groups/:id/bots/:botId/workspace { path | null }`：仅 bot 主人；null = 托管工作区（群有仓库时克隆）。
- `joinWorkspace` 按 W2–W5 决定工作区并发出对应事件；`ensureWorkspace` 只在机器重连时补做主人已选的托管工作区。
- 分派运行时，`unbound` 不下发，只发提醒事件（W5）。
- `/cd` 放开「无仓库群」限制，同时保留仅限分区模式。
- 测试：生效顺序四种情况、默认工作区 remote 匹配时自动绑定、非主人被拒、`unbound` 不分派、改默认工作区不影响已有绑定。

### S4 Web
- `DirPicker` 组件：按层级浏览 bot 机器上的目录，支持粘贴路径，标出 git 仓库。
- `NewBotDialog`：满足 W1 条件时显示「默认工作区」；bot 设置页可修改。
- 聊天区绑定横幅（跟随实时状态，不是时间线消息，避免过期）：主人看到「绑定工作区」，打开目录选择器，附带「使用默认工作区 / 托管克隆群仓库」；其他人只看到等待文案。
- `GitBar` 工作区类型显示「托管 / 本机目录」，本机目录不显示「已快进」。
- 私聊创建后横幅立即出现，直接选目录。
- 测试：横幅按角色显示、目录浏览与选择后发出请求、默认工作区设置与清除。

### S5 e2e
- `m1-walking-skeleton`：建私聊 → 横幅 → 目录选择器选临时目录 → @ bot，文件落在该目录。
- `m1-edges`：默认工作区在机器离线时进群，上线后自动绑定并执行排队消息。
- 其余用例建群后用 `bindManaged` 选托管工作区。
