# 飞书易用性开发计划（一、二期）

范围（姜维川 2026-11-14 定）：只做界面、文案和状态总览，**不改应用模型**（每个 Bot 一个飞书应用保持不变），不加数据库迁移。背景见《飞书联动-开发计划》。

目标：从零到「飞书群里 @Bot 有回复」，由 13 步降到 9 步左右；每一步界面都告诉用户下一步是什么、卡在哪。

## 2. 用词（Q8）

| 对象 | 统一用词 | 替换掉 |
| --- | --- | --- |
| 应用 ↔ 共工 | **接入**飞书应用 / 移除 | 绑定应用、解除飞书应用 |
| 共工群 ↔ 飞书群 | **关联**飞书群 / 取消关联 | 绑定飞书群、解绑 |
| 共工账号 ↔ 飞书账号 | **绑定**飞书账号 / 解绑 | 认证共工账号 |
| 主应用在飞书里的机器人 | 有显示名时用「{name}」机器人，没有时用「共工机器人」 | 主应用机器人、共工主应用 |

「主应用」「Bot 应用」只在管理后台和文档里出现，成员看到的文案不出现。中文改了 key，英文词典、`website/` 中英文档、飞书卡片文案、`feishu-errors.ts` 的提示一起改。

## 3. 一期（界面与文案，不动协议以外的结构）

### S1 接入后的「还差几步」清单（Q1）

`FeishuAppForm` 在应用状态行下方常驻一个清单，`FeishuScanDialog` 成功后不再自动关窗，显示同一个清单：

| 项 | 判定 | 未完成时显示 |
| --- | --- | --- |
| 凭证已保存、长连接已连上 | `status === 'connected'` | 现有错误 |
| 飞书管理员已审核通过 | `configError === null`（审核前配置接口报 99991672，通过后成功，见联动计划 §5.3）；`not_modifiable` 的应用判定不了，显示「请在飞书开发者后台确认已发布」 | 「等待企业飞书管理员审核，通过后自动完成，无需回来操作」+「重试」 |
| 成员可以使用 | 判定不了，显示为提醒而非勾选项 | 「新应用默认只有创建者可用。请在飞书管理后台把可用范围改为需要的成员」+ 打开飞书管理后台的链接 |

全部完成后清单收成一行「已接通」。现有 `configError` 黄条并入清单，不再单独显示。

### S2 对外地址前置（Q2）

- 管理后台飞书页顺序改为：对外地址 → 主应用 → 账号。
- 对外地址为空时，输入框用 `window.location.origin` 预填，「保存」可点；未保存前「扫码创建或接入」禁用，旁注「先保存对外地址」。
- `invite.ts`：对外地址为空时也发卡片，不带按钮，文字改为「请在共工的群设置 › 飞书里关联本群」。

### S3 群设置飞书页重排（Q3、Q5、Q6）

未关联时，从上到下：

1. **前置检查**两行，各带状态：
   - 「你已绑定飞书账号」：取 `members` 里本人的 `linked`；未绑定给「绑定飞书账号」按钮（`feishuStartUrl(当前页, 'link')`）。
   - 「{name}」机器人已在飞书群：给不了状态，显示操作说明「在飞书群设置 › 群机器人里添加」+ 复制机器人名。
2. **选择飞书群**下拉 +「刷新」+「关联」（现有逻辑）。下拉为空时的占位改为「没有可关联的飞书群，先把机器人拉进群」。
3. **没有现成的飞书群**：「创建飞书群」（现有逻辑）。

4 段 `gs-note` 删除，内容并入各行描述；成员自动同步的说明移到已关联态的「群成员」行。

已关联时，同步设置按方向分组，仍是原来两个字段，不合并（四种组合都有人在用，合并会丢状态）：

- **共工 → 飞书**：开关「网页消息发到飞书群」（`syncOutbound`）。
- **飞书 → 共工**：二选一「只同步 @Bot 的消息 / 同步全部消息」（`syncAll`）。

Bot 行的「未接入飞书」：Bot 主人或系统管理员看到「去接入」（打开该 Bot 设置的飞书页），其他人看到「请 Bot 主人接入」。

### S4 建群卡片支持关联已有群（Q4）

- `FeishuGroupDialog` 顶部加二选一：「新建共工群」（现有）/「关联到已有群」。后者列出本人是管理员、还没关联飞书群的群，提交走现有 `PUT /api/groups/:id/feishu`。
- 卡片文字改为两句：这个飞书群还没接入共工；点按钮新建或关联已有的共工群。按钮文案「接入共工」。
- 群设置飞书页 S3 第 1 步的说明里写明：把机器人拉进群后，群里会出现接入卡片，也可以直接点卡片完成。

### S5 非成员可申请加入（Q7）

`groupTarget` 里「已绑定账号但不是群成员」的提醒卡片：对外地址已设置、且该群按现有入群申请规则对此人可申请时，加按钮「申请加入」，链接到共工里该群的申请入口；否则保持原文案。申请入口的路由由实施时按《团队分区与入群申请》现有实现确定，不新增接口。

### S6 Bot 的飞书入口上提（Q6）

- `BotSettings` 新增独立页「飞书」（`BotTab` 加 `'feishu'`），把「飞书应用」从「高级」移过去，只有可编辑者可见。
- `BotPage` 的「飞书应用」行显示状态标签（未接入 / 已接通 / 等待审核 / 连接失败），不再显示 App ID。

### S7 用词与文档

按 §2 全量替换，更新 `website/admin/feishu.md`、`website/user/groups.md`、`website/user/bot-settings.md` 及英文版。

## 4. 二期（管理后台飞书页：向导 + 总览）（Q9）

### 页面结构

1. **接入进度**（四步，横向）：对外地址 → 接入主应用 → 审核通过 → 成员可用。每步是 S1/S2 的同一判定；「成员可用」的判定为：除接入人外，至少还有 1 个账号绑定了飞书。未达成时给「复制登录地址，发给同事验证」。四步都完成后收成一行「飞书已接通 · {n} 人已绑定飞书账号」。
2. **Bot**（表）：Bot、团队、主人、飞书状态（未接入 / 已接通 / 等待审核 / 连接失败 + 原因）。行操作：接入、更新权限、重试，直接在本页弹扫码窗（系统管理员已有权限，见 `routes.ts` `manageableBot`）。默认只列已接入和出错的，「显示全部」展开未接入的。
3. **飞书群**（表）：共工群、团队、飞书群名、关联时间、Bot 入群情况（如 2/3）、最近一次失败原因。行操作：打开群设置飞书页（本人是群成员时）。
4. **账号**：飞书自动开户开关（现有）。

### 接口

新增 `GET /api/admin/feishu/overview`（系统管理员），协议先加在 `packages/protocol/src/feishu.ts`：

```
FeishuOverviewDto {
  publicUrl: string
  main: FeishuAppDto | null
  linkedUsers: number            // feishu_identities 行数
  bots: { botId, name, teamName, ownerName, app: FeishuAppDto | null }[]
  chats: { groupId, groupName, teamName, chatName, boundAt,
           botsInChat: number | null, botsTotal: number, issue: FeishuIssue | null }[]
}
```

- `botsInChat` 逐群要实时调飞书，总览不查：返回 `null`，前端显示「—」，进群设置页才看实时值。只返回库里和内存里已有的失败原因（`issues.ts` `botIssue`）。
- 不加表、不加列。

### 待核实（实施前先查官方文档，查不到就按上面的代理判定做）

- 应用能否用自己的凭证读到版本审核状态和可用范围（应用信息 / 应用版本列表接口及所需权限）。能读到：S1 清单第 2、3 项和进度第 3、4 步改用真实状态，并把所需权限加进扫码预填。

**结论（2026-11-14 查官方文档）：保持代理判定。**
- 审核状态：「获取应用信息」`GET /open-apis/application/v6/applications/me`（返回 `online_version_id`、`unaudit_version_id`）用 `application:application:self_manage` 即可调用。但新应用的权限要首个版本审核通过才生效，审核前这个接口和自动配置一样调不通，得到的信息与「自动配置是否成功」相同，不值得多申请一个权限。
- 可用范围：「获取应用在企业内的可用范围」`GET /open-apis/application/v2/app/visibility` 需要 `admin:app.info:readonly`，是要企业管理员审批的高级权限，不加进预填。
- 实现：`FeishuAppDto.review`（approved / pending / unknown）由 `config_error` 推出；「成员可用」= 除接入主应用的人外至少 1 个账号绑定了飞书（总览接口 `othersLinked`）。
