# 产品原型提示词 · Stitch 对照三轮（2026-10-31）

同一需求（滴滴打船，小程序，麓客+ 设计系统，乘客端 + 船长端）分别交给 Stitch 和本机 Claude Code（`claude -p`，创作消息与线上一致，Skill 用工作区副本）生成，逐轮改 Skill 再实跑对比。

## 根因

- **没图不是漏了提示词，而是规则禁止**：SKILL.md / GUIDE.md 要求「没有附件就用 `.gg-ph` 占位，不得外链」，示例产物也全是占位。用户实测 6 屏共 24 个占位，而麓客+ 的 DESIGN.md 恰恰要求「让图片和海报做主角」。
- **Stitch 的做法**：每个图片位都由模型写一段摄影式描述（`data-alt="Modern streamlined eco sightseeing electric boat … on a radiant sunny day"`），再生成 AI 图（`lh3.googleusercontent.com/aida-public/…`）。地图也是图片，船长头像也是生成图。
- **缺少「需求扩写」**：Stitch 会先把一句话扩成设计规格，包括每屏的分区、标志性模块和领域细节，比如费用透明、安全提示、调度津贴。我们的 Skill 拿到页面清单就直接开始写。

## 三轮改动与结果

| 轮次 | Skill 改动 | 结果（5 屏） |
|---|---|---|
| 基线 | — | 24 个占位，画面偏线框；用时约 7 分钟 |
| 1 | 新增 `craft/imagery.md`：图片来源按附件 → 生图工具 → Wikimedia/Unsplash 下载到 `assets/` → SVG 插画 → 占位依次选用；新增 Step 0「设计简报」（标志性模块、领域细节、图片位）；硬规则改为「真实图片」 | 占位降为 0，有 3 张实拍船照和 SVG 湖区地图，新增倒计时接单卡和登船码；但地图简陋、图标少、首页没有标签栏。6 分钟，$1.7 |
| 2 | 地图分层画法（岸线、路网、建筑、标注、产品层）；图标用 `<symbol>` 雪碧图，放在小节标题、元信息和状态标签上；顶层屏必须带 DESIGN.md 的标签栏；说明示例里的占位只是为了控制插件体积 | 地图像真实地点，标签栏用了麓客+ 六边形扫码，有日落 Banner 照片；首页下半屏空。9 分钟，$2.2 |
| 3 | 首屏必须填满（375×812 下不能有空带）；页面主数字可用最大字号 ×1.75；地图和照片上的浮层不能遮挡船只、码头图钉或彼此；自检增加设备尺寸截图 | 5 屏首屏都填满，收入、ETA、价格用大号数字；首页加了带照片的船型卡，选码头页加了带照片的选中卡。11 分钟，$2.9 |

另外，服务端 lint 增加了对 `<img>`、`srcset` 和 CSS `url()` 外链图片的检查（规则码 `external-resource`），与「不得外链」一致。

## 仍落后 Stitch 的地方

- **图片**：只能用图库实拍做替身，内容匹配度不如 AI 按描述生成。若要追平，需要平台给 Bot 提供生图工具，Skill 已预留「生图工具优先」。
- **字号**：麓客+ 的字号范围是 9–16px，整体比 Stitch 平淡。这是设计系统本身的风格，换「冰川」「霓虹夜」等预设时差距更小。
- **用时与费用**：比基线多 50%–60%，主要花在搜图和下载核对上。
