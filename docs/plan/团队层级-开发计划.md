# 团队层级开发计划

目标：在「平台 → 群」之间加入「团队」层，以团队为单位隔离成员、群、Bot、仓库与配置，形成 SaaS 式的多团队使用方式。不做商业化（无套餐、配额、支付）。私有部署可在管理后台开启单团队模式，界面与现在一致。

## 1. 现状

| 项 | 现状 |
| --- | --- |
| 账号 | `users.role` 只有 `sysadmin` / `member`；群管理员按群设置（`group_members.is_admin`） |
| 可见性 | `/api/users` 返回全部启用账号，任何人可私聊、拉任何人的 Bot 进群 |
| 资产归属 | `machines`、`bots` 只有 `owner_id`；`groups` 只有 `created_by` |
| 仓库历史 | `repos.key` 全实例唯一（「Team-wide history」） |
| MCP | 只有全局层 `mcp_servers`（sysadmin 维护），`enabledMcpServers(db)` 在建会话时注入 |
| 参数 | `system_params` 全局 + `groups.params` 群覆盖 |
| 实时 | `Bus` 按用户推送，事件对象是群成员 |
| 后台 | `/admin` 仅 sysadmin：账号、Bot、群、配置（MCP）、参数、发布、机器、用量、预览、审计 |
| 注册 | `registrationOpen` 开启时自助注册，否则 sysadmin 建账号 |

## 2. 决策

| # | 项 | 结论 |
| --- | --- | --- |
| D1 | 账号与团队 | 一个账号可加入多个团队，界面左上角切换 |
| D2 | 团队角色 | 所有者 / 管理员 / 成员；群管理员仍按群设置。一个团队至少一名所有者 |
| D3 | 平台角色 | `sysadmin` 即平台管理员，不自动成为任何团队成员；通过后台治理团队 |
| D4 | 机器 | 归个人，跨团队复用。一台机器可同时为本人在多个团队的 Bot 服务；供应商配置仍只存本地 |
| D5 | Bot | 归团队（`team_id` + `owner_id`）。只能加入本团队的群；私聊只能与本团队成员/Bot |
| D6 | 隔离 | 完全隔离：无跨团队私聊、共享群、跨团队搜索。内置 MCP 的跨群读取限定在本团队 |
| D7 | 团队上下文 | 以资源推导为主：带 `groupId` / `botId` 的接口由资源反查团队并校验成员身份；只有列表与创建类接口读请求头 `X-GG-Team` |
| D8 | MCP 三层 | 平台（sysadmin）→ 团队（团队管理员）→ 群（群管理员），同名时下层覆盖上层；`gonggong` 保留名三层都禁用 |
| D9 | 参数三层 | 平台默认（sysadmin）→ 团队覆盖（团队管理员，仅白名单键）→ 群覆盖（现有 `groups.params`） |
| D10 | 后台可配 | 新增平台参数 `singleTeamMode`（默认 `true`）、`teamCreation`（`all` \| `sysadmin`，默认 `sysadmin`），后台动态修改即时生效 |
| D11 | 单团队模式 | 开启时：隐藏团队切换与建团队入口，新注册账号自动加入默认团队。仅当恰好一个未归档团队时允许开启，该团队即默认团队 |
| D12 | 加入团队 | 邀请链接（可设角色、有效期、次数，可撤销）；或管理员按账号直接添加。持有效邀请链接可注册，不受 `registrationOpen` 限制 |
| D13 | 离开 / 移出 | 等同该团队内的「账号停用」：其在本团队的 Bot 删除并移出群、退出本团队所有群；其他团队不受影响。唯一所有者需先转让 |
| D14 | 账号停用 | 维持平台级停用（sysadmin），作用于全部团队 |
| D15 | 团队归档 | 所有者或 sysadmin 归档；群转只读归档，Bot 停止调度，成员列表中隐藏 |
| D16 | 管理入口 | 遵循「后台只给 sysadmin」：团队管理放聊天侧「团队设置」弹窗；`/admin` 只做平台治理 |
| D17 | 实时 | `Bus` 保持按用户推送；群事件带 `teamId`，客户端对非当前团队只累计未读；新增 `team.*` 事件 |
| D19 | 群管理口径 | 管理群统一由群管理员负责。团队管理员/所有者未进群时只能只读查看该群（信息与消息），不能管理；需要管理时「强制进群并成为群管理员」，写审计并发群事件 |
| D20 | Bot 名称 | 维持全平台唯一；桌面端显示 Bot 所属团队 |
| D18 | 迁移 | 有数据时建「默认团队」，所有启用账号加入，最早的 sysadmin 为所有者（无则最早账号），现有数据全部归入；`singleTeamMode=true`，老部署无感 |

## 3. 数据模型

新表：

| 表 | 字段 |
| --- | --- |
| `teams` | `id`、`name`、`avatar`、`params jsonb`（团队覆盖）、`created_by`、`archived_at`、`created_at` |
| `team_members` | `team_id`、`user_id`、`role`（`owner` \| `admin` \| `member`）、`joined_at`；主键 `(team_id, user_id)` |
| `team_invites` | `id`、`team_id`、`token_hash`、`role`、`max_uses`、`uses`、`expires_at`、`created_by`、`revoked_at`、`created_at` |

加 `team_id`（迁移回填后 `NOT NULL`，除注明外）：

| 表 | 说明 |
| --- | --- |
| `groups` | 群（含私聊）归属 |
| `bots` | Bot 归属 |
| `repos` | 唯一键 `key` → `(team_id, key)` |
| `mcp_servers` | 加 `scope`（`platform` \| `team` \| `group`）、`team_id`、`group_id`（可空）；唯一键改为 `(scope, team_id, group_id, name)` |
| `notifications` | 可空，按团队分组与角标 |
| `audit_logs` | 可空，平台级事件为空 |

不加：`machines`、`git_accounts`、`push_subscriptions`（个人）；`messages`、`runs`、`approvals`、`attachments`、`previews` 等经群推导。

迁移追加为新文件（dev server 会自动应用已有迁移，不重生成），回填写在迁移 SQL 内；`ensureBootstrapAdmin` 在空库首启时同时建默认团队。

## 4. API

团队（成员身份校验 `requireTeam(ctx, req, teamId, minRole)`）：

| 方法 | 路径 | 权限 |
| --- | --- | --- |
| GET | `/api/teams` | 我加入的团队 |
| POST | `/api/teams` | `teamCreation` 允许者 |
| PATCH | `/api/teams/:id` | 管理员（名称、头像、参数覆盖） |
| POST | `/api/teams/:id/archive` | 所有者 |
| GET | `/api/teams/:id/members` | 成员 |
| POST | `/api/teams/:id/members` | 管理员（按账号添加） |
| PATCH | `/api/teams/:id/members/:userId` | 管理员改角色；涉及所有者需所有者 |
| DELETE | `/api/teams/:id/members/:userId` | 管理员移出 / 本人离开 |
| POST | `/api/teams/:id/transfer` | 所有者 |
| GET/POST/DELETE | `/api/teams/:id/invites[/:inviteId]` | 管理员 |
| GET | `/api/invites/:token` | 公开（团队名、邀请人、是否有效） |
| POST | `/api/invites/:token/accept` | 登录用户 |
| GET/PUT/DELETE | `/api/teams/:id/mcp[/:mcpId]` | 管理员 |
| GET/PUT/DELETE | `/api/groups/:id/mcp[/:mcpId]` | 群管理员 |

现有接口改造：`/api/users`、`/api/groups`（列表/创建）、`/api/bots`（列表/创建）、`/api/repos`、`/api/search`、`/api/usage`、`/api/notifications` 读 `X-GG-Team`；其余按资源推导团队。`/api/me` 返回 `teams[]`。

平台后台：`/api/admin/teams`（列表、新建、归档、指定所有者）；账号、群、Bot、用量、审计接口加 `teamId` 筛选；参数接口增加 `singleTeamMode`、`teamCreation`。

## 5. 界面

| 位置 | 内容 |
| --- | --- |
| 聊天侧栏顶部 | 团队切换器（头像 + 名称 + 其他团队未读角标），「新建团队」「加入团队」；单团队模式隐藏 |
| 团队设置弹窗 | 概览、成员（角色、移出、转让）、邀请链接、MCP（团队层）、参数覆盖、群管理、用量、审计；成员只读看概览与成员 |
| 群设置 | 新增「MCP」页签（群层，群管理员可编辑） |
| `/join/:token` | 邀请落地页：未登录先登录/注册，确认后加入并切到该团队 |
| `/welcome` | 无团队时：建团队（若允许）或输入邀请链接 |
| `/admin` | 新增「团队」页；账号页显示所属团队；群/Bot/机器/用量/审计加团队筛选；参数页增加单团队模式与建团队权限；配置页标注为平台层 MCP |
| 桌面端 | Bot 列表显示所属团队 |

前端当前团队存 `localStorage['gg.team']`，`g/:groupId` 打开时以群所属团队为准并同步切换。

## 6. 切片（TDD，每片测试全绿 + 全量不回归 + typecheck + lint）

### T0 数据底座（无可见变化）
- 协议：`TeamRole`、`TeamDto`、`TeamMemberDto`、`TeamInviteDto`；`SystemParams` 增 `singleTeamMode`、`teamCreation`；`TEAM_PARAM_KEYS` 白名单。
- schema + 迁移 + 回填；`createTestDb` 种子助手增 `seedTeam`，现有种子默认挂到一个团队。
- `requireTeam`、`teamOfGroup`、`teamOfBot`；所有列表查询加团队条件；拉 Bot 进群、私聊、内置 MCP 跨群读取加同团队校验。
- 验收：两团队数据互不可见的隔离测试（用户列表、群、Bot、仓库、搜索、内置 MCP 工具）；迁移回填测试。

### T1 团队与成员
- 团队 CRUD、成员、角色、转让、离开/移出（D13）、邀请链接。
- 前端团队切换器、团队设置（成员与邀请）、`/join/:token`、`/welcome`；`team.*` 实时事件与跨团队未读。
- e2e：A 建团队 → 邀请 B → B 加入并在群内 @ 自己的 Bot → A 移出 B，B 的 Bot 离群。

### T2 团队管理下放
- MCP 三层合并注入（`enabledMcpServers(db, groupId)`），团队层与群层编辑界面。
- 参数三层合并（`effectiveParams(groupId)` 替换现有直接读 `sysParams` 的调度相关处）；团队设置参数页。
- 团队设置：群管理、用量、审计（按 `team_id`）。
- 后台：团队页、各页团队筛选、参数页新项、单团队模式开关校验（D11）。

### T3 自助与单团队模式
- 注册后流程：单团队模式自动加入默认团队；否则进 `/welcome`。
- `teamCreation` 生效；邀请链接免 `registrationOpen` 注册。
- 单团队模式切换即时生效的 web 测试。

## 7. 风险

1. 遗漏团队条件导致串数据：T0 以「两团队隔离」测试覆盖每个列表与检索接口，新增接口需同样补测。
2. 一台机器跑多团队 Bot 时，工作区目录可能同名：托管工作区路径已含群 id 与 Bot id，`/cd` 路径由用户自选，需在 Bot 详情标出所属团队避免误操作。
3. 群事件跨团队推送增加客户端负担：仅累计未读，不加载内容。
