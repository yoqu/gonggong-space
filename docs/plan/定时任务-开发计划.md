# 定时任务开发计划

目标：群（含与 Bot 的私聊）可以挂定时任务，到点以任务主人的名义 @ 指定 Bot 执行一段指令。任务可配置多个候选 Bot，到点按擅长度与可用状态只选一个执行。任务既能在界面上建，也能由 Agent 在运行中通过内置 `gonggong` MCP 直接创建、查看、修改、删除；群 / 私聊右侧设置面板可查看管理，后台有全局总览。

## 1. 现状

| 项 | 现状 |
| --- | --- |
| 触发 | 只有人发消息 @Bot（`runs/trigger.ts::triggerRuns`）和接力 `hand_off`（`triggerChain`）两条入口，都汇入 `createRuns` → `schedule` |
| 授权 | `refusal(bot, originUserId)` 按 Bot 的触发范围校验发起人；工作区未绑定 / 仓库不可达时发群事件不建 run |
| 周期任务 | 各引擎用 `setInterval` + `unref` 并在 `app.ts` 的 `onClose` 停止（如 `startRetention`），没有通用调度器，也没有 cron 能力 |
| 内置 MCP | `GONGGONG_TOOLS`（`packages/protocol/src/tools.ts`）生成 `gonggong-tools.json`；daemon 通用转发到 `/api/daemon/runs/:runId/tools/:name`，以进行中的 run 为鉴权锚点；`gonggong` 工具全部免审批 |
| 写类工具先例 | `hand_off` 在 run 上记账、结束后生效；`preview_expose` 直接在群里发卡片 |

## 2. 决策

| # | 项 | 结论 |
| --- | --- | --- |
| T1 | 归属 | 任务属于**群**（私聊即个人任务），指向本群 1 个或多个 Bot（`botIds`）。系统级任务不做：每次运行都需要群上下文 |
| T1a | 智能调度 | 每次触发**只 @ 一个 Bot**，不做多 Bot 同时分发。候选 Bot 按擅长度排序：Agent 创建时读取本群 Bot 的名称、介绍（系统提示词摘要）、agent 类型与模型，按任务内容选出擅长的 Bot 并排好顺序；界面创建时由用户多选并拖动排序。到点按顺序取第一个**可用**的：在线、空闲（无 queued / running）、工作区可用、未被停用。都不可用时本次跳过并发群事件。服务端只做可用性判断，不在触发时调用模型 |
| T2 | 主人 | 每个任务有一个人类主人 `ownerId`，到点以主人身份触发，按 `refusal(bot, ownerId)` 校验。界面创建 = 创建人；Agent 创建 = 该 run 的 `originUserId`（发起这条链的人），并记录 `createdByBotId / createdByRunId` |
| T3 | 计划类型 | `cron`（5 段表达式 + IANA 时区）与 `once`（指定时刻）。时区默认取创建人浏览器时区，Agent 创建时缺省 `Asia/Shanghai`。表达式解析用 `croner`（v10，无依赖，支持时区与 `nextRuns`，实现前按 CLAUDE.md 核对文档） |
| T4 | 触发方式 | 到点由服务端以主人名义发一条 `kind='user'` 消息 `@Bot 指令`，`meta = { mentions: [按 T1a 选出的 botId], scheduleOf: taskId }`，再走 `createRuns`。复用上下文、排队、离线、工作区检查、飞书镜像全部现有逻辑；界面按 `scheduleOf` 显示「⏰ 定时任务·名称」标记，与真人发言区分 |
| T5 | 调度器 | `startScheduleEngine(ctx)`：每 30 秒一跳，`UPDATE … SET next_run_at = <下一次> WHERE enabled AND next_run_at <= now() … FOR UPDATE SKIP LOCKED RETURNING`，先推进再触发，多实例与重启都不重复触发 |
| T6 | 漏触发 | 服务停机期间错过的，恢复后**只补触发一次**，再从当前时间算下一次；`once` 任务错过超过 24 小时则作废并通知主人 |
| T7 | 防堆积 | 上一次触发的 run 还在 queued / running / awaiting_* 时，本次跳过并发群事件「上次尚未结束，本次跳过」 |
| T8 | 自动暂停 | 连续 3 次失败（run 失败 / 被拒 / 工作区不可用）自动停用，记 `pausedReason`，通知主人；`once` 触发后自动停用 |
| T9 | 限额 | 每群最多 20 个任务（含停用，不含已删除）；cron 最小间隔 5 分钟。均为系统参数（`scheduleMaxPerGroup`、`scheduleMinIntervalMin`），走 `SYSTEM_PARAM_VIEW` |
| T10 | 管理权限 | 任务主人与群管理员可改、停、删；其他成员只读。Agent 只能管理**当前群**的任务，且只能改删自己（同一 Bot）创建或目标包含自己的任务。系统管理员在后台可停用 / 删除任意任务 |
| T11 | 即生效 + 通知卡片 | Agent 创建与其他 `gonggong` 工具一致免审批、立即生效。无论界面还是 Agent 创建，群里都发一张**定时任务卡片**（`meta.scheduleCard = taskId`）：名称、候选 Bot（按顺序）、计划描述、下次触发、创建来源；按钮「暂停 / 恢复」「删除」「查看」，按钮仅主人与群管理员可点，其他人只读。卡片随任务状态实时更新（已暂停 / 已删除） |
| T12 | 运行上下文 | 定时触发的 run 在 prompt 里注明「本轮由定时任务「x」(id) 触发」，Agent 可据此在条件满足后自行 `schedule_delete`（如「每 30 分钟查 CI，绿了就删掉自己」） |
| T13 | 审计 | 创建 / 修改 / 删除 / 自动暂停写审计 `category: 'schedule'`，detail 记录 taskId、操作来源（user / runId） |

## 3. 数据

`schedules` 表（`src/db/schema.ts`）：

| 列 | 说明 |
| --- | --- |
| `id`、`groupId`、`ownerId` | 归属 |
| `createdByBotId`、`createdByRunId` | Agent 创建时记录，界面创建为空 |
| `name`、`prompt` | 名称与发给 Bot 的指令 |
| `kind` | `'cron' \| 'once'` |
| `cron`、`timezone`、`runAt` | 计划 |
| `enabled`、`pausedReason` | 状态 |
| `nextRunAt` | 调度游标，索引 `(enabled, next_run_at)` |
| `botIds` | 候选 Bot（uuid[]，按擅长度排序，第一个为首选） |
| `lastFiredAt`、`lastRunId`、`lastPickedBotId`、`failStreak` | 最近一次结果与实际执行的 Bot |
| `createdAt`、`updatedAt`、`deletedAt` | 软删除，历史消息里的 `scheduleOf` 仍可解析名称 |

候选 Bot 移出群或被删除时从 `botIds` 去掉并发群事件，去空后停用；群归档时停用（`pausedReason` 写明原因）。

## 4. MCP 工具

均在 `GONGGONG_TOOLS`，服务端实现于 `agent-tools/service.ts`，daemon 无需改代码（通用转发 + 前缀免审批），只需随新 `gonggong-tools.json` 重新构建。

| 工具 | 入参 | 返回 |
| --- | --- | --- |
| `schedule_create` | `name`、`prompt`、`cron?` / `at?`（ISO，二选一）、`timezone?`、`bots?`（名称数组，按擅长度从高到低，默认只有自己，须为本群 Bot） | 任务 id、人类可读的计划描述、接下来 3 次触发时间 |
| `schedule_list` | `all?`（默认只列本群） | 任务行：id、名称、Bot、计划、启用状态、下次触发、最近结果 |
| `schedule_update` | `id`，以及 `name? / prompt? / cron? / at? / timezone? / bots? / enabled?` | 同 `schedule_create` |
| `schedule_delete` | `id` | 确认文本 |

校验失败（表达式错误、间隔过短、超限、越权）返回 `isError` 文本，便于 Agent 自行纠正。系统提示词加一句：「用户要求定期 / 稍后做某事时，用 gonggong 的 schedule_create 建定时任务，不要自己 sleep 等待。」

## 5. 界面

- **右侧群设置 / 私聊设置面板**（`GroupInfo`）：新增「定时任务」一行（显示「{n} 个」），进入子视图：列表（名称、候选 Bot（按顺序）、计划描述、下次触发、最近结果、启用开关）；新建 / 编辑弹窗：多选候选 Bot 并拖动排序（提示「到点选第一个可用的」）、名称、指令、频率预设（每天 / 每个工作日 / 每周 / 每月 / 仅一次 / 自定义 cron），实时预览接下来 3 次时间。非主人非管理员只读。
- **定时任务卡片**：T11 的卡片组件，按钮调用 REST，状态随实时事件刷新。
- **消息**：`scheduleOf` 消息显示「⏰ 定时任务·名称」标记，点击打开右侧面板对应任务。
- **群事件**：跳过、自动暂停、Bot 移出导致变更的事件。
- **后台 → 定时任务**（仅系统管理员，`features/admin/SchedulesPage.tsx`，挂到 `nav.tsx`）：全局列表，按团队（复用 `TeamFilter`）/ 群 / Bot / 状态 / 来源（界面 / Agent）筛选；列：名称、群、候选 Bot、最近执行的 Bot、计划、主人、下次触发、最近结果、连续失败；操作停用 / 恢复 / 删除。顶部汇总：启用数、24 小时内触发数、失败数、已自动暂停数。
- 文案走 i18n（`features/groups/en.ts`、`features/admin/en.ts`，服务端事件文案加 `en`）。

## 6. 切片（TDD，每片测试全绿 + typecheck + lint）

### S2 服务端：表与 REST
- `schema.ts` 加表并 `db:generate`（新迁移，不重生成旧迁移）。
- `src/modules/schedules/`：`service.ts`（校验、算 `nextRunAt`、限额、权限）与 `routes.ts`：`GET/POST /api/groups/:id/schedules`、`PATCH/DELETE /api/schedules/:id`；创建时发 T11 卡片，变更后更新卡片并推群实时事件。

### S3 服务端：调度引擎
- `engine.ts::startScheduleEngine`，接入 `app.ts` 的 `onClose`；时钟走 `ctx.now()`，测试可注入。
- 智能调度：按 `botIds` 顺序取第一个可用的 Bot（T1a），全部不可用时跳过。
- 触发：T4 发消息 → `createRuns`；T6 补触发；T7 跳过；run 结束时回写 `lastRunId / failStreak`，T8 自动停用并通知；Bot 移出 / 群归档时停用。
- 测试：到点触发一次且只一次（两个引擎并发跳不重复）；只建一个 run；首选不可用（离线 / 忙碌 / 工作区不可用）时顺延到下一个；全部不可用时跳过；停机补一次；`once` 触发后停用、过期作废；上次未结束跳过；连续失败停用；主人无触发权限时建 forbidden 并计失败。

### S4 服务端：MCP 工具
- `get_group_info` 的 Bot 行补充介绍（系统提示词前 200 字）、agent 类型与模型，供 Agent 判断擅长度（T1a）。

- 测试：Agent 创建后主人为 `originUserId`；`bots` 缺省为自己、多个候选按传入顺序保存；越群、改别的 Bot 的任务被拒；`schedule_list` 格式。

## 7. 验收

- 界面和 Agent 都能建任务且立即生效，群里出现定时任务卡片，主人 / 群管理员可在卡片上暂停、恢复、删除。
- 右侧群设置与私聊设置面板能查看和管理本群全部任务。
- 多候选 Bot 任务：到点只有一个 Bot 执行，首选不可用时自动顺延到下一个可用的；Agent 创建时能按任务内容选出擅长的 Bot。
- 对 Bot 说「每个工作日早上 9 点汇总昨天的 PR」，Agent 自行建出正确的 cron 任务并回报下次时间。
- 重启服务不重复、不漏（补一次）；连续失败自动停用并通知主人；Bot 移出群后任务随之调整。
- 每群超过 20 个任务被拒；越权操作被拒并有审计。
- 后台总览可跨团队查看、筛选、停用、删除任意任务。
- `pnpm -r test`、`cargo test --workspace`、`pnpm typecheck`、`pnpm lint` 通过，`pnpm e2e` 不回归。

## 9. 实现说明（2026-10-03）

- 限额与最小间隔用常量 `SCHEDULE_MAX_PER_GROUP = 20`、`SCHEDULE_MIN_INTERVAL_MIN = 5`（`packages/protocol/src/schedules.ts`），未做成系统参数。
- 「由定时任务触发」的说明由服务端作为一条上下文追加（同 /stop 中断说明），`RunStart` 与 daemon 代码未改；daemon 只随新的 `gonggong-tools.json` 重新构建。
- 连续失败按该任务最近 3 个已结束运行重算（可重复调用），在运行收尾与下次触发前各结算一次。
- 候选 Bot、主人是否在群在触发时检查，不在群/Bot 模块里挂钩子。
- 界面：候选 Bot 用「上移」按钮排序；卡片提供暂停/恢复、编辑、删除（两次点击确认）。
- 测试：`packages/protocol/test/schedules.test.ts`、`apps/server/test/schedules.test.ts`、`apps/server/test/schedule-tools.test.ts`、`apps/web/test/schedules.test.tsx`、`e2e/schedules.spec.ts`。
