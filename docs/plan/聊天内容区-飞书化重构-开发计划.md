# 聊天内容区飞书化重构开发计划（草案）

目标：聊天内容区的结构对齐飞书桌面端，视觉遵循 macOS 27（沿用《macOS27-视觉与动效重构-开发计划》的 token），状态类信息**用图形代替文字**，配合有目的的动效。

## 1. 已确认决策

| # | 项 | 结论 |
| --- | --- | --- |
| C1 | 排布 | 我的消息靠右、用蓝色气泡；其他成员和 Bot 靠左、用浅色气泡；连续同一发送者 5 分钟内合并，不重复显示头像和名字 |
| C2 | Bot 回复 | 纯文字回复用气泡；含代码块、表格、文件或 diff 的回复并入运行卡片，卡片最大宽度加宽 |
| C3 | 动效实现 | 引入 `motion`（13.4.x，已用 `npm view` 核实兼容 React 19）。**推翻原 D1**：弹簧、布局动画、手势交给 motion；token 仍以 `motion.css` 为准，在 JS 侧镜像一份 |
| C4 | 范围 | 时间线、悬浮操作条 + 表情回应、输入框、右侧过程面板（RunRail） |

## 2. 飞书结构对齐

| 元素 | 飞书做法 | 我们的落地 |
| --- | --- | --- |
| 气泡 | 左侧灰白、右侧浅蓝，圆角 8–12，发送者名字在气泡上方（仅群聊） | 气泡的圆角用同心 token；右侧不显示自己的名字 |
| 日期分隔 | 居中的灰色小胶囊 | `tl-day` 改成胶囊，吸顶（sticky），滚动时显示当前日期 |
| 系统事件 | 居中灰色小字 | 保留，改为「图标 + 短句」胶囊（见 §3） |
| 未读分隔 | 「以下为新消息」横线 | 新增，位置取进入群时的已读 seq |
| 悬浮操作条 | 悬停时在气泡右上角浮出：表情、回复、转发、更多 | 表情回应、引用回复、复制、查看过程（仅运行卡片）；放进「更多」的：复制链接 |
| 表情回应 | 气泡下方一排表情计数胶囊 | 新增（需要后端，见 S5） |
| 消息卡片 | 彩色标题栏 + 正文 + 底部按钮 | 运行卡片的标题栏按状态着色（仅做细色条，不铺满） |
| 输入框 | 底部整块圆角框，工具行放在框内底部 | 见 S7 |

## 3. 哪些内容适合图形化

判断原则：**离散状态、数量级、关系、进度**适合用图形表达；**需要逐字读的内容**（正文、命令、路径、错误原因、审批参数）保留文字。每个图形都必须带 `aria-label` 和 `title`，动效不能是唯一的信息来源（HIG）。

| 信息 | 现状 | 图形化方案 | 动效 |
| --- | --- | --- | --- |
| 运行状态（9 种） | Badge 文字 | 自绘 SVG 状态图标：排队＝沙漏，运行＝旋转弧，等待审批＝盾牌脉冲，等待回答＝问号气泡，完成＝对勾，中断＝方块，作废＝虚线圆；文字只在 hover 时显示 | 状态切换时用 motion `AnimatePresence` 交叉淡入；完成时对勾用 stroke 描线 |
| 进行中的步骤 | 一行文字 | 工具类型图标轨道：读取/编辑/执行/搜索/访问网络/思考，已完成的变灰，当前步骤高亮；步骤全文放在 tooltip 里 | 新步骤从右侧滑入，当前步骤呼吸高亮 |
| 改动文件数 | 「改动 N 个文件」 | 文件图标 + 数字，外加 `+12 −3` 五格增删条（GitHub 式） | 增删条从 0 长到目标值 |
| 耗时 | `mm:ss` | 保留数字，前面加一个小时钟环（环的进度按分钟循环） | 环连续转动（仅运行中） |
| Token 用量 | 「1.2k tokens」 | 保留数字，前面加一个小能量条，按 10k 为满格 | 无 |
| 接力 hop | 「接力 2/5」 | 5 个链节圆点，已走的实心 | 前进一节时点亮 |
| 扇出 | 「扇出 · 3 个 bot 并行」 | 消息下方画分叉线，连到 3 个 Bot 头像 | 分叉线依次描线 |
| 审批倒计时 | `mm:ss` 文字 | 围绕盾牌的倒计时环 + 数字 | 环连续收缩，剩 30 秒变橙色 |
| 离线等待 | 文字说明 | 机器图标 + 断开的连线 | 连线虚线流动 |
| 新会话提示 | 文字 | 刷新图标 + 短句（原因保留文字） | 无 |
| 系统事件 | 小图标 + 长句 | 大一号的彩色图标 + 精简短句，完整文字放在 tooltip | 首次到达时弹入 |
| 附件 | 已有类型图标 | 按文件类型着色（PDF 红、表格绿……） | 无 |
| 空会话 / 空群 | 文字 EmptyState | 插画 | 轻微漂浮 |

图标来源的优先级：lucide（已在用）→ `better-icons` 检索 Iconify → 手绘 SVG（状态图标、增删条、链节、倒计时环）→ `ludou-gpt-image-2` 生成透明背景 PNG，**只用于插画**（空状态、首次引导），不用于需要随主题变色或做动效的元素。

| # | 项 | 结论 |

### 4.1 图像风格（依据 macOS 27 调研）

调研结论：macOS 27 的图标更锐利、暗边加亮高光、颜色更饱和、多层玻璃叠加；侧栏图标恢复彩色；HIG 要求图标「少量且有目的」地使用；SF Symbols 提供分层着色（同一颜色、不同透明度）和 Draw On/Off、Bounce、Pulse、Breathe、Rotate 等动效。

| 层 | 用途 | 风格 |
| --- | --- | --- |
| 界面图标 | 状态、工具轨道、事件、附件 | SF Symbols 风格的线性图标：lucide 描边 1.5–1.75，对应 SF 的 regular 字重。**分层着色**：主体 100% 语义色，辅助部分 40% 透明度填充。动效只用 SF 那几种：出现用 Draw On，完成用 Bounce，等待用 Pulse/Breathe，运行用 Rotate |
| 插画 | 空状态（见下表） | **纯扁平**（样图评审定稿）：纯色填充，无渐变、无高光、无玻璃、无 3D；前后层次只靠重叠处加深同色表达；限定三色：系统蓝 `#0A84FF`、浅靛 `#7D7AFF`、浅青 `#8FE3F7`；单个居中物体，大圆角，无文字；透明背景 PNG，显示尺寸 ≤ 160px |

评审过程：玻璃物件风（玻璃感过强）→ 半扁平 → **纯扁平**。3D 黏土风不考虑。

| 插画 | 场景 | 物体 |
| --- | --- | --- |
| `empty-chat` | 时间线「还没有消息」 | 两个重叠的对话气泡 + 星点 |
| `pick-chat` | 未选择会话 | 列表面板 + 指针 + 小气泡 |
| `denied` | 群不存在或你已不在群内 | 对话气泡 + 锁 |
| `failed` | 加载失败（群列表、时间线、运行过程） | 云 + 断开的链节 |
| `no-result` | 搜索无结果 | 放大镜 + 空白文档 |

生成统一用下面这段风格描述，只替换物体描述；产物裁掉透明边后缩放到 320px（2x），放在 `apps/web/src/assets/illustrations/`：

```
App empty-state illustration, flat vector style: a single centered object — <object>. Pure flat solid color fills, no gradients, no highlights, no glass, no 3D; overlapping areas use a slightly darker tone of the same hue to show layering. Colors: system blue #0A84FF, light indigo #7D7AFF, soft cyan #8FE3F7. Geometric, clean, minimal, generous rounded corners, consistent with Apple SF Symbols and macOS 27. No scene, no floor, no shadow, no outline, no text, no letters. Transparent background, object fills about 70% of canvas.
```

## 6. 实施记录（2026-09-24）

S1–S8 已完成：web 281 个、server 312 个测试全绿，typecheck 通过，biome 无新增问题；e2e 尚未跑。与计划的偏差：
- 运行卡片暂不显示五格增删条：`RunDto` 只有 `filesChanged`，没有行数。后续如果要显示，需在协议中增加 `linesAdded` / `linesRemoved`。RunRail 中已按每个文件显示。
- 图形的读屏标签用视觉隐藏文字 + `title` 实现（不用 `role="img"`），这样现有 e2e 对「已完成 / 运行中」等文字的断言仍然有效。
- 非群成员操作表情回应返回 404，与 `requireMember` 一致；接口允许对任何消息加回应，界面只在普通消息和 Bot 回复上显示。
