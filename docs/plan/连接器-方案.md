# 连接器 · 调研与方案（M1 开发中）

> 2026-11-23 姜维川提出：对话里没有「连接器」入口，新手不知道 Bot 能连哪些外部系统、怎么连、怎么用。对标 WorkBuddy「连接器」一比一复刻，把飞书、飞书项目、数仓、墨刀等现有 MCP / Skill 集成各包装成一个连接器；数仓自研，留口子让数仓自己迭代追加工具。本文只做调研与规划。

## 1. WorkBuddy 连接器拆解

| 位置 | 做法 |
|---|---|
| 入口 | 左栏「专家 · 技能 · 连接器」一页三 Tab；输入框「+」菜单 → 连接器子菜单 |
| 目录页 | 三列卡片：图标、名称、两行描述、右上「+」；顶部搜索框、右上「自定义连接器」 |
| 详情弹窗 | 产品图标 ··· 第三方图标、「连接 飞书」、能力说明、主按钮「去试试」+ 次按钮「解绑」（未连接时为「连接」）；下方「试试这样用」示例卡，点卡片右侧图标把示例填进输入框 |
| 输入框子菜单 | 搜索；每行图标 + 名称 + 「连接」（已连接为开关）；底部「管理连接器」跳目录页 |
| 授权 | 各连接器自带：OAuth 跳转、扫码、CLI 登录（飞书、企业微信、钉钉为官方 CLI） |
| 断开 | 已连接卡片右侧开关，关掉提示「已断开」 |
| 自定义连接器 | 弹窗「MCP Server Management」：我的 MCP 列表（名称、绿点状态、开关、展开看工具）+「Configure MCP」写 JSON |

本质：**连接器 = 外部系统的一次授权 + 一组 MCP 工具 / Skill + 一份上手示例**，对用户隐藏 MCP、密钥、Skill 这些概念。

## 2. 共工现状

已有全部零件，缺的是面向用户的统一外壳。

| 零件 | 现状 | 问题 |
|---|---|---|
| MCP | `mcp_servers` 平台/团队/群三层，`${secret:NAME}` 引用密钥，运行时下发（`modules/mcp/`） | 只有管理员在配置页手填 JSON；没有个人层；用户看不到有哪些 |
| Skill / 市场 | `skills` 三层 + 市场 `plugins/installs`，个人层只在本人发起的运行生效 | 用户要先知道 Skill 名才会去装 |
| 插件 | 清单可带 `contributes.mcp` + `skills/` + `secrets` + 图标（`packages/protocol/src/plugins.ts`） | 已能表达一个连接器，只是没有「连接」语义 |
| 密钥 | 团队密钥 `shared / shared_overridable / personal` + 个人密钥，「填写密钥」卡（`modules/secrets/`） | 数仓 Key 靠 Bot 发卡片才填，入口隐蔽 |
| 飞书 | 登录 OAuth 存了用户 token（`feishu_identities`），但 scope 只有 IM；Bot 侧只有 `feishu_send_card`、`list_feishu_messages` | 文档、多维表格、日历等用户态能力没给 Agent |
| 输入框 | `@` 选 Bot，`/` 选命令与插件命令 | 没有连接器入口 |
| 过程展示 | MCP 调用显示为 `plug` 图标 + 原始工具名（`runs/ProcessView.tsx`） | 看不出用的是哪个外部系统 |

## 3. 方案（11-23 综合共字君Codex、gemini大师评审修订）

### 3.1 模型：连接器 = 一类插件，授权态与可用态分开

- 插件 `category: connector`，市场加「连接器」货架。清单加 `connector: { examples, docs? }`（有且仅有连接器类填写）。工具仍走 `contributes.mcp`（优先 http）或 `skills/`，凭据仍走 `secrets`。
- **个人 / 共享不另设字段**：必需密钥里有 `personal` 或 `shared_overridable` 即个人型（每人连自己的），否则共享型（团队管理员填一次）。
- **可用态（Bot 能不能用）**：沿用现状，群里装了并开启（管理员操作）。不做个人层插件安装，`runPlugins()` 不改读取范围。
- **授权态（我连没连）**：按我发起的运行能否解析出全部必需密钥推导，不落新表。
- **连接**：在弹窗里填个人密钥，**默认允许他人机器上的 Bot 使用**（群里的 Bot 极少跑在本人机器上；评审指出原 `allowForeignMachines=false` 会导致填完仍用不了），弹窗明示这一点。
- **解绑**：删除我在本团队的这些个人密钥。连接是账号级、全团队生效；确认框列出读同一密钥的其他插件 / Skill（如 `dw-query`），说明会一起断开。
- **缺连接时 Bot 看得见**：只因缺密钥被挡下的连接器不再静默消失，运行提示词附「未连接的连接器」清单（名称、用途、所需密钥），Bot 需要时调用现有 `secret_request` 给发起人发填写卡，填完继续。
- 运行身份沿用「谁发起用谁的凭据」；接力、定时任务按现有发起人规则。

### 3.2 界面

1. **市场「连接器」Tab**：与插件、Skill 并列；卡片 + 搜索；详情里展示「试试这样用」。负责浏览与安装到群 / 团队（现有安装流程）。
2. **输入框连接器按钮**（M1 即做）：附件旁，列出本群已开启的连接器：图标、名称、已连接 / 「连接」；搜索；底部「管理连接器」跳市场 Tab。不做个人开关，群内开关仍归管理员。
3. **连接器详情弹窗**：共工图标 ··· 连接器图标、说明、「连接 / 去试试 / 解绑」、「试试这样用」示例。去试试 = 把示例填进当前输入框（不自动发送）；个人型连接器在公开群里提示「Bot 的回复群内可见」。
4. **过程展示**：MCP 调用 `<插件>-<名称>__tool` 显示为「连接器名 · tool」。
5. 自定义连接器：沿用群 / 团队 MCP 配置；个人 MCP 放 C3，且只开放 HTTP。

### 3.3 数仓开放口子（C4，上线门槛）

1. 数仓自建远程 MCP（Streamable HTTP），`Authorization: Bearer <个人 Key>`，数据权限照旧按 Key。
2. 工具动态发现：daemon 的 `mcp_tools` 缓存加 TTL；**远程工具非只读（未声明 `readOnlyHint`）一律走审批**，新增写能力不能绕过。
3. 连接器包由数仓维护，市场优先支持**内网 GitLab 导入 + 团队审核**，不做免审 CI 直推。
4. 慢查询回调**不复用群 Webhook**（查数权限 ≠ 发群权限、不支持话题、会镜像到飞书群）：C4 单独设计按运行回调——只回发起人所在话题、校验发起人、不镜像飞书。
5. 内部地址（数仓 MCP、墨刀 token）不进公开仓库：首批连接器包通过市场发布，不放 `plugins/official`。

## 5. 已定（11-23 姜维川「综合意见修改开始开发」）

1. 授权态与可用态分开：群开启 = Bot 可用；个人密钥 = 我的连接（默认允许他人机器）。
2. M1 前置对话入口与过程来源，用数仓（个人）+ 墨刀（共享）验证。
3. 解绑按账号级处理，确认框列出连带断开的插件 / Skill。
4. 慢查询回调不用群 Webhook，C4 另行设计。
5. 数仓发布走内网 GitLab 导入 + 审核。
6. 远程 MCP 写工具强制审批、工具缓存 TTL；个人自定义连接器仅 HTTP；飞书用户态走服务端代理。
