# 连接器 · 调研与方案（待拍板，未开工）

> 2026-11-23 姜维川提出：对话里没有「连接器」入口，新手不知道 Bot 能连哪些外部系统、怎么连、怎么用。对标 WorkBuddy「连接器」一比一复刻，把飞书、飞书项目、数仓、墨刀等现有 MCP / Skill 集成各包装成一个连接器；数仓自研，留口子让数仓自己迭代追加工具。本文只做调研与规划。

## 1. WorkBuddy 连接器拆解

| 位置 | 做法 |
|---|---|
| 入口 | 左栏「专家 · 技能 · 连接器」一页三 Tab；输入框「+」菜单 → 连接器子菜单 |
| 目录页 | 三列卡片：图标、名称、两行描述、右上「+」；顶部搜索框、右上「自定义连接器」 |
| 详情弹窗 | 产品图标 ··· 第三方图标、「连接 飞书」、能力说明、主按钮「去试试」+ 次按钮「解绑」（未连接时为「连接」）；下方「试试这样用」示例卡，点卡片右侧图标把示例填进输入框 |
| 输入框子菜单 | 搜索；每行图标 + 名称 + 「连接」（已连接为开关）；底部「管理连接器」跳目录页 |
| 授权 | 各连接器自带：OAuth 跳转、扫码、CLI 登录（飞书、企业微信、钉钉为官方 CLI） |
| 断开 | 已连接卡片右侧开关，关掉提示「已断开」 |
| 自定义连接器 | 弹窗「MCP Server Management」：我的 MCP 列表（名称、绿点状态、开关、展开看工具）+「Configure MCP」写 JSON |

本质：**连接器 = 外部系统的一次授权 + 一组 MCP 工具 / Skill + 一份上手示例**，对用户隐藏 MCP、密钥、Skill 这些概念。

## 2. 共工现状

已有全部零件，缺的是面向用户的统一外壳。

| 零件 | 现状 | 问题 |
|---|---|---|
| MCP | `mcp_servers` 平台/团队/群三层，`${secret:NAME}` 引用密钥，运行时下发（`modules/mcp/`） | 只有管理员在配置页手填 JSON；没有个人层；用户看不到有哪些 |
| Skill / 市场 | `skills` 三层 + 市场 `plugins/installs`，个人层只在本人发起的运行生效 | 用户要先知道 Skill 名才会去装 |
| 插件 | 清单可带 `contributes.mcp` + `skills/` + `secrets` + 图标（`packages/protocol/src/plugins.ts`） | 已能表达一个连接器，只是没有「连接」语义 |
| 密钥 | 团队密钥 `shared / shared_overridable / personal` + 个人密钥，「填写密钥」卡（`modules/secrets/`） | 数仓 Key 靠 Bot 发卡片才填，入口隐蔽 |
| 飞书 | 登录 OAuth 存了用户 token（`feishu_identities`），但 scope 只有 IM；Bot 侧只有 `feishu_send_card`、`list_feishu_messages` | 文档、多维表格、日历等用户态能力没给 Agent |
| 输入框 | `@` 选 Bot，`/` 选命令与插件命令 | 没有连接器入口 |
| 过程展示 | MCP 调用显示为 `plug` 图标 + 原始工具名（`runs/ProcessView.tsx`） | 看不出用的是哪个外部系统 |

## 3. 方案

### 3.1 模型：连接器 = 一类插件，不新造体系

- 插件清单 `category` 加 `connector`，市场货架加「连接器」栏。清单新增 `connector` 段：
  ```jsonc
  "connector": {
    "auth": "secret",            // secret | feishu-oauth | none；以后加 oauth2
    "audience": "personal",      // personal：每人连自己的账号；shared：团队管理员连一次全员用
    "examples": ["查一下上周麓客+新注册用户数，按城市分组", "..."],
    "docs": "https://..."
  }
  ```
  工具仍走现有 `contributes.mcp`（优先 http，免机器授权）或 `skills/`，密钥仍走 `secrets`。
- **「已连接」不落新表，按现有数据推导**：personal = 本人有个人层引入且所需个人密钥已填（飞书为 `feishu_identities` 有效）；shared = 团队层引入且共享密钥已填。
- 连接 = 个人层引入 + 填密钥（一个弹窗内完成）；解绑 = 删个人密钥 + 取消引入；开关 = 个人层引入的启停。
- 运行时沿用「个人层只在本人发起的运行生效」：谁 @ Bot 就用谁的连接器与凭据，天然做到数据权限隔离；接力、定时任务按现有发起人规则。

### 3.2 界面（一比一对标）

1. **目录页**：市场页顶部加「连接器」Tab（与插件、Skill 并列），三列卡片、搜索、右上「自定义连接器」。卡片右上：未连接「+」、已连接开关。
2. **详情弹窗**：共工图标 ··· 连接器图标、「连接 数仓」、说明、「去试试 / 解绑」（未连接为「连接」），「试试这样用」示例卡，点击回到当前群并把示例填进输入框。
3. **连接流程**：`secret` 弹出填写框（复用「填写密钥」表单，附「如何获取」链接）；`feishu-oauth` 走飞书授权页补 scope；完成后弹窗变「已连接」。
4. **输入框入口**：附件按钮旁加「连接器」按钮（或「+」菜单子项），列出本群可用连接器：搜索、状态、连接/开关，底部「管理连接器」。
5. **对话中缺连接**：Bot 用到未连接的连接器时，发「连接 数仓」卡给发起人（复用 `secret_request` 卡的投递与回调），连上后可「继续」。
6. **过程展示**：MCP 调用显示连接器图标与名称（`数仓 · query`），代替原始 `<插件>-<name>__tool`。
7. **自定义连接器**：先复用现有群/团队层 MCP 列表；个人层 MCP（我的 MCP）放 C3。

### 3.3 数仓开放口子

目标：数仓团队加工具不用等共工发版，共工只认一个地址。

1. **数仓自建远程 MCP 服务**（Streamable HTTP），鉴权 `Authorization: Bearer <个人 Key>`，按 Key 做数据源/表权限（沿用现有 Manager 权限体系）。
2. **工具即时生效**：共工每个新会话调 `tools/list`，数仓新增、修改工具，下一个会话就能用；工具描述写清用途和口径，Agent 自己选。可选支持 `notifications/tools/list_changed`。
3. **连接器包由数仓团队维护**：`dw` 插件只含清单（图标、说明、示例、`contributes.mcp` 指向地址、`secrets: DW_MANAGER_API_KEY`）和一份取数规范 `SKILL.md`（替代现在的 `dw-query`），放在数仓自己的仓库，经市场「GitHub/GitLab 导入 → 团队审核」发布；改示例、改说明不涉及共工代码。
4. **回调**：慢查询由 MCP 工具立即返回任务号，结果出来后数仓调群 Webhook（`POST /api/hooks/:token`，已有）把结果或下载链接发回群里并 @ 发起人。不新开回调协议。
5. **共工侧只需**：市场支持 GitLab 内网导入（目前只认 github.com）或开放「发布新版本」API token —— 二选一，见拍板项。

|---|---|---|---|

## 4. 分期

| 期 | 内容 | 涉及 |
|---|---|---|
| C1 目录与详情 | 清单 `connector` 段、连接器货架与目录页、详情弹窗、连接/解绑（secret 型）、去试试；首批包装数仓、飞书项目、墨刀 | protocol、server market、web market |
| C2 对话入口 | 输入框连接器菜单、缺连接卡、过程展示连接器名 | web chat/runs、server secrets |
| C3 飞书用户态 + 个人 MCP | 飞书 OAuth 补 scope 并注入运行；「我的 MCP」个人层 | server feishu/mcp（迁移）、daemon 无改动 |
| C4 数仓开放 | 数仓远程 MCP 上线、GitLab 导入或发布 API、Webhook 回调联调 | 数仓团队为主 |

C1、C2 不改表（`category`/清单是 jsonb）；C3 个人层 MCP 需要迁移，推前确认。
