# 群内多工作区开发计划

目标：一个 Bot 在一个群里可以同时有多个工作区（仓库或目录），统一在「Bot 与工作区」里管理。「额外仓库」「附加目录」「/cd 工作区」三个概念合并为「Bot 在本群的工作区列表」。

姜维川 2026-11-04 确认方向：群仓库仍按群管理，每个 Bot 维护自己的工作区列表；强制同步只同步主仓库；`/cd` 改为切换主工作区、把仓库改为本机检出；默认工作区仍只有一个。

## 1. 现状

| 概念 | 存放位置 | 谁来设 | 下发给 daemon 的字段 |
|---|---|---|---|
| 群主仓库 | `group_repos.is_primary` | 群管理员 | `workspace.repo`，托管路径 `<home>/workspaces/<g>/<b>/<repoId>` |
| 额外仓库（只能在分区群用） | `group_repos` 非主仓库 | 群管理员 | `workspace.extraRepos`，daemon 在主仓库旁托管克隆，再并入 `extra_dirs` |
| 本群工作区 | `group_bots.workspace_kind/cd_path/workspace_*` | Bot 主人 | `workspace.cdPath`，为空时用托管路径 |
| 附加目录 | `group_bots.extra_dirs` | Bot 主人 | `workspace.extraDirs`，即 ACP 的 additionalDirectories |
| 默认工作区 | `bots.default_workspace` | Bot 主人 | 进群时写入 `cd_path` |

存在的问题：
- 额外仓库只能托管克隆，不能用本机已有的检出。
- 附加目录只是一串路径，看不到它是哪个仓库、哪个分支、状态如何。
- 同样是「会话里多一个目录」，却分在三个入口、用三种叫法。

## 2. 决策

| # | 项 | 结论 |
|---|---|---|
| D1 | 模型 | 新表 `group_bot_workspaces`，每行是 (群, Bot) 的一个工作区。`source`：`repo`（对应一个群仓库）或 `dir`（Bot 自带目录）。`kind`：`managed`（托管克隆）或 `local`（本机路径） |
| D2 | 群仓库与工作区的对应 | 群里每个仓库，每个 Bot 都自动有一行 `source=repo`，默认托管克隆。主人可以改成本机检出，要求 remote 与群仓库一致（沿用 `check_cd`）。群仓库增删时，对应的行随之增删 |
| D3 | 自带目录 | `source=dir, kind=local`，取代 `extra_dirs`，只有 Bot 主人能增删。可以是任意仓库或普通目录，路径校验沿用工作区绑定计划的 W8 |
| D4 | 主工作区（会话启动目录） | 群绑了仓库时，主工作区固定为群主仓库对应的那一行（Git 面板、禁止直推、强制同步都基于它）。主仓库由群管理员在群仓库列表里切换。群没有仓库时，由主人从自带目录里选一个作主工作区。**这一条比讨论时说的「任意一项都能设为主工作区」收紧了**：放开要等第二期 daemon 能按工作区分别报 git 状态 |
| D5 | 额外仓库与群模式 | 去掉「额外仓库只能在分区群用」的限制。强制同步群只同步主仓库，其他工作区标「不参与同步」 |
| D6 | 生效时机 | 换主工作区：开新会话，并在群里说明原因（沿用 W11）。增删其他工作区：下一轮生效，会话接续（additionalDirectories 在恢复会话时重新传入） |
| D7 | `/cd` | `/cd @bot <路径>`：路径的 remote 与某个群仓库一致时，把该仓库改为本机检出（若是主仓库，即切换主工作区）；不一致时加为自带目录。`/cd --reset` 把主仓库改回托管克隆 |
| D8 | 默认工作区 | 仍只有一个目录。进群时：remote 与群仓库一致，就作为该仓库的本机检出；群无仓库时，作为主工作区的自带目录 |
| D9 | 下发（第一期不改 daemon） | 服务端把列表拆回现有字段：主工作区 → `repo` + `cdPath`；托管的非主仓库 → `extraRepos`；本机检出的非主仓库和自带目录 → `extraDirs`。daemon 本来就把 extraRepos 的托管路径并进 `extra_dirs`，所以旧客户端行为不变 |
| D10 | 状态与 git | 第一期：每一行显示服务端已知的信息（仓库、分支、托管或本机、路径）。只有主工作区显示 git 状态，与现在相同。第二期 daemon 按工作区分别报状态，届时再放开 D4 |
| D11 | 权限 | 群仓库：群管理员。每行的托管/本机切换、自带目录增删：Bot 主人或 sysadmin。普通成员只能查看 |
| D12 | 清理 | 移出群、删除行时只删托管目录，永不删除本机目录（沿用 W14） |

## 2.1 第一期实现时的调整（2026-11-04）

- **存储**：没有建 `group_bot_workspaces` 表。主工作区仍用 `group_bots` 上原有的字段，它有完整的克隆/确认/绑定状态机，原样保留最稳。只给 `group_bots` 加了一列 `repo_paths`（附加仓库 id → 本机克隆路径），没有这项的附加仓库就是托管克隆。自带目录继续存 `extra_dirs`。迁移 `0095_bot_repo_paths` 只加这一列，不回填数据。第二期改 daemon 时再决定要不要建表。
- **D6**：增删任何工作区都开新会话，和原来改附加目录时一样，不再区分。
- **D7**：`/cd` 指向某个附加仓库的克隆（remote 一致）时，改用这份克隆；其他路径仍然重新绑定主工作区（remote 不一致照旧报错），不会悄悄变成自带目录。
- **附加仓库的本机克隆**：由服务端通过 `dir.list` 校验 remote，不经过 `workspace.cd`，免得打断主工作区正在进行的克隆。改分支时本机克隆跟着保留；改回托管会立即补克隆。
- **桌面端空间管理**：`extraRepoIds` 仍列出全部附加仓库，改用本机克隆后原来的托管克隆不会被当作「未使用」自动清理。

## 3. 切片（TDD；每片测试全绿 + typecheck + lint）

### S1 协议
- `web.ts`：新增 `GroupBotWorkspaceDto { id, source, kind, repoId | null, path | null, primary, state, error }`，`GroupBotStateDto.workspaces` 取代 `extraDirs`，后者保留一个版本用于兼容。
- 请求：`PUT /api/groups/:id/bots/:botId/workspaces/:wsId { kind, path }`（本机检出或改回托管），`POST …/workspaces { path }`（新增自带目录），`DELETE …/workspaces/:wsId`，`PUT …/workspaces/:wsId/primary`（仅限群无仓库时）。
- `daemon.ts` 不改（D9）。

### S2 服务端（含迁移，推送前先确认）
- `schema.ts` 新增 `group_bot_workspaces` 表，执行 `db:generate`。迁移回填：
  - 每个未移出的 (群, Bot)，按群仓库各生成一行；主仓库那一行按 `workspace_kind/cd_path` 决定托管还是本机；
  - `extra_dirs` 每一项生成一行 `source=dir`。
  - `group_bots` 上的旧字段这一期保留不删，作为兼容读取的来源；下一期再删。
- 群仓库增删（`extra-repos.ts`）时同步增删各 Bot 对应的行；新 Bot 进群时生成对应的行（`joinWorkspace`）。
- `scheduler.ts`、`workspaces/diff.ts`、`workspaces/daemon.ts`（`DaemonWorkspaceDto`）、`git/service.ts` 改为从新表拼下发字段（D9）。
- 解除额外仓库只能在分区群用的限制。强制同步的切换校验只看主仓库。
- `/cd` 按 D7 实现。
- 测试：
  - 回填（三种来源）；
  - 拆字段下发（托管/本机 × 主/非主）；
  - 权限（主人、sysadmin、普通成员、群管理员）；
  - 群仓库增删联动；
  - 改主工作区开新会话，增删其他工作区不开新会话；
  - 强制同步只同步主仓库。

### S3 Web
- 群设置「Bot 与工作区」：上面是群仓库列表（管理员维护）。下面每个 Bot 一张卡片，列出它的工作区：图标、仓库名或目录名、分支、托管/本机、路径、状态，主工作区标 ★。主人可以「改为本机检出… / 改回托管」「添加目录…」（沿用目录浏览器 `DirPicker`）、「移除」。
- 删除「附加目录」对话框和群信息里的相关入口，改到卡片里。
- Bot 详情页加「工作区」tab：默认工作区，加上按群列出的全部工作区（扩展 `/api/bots/:id/activity` 返回的数据）。
- 测试：卡片渲染、本机检出、添加和移除目录、普通成员只读、强制同步群标「不参与同步」。

### S4 桌面端
- 空间管理页（`DaemonWorkspaceDto`）显示的多个工作区要与新模型一致，确认托管目录的归类和清理不受影响。

### 第二期（2026-11-04 姜维川定：只做界面）
- daemon 本来就把附加目录（托管的附加仓库、本机克隆、自带目录）作为 `kind: 'extra'` 报在 `GitStatus.repos` 里，所以不改 daemon、不发版。
- 「Bot 与工作区」里每个工作区显示当前分支、↓落后 ↑领先、是否有未提交改动。本机克隆和自带目录按路径对应；托管克隆按路径里的仓库 id 对应。
- 不做：主工作区设成任意一项。Git 面板、禁止直推、强制同步、工作区就绪状态都默认主工作区就是群主仓库，改动面大，暂不做。旧字段也继续沿用。

## 4. 风险
- 回填迁移涉及正式数据：先在本机用正式库的备份演练，核对行数（未移出的 group_bots × 群仓库数 + 附加目录总数）。
- 恢复会话时 additionalDirectories 变化：claude / codex 适配器都要验证「下一轮生效、会话接续」。如果某个 agent 不支持，就退回开新会话并在群里说明。
