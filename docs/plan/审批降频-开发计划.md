# 审批降频开发计划

目标：在不放宽安全底线的前提下，减少 Bot 主人收到的权限审批。借鉴 Claude Code（只读免审、「始终允许」持久化为最小规则并展示范围）、Codex（前缀规则、推荐规则），以及两者共有的「高危操作永不自动放行」。

## 1. 现状（频繁的根因）

| 项 | 现状 |
| --- | --- |
| 只读命令 | `ls/cat/git status` 等只在 `allowlist` 模式免审；默认 `ask` 模式下每次都问（`local.rs` `read_only_trusted=false`） |
| 始终允许 | 只存在 daemon 内存 `State.always`，按（群, Bot）区分；daemon 重启、换群都要重批；不回写服务端 |
| 记住的粒度 | `remembered()` 记录整段命令（`npm test foo`），参数一变就不命中 |
| 非命令请求 | MCP 工具、网络访问等非 execute 请求无法被记住，每次都问 |
| 卡片 | 「始终允许」不显示会放行什么 |
| 底线 | `全部自动` 模式连 `sudo`、`git push --force` 也自动放行 |

## 2. 决策

| # | 项 | 结论 |
| --- | --- | --- |
| A1 | 只读免审 | 内置只读命令（及工作区内 `cd`）在 `ask`、`allowlist` 两种模式都视为可信：整条命令全由只读段组成即自动批准 |
| A2 | 记住的粒度 | `remembered()` 对每段生成**最小前缀**：取开头最多 3 个「普通词」（`^[A-Za-z0-9][A-Za-z0-9._:@+-]*$`，遇 `-` 开头、路径、引号、`=` 即停）；普通词少于 2 个且该段还有其他词时，记整段原文；只读段和工作区内 `cd` 不记；程序名属于 `EXACT`（`rm sudo su doas sh bash zsh fish python python3 node deno bun perl ruby php eval exec xargs env curl wget ssh scp rsync dd chmod chown kill pkill killall mv`）时记整段原文 |
| A3 | 非命令请求 | 非 execute 请求「始终允许」时记 `tool:<title>`（完整标题，精确匹配）；`allowlist` 白名单里也可手写 `tool:<title>` |
| A4 | 持久化 | 新字段 `bots.always_allow`（`string[]`，按 Bot，跨群生效）。daemon 在 `approval.request` 带上 `remember`（点「始终允许」会记住的规则）；主人选 `allow_always` 时服务端把 `remember` 并入 `always_allow` 并广播 Bot；之后每次 `run.start` 下发 `alwaysAllow`。daemon 内存 `always` 保留，用于本次运行内立即生效 |
| A5 | 生效范围 | `alwaysAllow` 与内存 `always` 在 `ask`、`allowlist` 模式生效（同今天的内存 always）；`all` 模式本就全放行 |
| A6 | 硬底线 | 命中底线的命令**任何规则都不自动放行**（含 `all` 模式、白名单、始终允许），一律转主人；`full` 档不变（agent 不会发请求）。底线：任一段程序名为 `sudo/su/doas`；`rm` 带 `-r`/`-f` 类参数且目标含 `/`、`/*`、`~`、`~/…`、`$HOME…`、`..`、`.`、`*`；`git push` 带 `-f`/`--force`/`--force-with-lease`/`--mirror`/`--delete`/`:`开头 refspec；`git reset --hard`；`git clean` 带 `-f`；管道下游是 `sh/bash/zsh/python*/node`；`chmod -R`/`chown -R`；`dd of=`；`mkfs*`。命令解析失败（`commands()` 为 `None`）时在 `all` 模式仍放行（与今天一致），但若原文命中上述关键字（`sudo `、`rm -rf /`、`| sh`、`| bash`）也转主人 |
| A7 | 卡片 | 「始终允许」按钮仅在 agent 提供 `allow_always` **且** `remember` 非空时显示；按钮旁显示「将始终允许：npm run build、tail」；`remember` 为空时只给「批准 / 拒绝」 |
| A8 | 管理 | Bot 设置「命令审批」下新增「始终允许」列表（TokenField，可删可加），`ask`/`allowlist` 模式显示，仅主人可改（同 J9） |
| A9 | 不做 | AI 分类器复审、OS 沙箱、可配置 deny 规则、运行中改档位重设 agent 模式——另立计划 |

## 3. 契约（S1，先于其他切片）

- `daemon.ts` `ApprovalRequest.remember: string[]`（default `[]`）；`RunStart.bot.alwaysAllow: string[]`（default `[]`）。
- `web.ts` `ApprovalDto.remember: string[]`；`BotDto.alwaysAllow: string[]`；`UpdateBotReq.alwaysAllow`（同 `Allowlist` 校验，仅主人）。
- fixture：`d2s.approval.request.json` 加 `remember`，`s2d.run.start.json` 加 `bot.alwaysAllow`；`protocol.rs` 同步。

## 4. 切片（TDD，每片测试全绿 + typecheck + lint）

### S1 协议（集成者）
见 §3。

### S2 daemon（`crates/gonggong`）
- `local.rs`：A1、A2、A3、A6。`Rules` 增加 `always_allow`（来自 `RunBot.always_allow`）；`decide` 接收请求标题以匹配 `tool:`。扩充 `approval_decision_matrix`、`always_allowed_commands_apply_in_every_mode`，新增底线矩阵与 `remembered` 粒度用例。
- `session.rs`：`on_permission` 计算 `remember` 填入 `ApprovalRequest`；`decide` 选 `allow_always` 时把同一 `remember` 并入内存 `always`。
- 新 `t!` 词条补 `i18n/en.rs`。

### S3 服务端（`apps/server`）
- `schema.ts`：`bots.always_allow jsonb not null default []`，`approvals.remember jsonb not null default []`；`db:generate`。
- `approvals/service.ts`：存 `remember`；`decideApproval` 选中 `allow_always` 且 `remember` 非空时去重合并进 `bots.always_allow`、`publishBot`、写审计（`bot.always_allow`）。飞书卡片决策走同一函数。
- `approvalDto` 带 `remember`；`BotDto` 带 `alwaysAllow`；`PATCH /api/bots/:id` 支持 `alwaysAllow`（仅主人、`normalizeAllowlist`）；组装 `run.start` 时下发 `alwaysAllow`。
- 测试：存取 remember、allow_always 后合并去重、allow_once 不合并、非主人改 alwaysAllow 被拒、run.start 携带。

### S4 Web（`apps/web`，desktop 复用需同时检查）
- `ApprovalBlock.tsx`：A7。
- `ApprovalFields.tsx`：A8；白名单提示文案改为「只读命令在每次询问模式下也自动批准」的口径；`ApprovalValue` 加 `alwaysAllow`，所有使用方（`BotsAdminPage`、`NewBotDialog` 等）同步。
- `en.ts` 补词条；`test/` 覆盖卡片显示范围、无 remember 时隐藏按钮、设置页编辑与非主人只读。

### S5 文档
- `website/user/approvals.md` 说明只读免审、始终允许的范围与管理、硬底线。

## 5. 验收
1. `ask` 模式下 agent 执行 `git status && ls` 不弹审批。
2. 对 `npm run build -- --watch=false` 点「始终允许」，卡片显示「npm run build」；daemon 重启、换群后 `npm run build` 不再弹审批。
3. `全部自动` 模式下 `sudo ls`、`git push -f` 仍弹审批。
4. Bot 设置中删除该规则后再次弹审批。
