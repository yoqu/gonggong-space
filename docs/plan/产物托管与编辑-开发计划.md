# 产物托管与编辑 · 开发计划（P3a 托管 + P3b 批注 + P3c 直接编辑）

> 对标 Google Stitch：AI 在 Bot 本机生成，文件以服务端为准，服务端渲染，右侧面板选中元素后批注或直接修改。方案背景见 `插件体系-方案.md` 第 6 节。分支 `feat/artifacts`。**有数据库迁移、跨 server / daemon / web 三端，推 main 前先确认。**

## 1. 已定决策（姜维川 2026-10-29）

| # | 项 | 结论 |
|---|---|---|
| A1 | 真相源 | 服务端为准。每轮开跑前把产物 head 检出到 Bot 本地；跑完上传新版本；面板手改直接在服务端生成新版本 |
| A2 | 托管范围 | 只托管产物目录 `design/<slug>/`，不托管整个工作区 |
| A3 | 首期范围 | P3a 托管、版本、产物卡片 + P3b 选中元素、批注、交给 AI + P3c 右侧面板直接编辑 |
| A4 | 样式落地 | 只改 `tokens.css` 变量和 inline style；增删、移动元素等结构改动一律交给 AI |
| A6 | 框架约束 | L1「固定外壳 + 约定」：平台固化外壳（设备边框、屏幕切换、跳转、桥接、基础样式），渲染时注入，AI 看不到也改不了；AI 只写清单、各屏 HTML 和 tokens。不合规不拦截，问题清单交给下一轮 AI 修。组件库（L2）和 JSON 结构描述（L3）不做 |
| A5 | 不做 | 无限画布、多屏连线和 Play、多方向分支视图、导出（zip / Figma）、从网址提取设计系统、版本对比、自动三方合并 |

## 2. 复用现有能力

| 需要 | 复用 | 改动 |
|---|---|---|
| 文件内容存储 | 强制同步 blob 的写入、加密、哈希校验代码（`sync/blobs.ts` 的 `writeBlob`/`openBlob`，`seal.ts`） | 抽出一个按根目录参数化的 blob 存储；产物用**独立目录** `<GONGGONG_DATA_DIR>/artifacts/<groupId>/`，不进 `sync/` 目录。原因：强制同步的回收会整目录删除（`purgeGroup`、归档到期），只加存活哈希挡不住。产物 blob 只在产物删除时回收（本期不做删除），版本、缩略图引用的内容都永久保留；配额与强制同步分开计算 |
| daemon 扫描、哈希、上传、原子落盘 | `crates/gonggong/src/sync/`（`manifest.rs` 的 scan / hash_file，`apply.rs` 的原子写，`path.rs` 的路径安全，`client.rs` 的并发传输） | 抽出与「群副本」无关的部分，供 `artifacts.rs` 调用 |
| 独立预览域名、端口模式、分享链接 | `previews`（域名 / 端口两种模式，`preview_shares`） | `previews.kind` 新增 `'artifact'`，内容从服务端 blob 读取，不走隧道 |
| 缩略图 | `snapshot.rs`（机器本地的 Chrome 截首屏） | daemon 上传版本后，在本地静态服务上截图并随版本上传 |
| 卡片原地更新 | `MessageDto.card`（creation 卡） | 新增 `ArtifactCard` |
| 创作入口 | `creations.ts` | 创建时预分配产物和目录，指令不再要求 `preview_static` |

## 3. 模型与机制

### 3.1 数据（迁移，只新增）

- `artifacts`：groupId、pluginId、pluginVersionId、designSystemId、title、`dir`（`design/<slug>`，同群唯一）、headVersionId、createdBy、messageId（卡片）、archivedAt。
- `artifact_versions`：artifactId、`n`（产物内递增，`(artifactId, n)` 唯一）、parentVersionId（必须属于同一产物）、`source`（`'run' | 'edit' | 'local'`）、runId / userId、`submitKey`（幂等键，`(artifactId, submitKey)` 唯一）、`files` jsonb（`[{path, hash, size}]`）、digest、thumbnailHash、`stale`（父版本不是当时的 head）、`issues` jsonb（规范校验结果）、createdAt。版本不可变。
- `artifact_annotations`：artifactId、versionId、`file`（屏幕文件）、ggId、selector、rect、snippet（元素外层 HTML，截断）、note、authorId、`status`（`'open' | 'sent' | 'resolved'`）、sentMessageId。
- `previews` 加 `artifactId`、`artifactVersionId`（为空表示跟随 head）。

### 3.2 一轮

```mermaid
sequenceDiagram
  participant D as daemon（Bot 机器）
  participant S as 服务端
  participant W as Web
  S->>D: RunStart.artifacts [{id, dir, headVersionId, digest}]
  D->>D: 本地目录与上次已知版本比对
  opt 本地有未上传的改动（离线、上次上传失败、人在本机手改）
    D->>S: 先上传为一版（source=local，父版本=已知版本，带幂等键）
    Note over D: 上传失败：本轮不检出该产物，目录原样保留
  end
  D->>S: digest 与本地不同才拉清单和缺失的 blob
  D->>D: 原子检出 head 到 design/<slug>/
  Note over D: Agent 运行
  D->>D: 扫描各产物目录，和检出的版本比对
  D->>S: 缺失 blob 检查 → 上传 → 提交版本 {parentVersionId, files}
  D->>S: 本地截首屏，上传缩略图
  S->>W: 卡片原地更新 vN，已打开的预览自动刷新
```

- **RunStart.artifacts**：目标优先。触发消息明确引用的产物（创作、批注发送、回复或引用产物卡片，包括很久以前的）一定下发；其余补本 Bot 产出或改过的未归档产物，凑满 20 个为止。Agent 需要清单外的产物时，用工具 `artifact_checkout` 按需拉取。避免把所有产物都检出到每个 Bot 的工作区，尤其是绑了用户仓库的工作区。只有机器带 `artifacts` 能力才下发。
- **前置保护（P0）**：开跑前发现本地有未上传改动，必须先上传成功才能检出 head。上传失败时该产物本轮不检出、目录不动，运行卡片提示「本地改动未能上传」。只有跑完后的上传失败可以不阻塞，留到下一轮开跑前重试。重试用同一个幂等键，服务端重复收到时返回已有版本。
- **提交**：同一事务里锁住产物行（`SELECT … FOR UPDATE`），再比较 head、分配 `n`、写版本、推进 head。两轮基于同一父版本并发提交时，只有一个能推进 head，另一个成为 stale。父版本等于 head 时成为新的 head；否则保存为 `stale` 候选版本，不动 head。卡片提示「v5 基于 v3，期间有 v4」，由人选「采用此版本」（以它为内容、以当前 head 为父，生成新一版）或「交给 AI 合并」（@Bot 附两版说明）。
- **限制**：单文件 10MB、单版 50MB、最多 500 个文件；跳过 `node_modules`、`.git`、点文件。超限时本轮不上传，产物卡片上给出原因。
- **强制同步群（目录所有权）**：产物目录 `design/<slug>/` 只归产物托管管理。强制同步扫描时排除所有已登记的产物目录，不同步、不提交、不检测本地改动。这样不会出现两套版本互相覆盖。产物在不同 Bot 之间流转只走产物托管（检出 head）。
- **旧 daemon**：没有 `artifacts` 能力的机器继续走原来的 `preview_static` 指令，不建产物。

### 3.3 产物结构与外壳（L1）

已落地为产品原型插件 v0.4.0（模板 `app-screens`、设计系统 `luke-plus`、外壳 `kit/`），契约以插件的 SKILL.md 为准。

AI 写的（产物目录 `design/<slug>/`）：

```
gg-artifact.json        清单：{ title, device: "miniprogram" | "mobile" | "desktop", entry,
                               screens: [{ id, title, file: "screens/<id>.html", statusBar?: "light" | "dark" }] }
tokens.css              主题变量（从设计系统原样复制）
screens/<id>.html       每屏一个完整 HTML 文档，引用 ../_gg/gg-kit.css、../tokens.css、../_gg/gg-kit.js
assets/                 图片等
```

平台固化的（**放在插件包的 `kit/` 里，随插件版本走**）：
- `index.html` 外壳：设备边框、状态栏、小程序胶囊、屏幕切换、返回栈；读 `gg-artifact.json`；
- `_gg/gg-kit.css`：重置样式、设备变量（`--gg-status-bar`、`--gg-capsule-*`、`--gg-nav-height`、`--gg-safe-bottom`）、`.gg-ph` 占位图、`.gg-scroll-x`；
- `_gg/gg-kit.js`：`data-gg-link` / `data-gg-back` 跳转，在外壳里通过 postMessage 交给外壳，单独打开时跳到同级文件；
- 桥接脚本（见 3.4）由服务端另外注入。

过渡期（服务端外壳上线前）由 AI 把 `kit/` 原样复制成产物里的 `index.html` 和 `_gg/`，`preview_static` 照常能看。上线后服务端按产物记录的插件版本，从插件文件直接返回 `/`、`/_gg/*`，覆盖产物里的副本。Bot 本机的静态预览和自检截图也用同一份，两边渲染一致。

令牌命名（由 DESIGN.md front matter 机械生成，Stitch 同款格式）：`colors.x` → `--color-x`，`rounded.x` → `--rounded-x`，`spacing.x` → `--space-x`，`typography.x` → `--text-x-size/-weight/-leading` 和类 `.t-x`，字体统一 `--font-sans`。

约定（已写进 SKILL.md）：
- 颜色、圆角、字号只用令牌，色彩变化用 `color-mix()` 叠在令牌上；
- 不用构建工具，不引入框架、CDN 和网络字体（不用 Tailwind，避免 CDN 依赖和类名编辑的复杂度）；
- 内容写成静态 HTML，JS 只用于屏内交互，不用来生成内容；
- 不画状态栏、胶囊和 Home 指示条，不改 `index.html` 和 `_gg/`。

校验（`modules/artifacts/lint.ts`，每次版本提交后执行，结果存在版本上）：
- 清单可解析，屏 id 唯一，文件存在；
- `data-gg-link` 指向的屏存在；
- 写死的色值（`#xxx`、`rgb()` 出现在 style 或 `<style>` 里）；
- 出现外部脚本或样式；
- tokens.css 与设计系统不一致时只提示（人可能在主题面板改过，属正常）；
- `index.html`、`_gg/` 与插件 kit 不一致。

有问题时卡片显示「N 项规范问题」，下一轮 RunStart 的上下文附带问题清单（最多 20 条）。没有 `gg-artifact.json` 的产物（旧产物、其他插件）按单页 L0 渲染（入口 `index.html`）。

### 3.4 渲染与桥接

- 产物预览由服务端读取，`/` 返回外壳页，`/screens/...` 等返回产物文件。每个预览一个 slug：跟随 head 的一个，查看历史版本时按需再开一个。HTML 走 3.5 的处理，其余文件按扩展名返回，加 `nosniff`。
- **外壳默认是画布视图**（姜维川 2026-10-29 定，已在 kit 实现）：所有屏并排平铺，可拖动、缩放，按 `data-gg-link` 画出屏间连线。在画布里点跳转元素，视图会平移到目标屏；每屏标题旁的「演示」按钮切到单机演示视图，点击即可跳转。右侧预览标签页打开就能看到全部界面。
- **桥接注入各屏，不经外壳**（R2 定，取代原「只注入外壳」）：web 画布直接用 iframe 平铺加载各屏（`screens/<id>.html`），不再套外壳，外壳只用于分享链接和 Bot 本机预览。所以由服务端在**成员打开的产物预览**返回屏幕 HTML（L1 的 `screens/*.html`，L0 的 `index.html`）时注入：每个源码里有起始标签的元素加 `data-gg-id="<起始偏移>"`，`</body>` 前插 `<script src="/__gg/bridge.js" data-gg-parent="<主站 origin>">`。外壳 `/`、`/_gg/*`、其他文件和**分享链接**都不注入，分享访客取 `/__gg/bridge.js` 也是 404。存储内容不改。
  - 主站 origin 由服务端决定：配置了 `GONGGONG_PUBLIC_URL` 用它，否则用成员打开 `/api/previews/:id/open` 时请求的 origin；写进预览 cookie（签名），AI 页面改不了。
  - 校验：桥接只往 `data-gg-parent` 精确 origin 发消息；只接受 `event.origin === data-gg-parent` 且 `event.source === parent` 的消息。主站只认该预览 slug 的 origin 和对应 iframe 的 `contentWindow`。
  - 取舍：桥接与 AI 写的屏幕脚本同在一个窗口，屏幕脚本理论上能伪造桥接消息。可接受，因为这些消息只是界面提示（悬停、选中、跳转、尺寸），主站按契约 zod 校验、不把其中字符串当 HTML 渲染，真正的修改都以 `(versionId, file, ggId)` 走服务端编辑接口并在服务端重新定位、转义。换来的是画布不用嵌套 iframe、坐标不用跨两层换算。
  - 预览域名与主站隔离，屏幕 iframe 由主站加 `sandbox="allow-scripts allow-same-origin allow-forms"`，读不到主站 cookie 和存储；端口模式下 `gonggong_session` 不转发（已修）。
  - 用 Playwright 做真实浏览器验收（选中、批注、跳转、画布缩放下的坐标换算）。
- 桥接消息（定义在 `packages/protocol/src/artifacts.ts` 的 `BridgeToShell` / `BridgeFromShell`，字段 `type`）：
  - 主站 → 屏幕：`mode`（preview / mark / edit）、`highlight`（ggIds）、`select-clear`、`scroll-to`（ggId）、`reload`；
  - 屏幕 → 主站（都带 `source: 'gg-bridge'` 和 `file`）：`ready` / `size`（文档宽高）、`hover`（ggId、rect）、`select`（ggId、selector、rect、tag、text、textOnly、computed、inlineStyle、src、href、link）、`nav`（screen）、`back`。rect 是屏幕 iframe 视口坐标，主站自己按画布缩放换算。
- 批注模式和编辑模式在 window 捕获阶段拦截点击和表单提交（先于 gg-kit 的跳转），选中 / 悬停用 `outline` 描边，不改布局；预览模式下点 `data-gg-link` / `data-gg-back` 发 `nav` / `back`，由画布平移到目标屏。

### 3.5 元素标识与源码编辑

- 只处理 `screens/*.html`（L0 产物为 `index.html`）。元素定位一律是 `(versionId, file, ggId)` 三元组，只在该版本内有效。服务端用 HTML 解析器（候选 parse5，开启 `sourceCodeLocationInfo`，引入前用 `npm view` 核实）解析版本里的 HTML。渲染时给每个元素注入 `data-gg-id="<起始偏移>"`，只注入输出，不改存储内容。
- 编辑请求：`{baseVersionId, ops: [{file, ggId, op}]}`。服务端按偏移定位源码片段做文本拼接，保留原有格式：
  - `text`：替换纯文本元素的内容（含子元素的拒绝，提示交给 AI）；
  - `attr`：只允许 `src`、`href`、`alt`；
  - `style`：合并进 inline style，白名单内的属性包括颜色、背景、字号、字重、行高、内外边距、圆角、边框、宽高；
  - `token`：改 `tokens.css` 里 `:root` 下的 `--x: value`，必须是已有变量；
  - `asset`：上传图片到 `assets/`，同时改 `src`。
- 一次保存可以带多个 op，生成一版（source=edit）。`baseVersionId` 不是 head 时返回 409，面板提示「AI 刚更新了 vN」，刷新后重做。
- JS 动态生成的元素在源码里找不到，这类元素只能批注、交给 AI。
- 产物正在被 AI 运行时，面板只读（显示「AI 正在修改」），运行结束自动解锁。这样 stale 候选只会来自离线上传等少数情况。
- 多个 op 先按文件分组，同一文件内按源码偏移从后往前拼接，前面的拼接不会让后面的偏移失效。同一元素上的多个 op 先合并成一次修改；范围重叠的 op 直接拒绝。
- 写入前转义：`text` 做 HTML 转义；`style` 的值只接受令牌引用（`var(--…)`）或数值加单位，拒绝 `url(`、`expression`、`;`、引号；`attr` 的 `href` 只接受相对路径或 `http(s):`。
- **拒绝与提示要分开**：路径越界、非法资源引用、外部脚本、转义失败、越权这类安全或结构错误一律硬拒绝（返回 400，不生成版本）；只有设计规范类问题（写死色值等）作为提示放行。daemon 上传的版本同样适用：路径不安全或超限时整版拒绝。
- 颜色类样式在面板里只能从令牌中选（色板列出 `--color-*`），不提供自由取色，保证人工编辑也能通过规范校验。改全局颜色走主题面板的 `token`。

### 3.6 插件声明

`PluginManifest.artifact`（可选）：`{ editable?: boolean, tokens?: string }`。预览、版本、批注对所有 HTML 产物开放；只有声明了 `editable` 的插件才显示直接编辑；声明了 `tokens`（如 `tokens.css`）才显示主题面板。产品原型插件全开，幻灯片插件不声明。插件不带前端代码。

## 7. 风险与待核实

- 端口模式下，每个打开的预览占一个端口：历史版本预览要用完即关，避免占满端口段。
- parse5 定位到的是解析后的偏移：AI 写出的不规范 HTML（自动补齐的标签）找不到源码位置，这类元素按「不可直接编辑」处理。
- 缩略图依赖机器上装有 Chrome 系浏览器：没有时卡片显示占位图。人工编辑生成的版本沿用父版本的缩略图，下一轮 AI 版本再刷新。
- 产物目录会出现在绑定仓库的工作区里，是否提交由用户自行决定，本期不自动 exclude。
- 画布同时加载所有屏的 iframe：屏数多（> 12）时改为进入视口才加载，离开视口换成截图。
- 过渡期 `creations.ts` 的指令仍是「写到 design/<slug>/index.html，用 preview_static 发布」，与 L1 不冲突：`index.html` 就是复制过去的外壳。S1 改成预分配目录、自动发布后，再删掉这句。
