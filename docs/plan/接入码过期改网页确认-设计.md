# 接入码过期改网页确认 + 新人走查剩余问题（设计）

姜维川 2026-11-12 定：粘贴的那句话照旧带接入码；接入码过期时改走网页确认，不让用户重跑；Docker 无人值守仍只用接入码，过期就重新发码。

## A. 接入码过期 → 网页确认

### 流程

1. `gg login --server S --code C` 照旧先用接入码登录。
2. 服务端回 `code_expired`（过期或已用过）时，gg 不再报错退出，改为发起「接入申请」：`POST /api/daemon/link-requests`，带上机器信息、`createBot` 和那个过期的接入码。
3. 服务端凭过期接入码查到发码人（`bind_codes.user_id`），把申请定向推给他；回给 gg 申请 id、轮询密钥、4 位核对码、确认链接、有效期。
4. gg 立刻打印并刷新输出：确认链接和核对码；有图形界面时尝试打开浏览器（macOS `open`，Linux 有 `DISPLAY`/`WAYLAND_DISPLAY` 时 `xdg-open`，失败忽略）。然后轮询。
5. 用户在网页看到「某机器请求接入」，核对后点「允许」。
6. gg 下一次轮询拿到与 `/api/daemon/login` 相同的结果（token、machineId、bot…），后续与现在完全一样（写配置、`service install`、`machine.onboarded` 打开私聊）。

`gg login --server S`（不带 `--code`）直接从第 2 步开始，供过期后手动重试。

### 服务端

新表 `link_requests`（需迁移）：

| 列 | 说明 |
|---|---|
| id uuid pk | 出现在确认链接里，不可猜 |
| secret_hash text | 轮询密钥的 sha256，只有发起的 gg 持有 |
| user_code text | 4 位核对码，字符集沿用 `CODE_ALPHABET` |
| machine jsonb | `MachineInfo` |
| create_bot_agent text null | |
| hint_user_id uuid null | 过期接入码的发码人；没有则为空 |
| ip text | 发起方 IP，确认页展示 |
| status text | pending / approved / denied / consumed |
| approved_by uuid null | |
| expires_at, created_at | 有效期 15 分钟 |

接口：

- `POST /api/daemon/link-requests` `{ machine, createBot?, code? }` → `{ id, secret, userCode, url, expiresAt, intervalMs }`。`url` 用 `serverUrl()`（与 install 相同的公网地址逻辑）拼 `/link/<id>`。复用现有 IP 限流；同一 `hint_user_id` 同时最多 3 个 pending，超出回 `code_locked`。`code` 只用于查发码人，查不到不报错。
- `POST /api/daemon/link-requests/:id/poll` `{ secret }` → `{ status: 'pending' | 'denied' | 'expired' }`，或 approved 时返回 `DaemonLoginRes`。**绑定在这一步做**：事务里把 approved 改成 consumed，再执行与 `/api/daemon/login` 相同的绑定逻辑（把现有事务体抽成共用函数，归属人用 `approved_by`）。这样 token 不落库。
- `GET /api/link-requests/:id`（需登录）→ 机器名、系统、架构、Agent、IP、核对码、状态、过期时间。
- `POST /api/link-requests/:id/approve`、`/deny`（需登录）。任何登录用户拿到链接都可以批准，机器归批准人（设备授权的标准做法）；写审计 `machine.link.approve`。
- 创建申请时，若有 `hint_user_id`：发实时事件 `machine.linkRequested { id }` 给他，并写一条通知「{机器名} 请求接入」，点开到 `/link/<id>`。

### gg（daemon）

- `bind::login_as` 遇到 `code_expired` 时走新函数 `link_request`；`code_locked`、`unauthorized`、`invalid` 维持原报错。
- 待确认状态存 `~/.gonggong/pending-link.json`（id、secret、server、过期时间）。再次执行 `gg login --server S` 时若有未过期的同服务器申请就接着轮询，不新建。Agent 的命令有时限（常见 2 分钟），被掐断后重跑即可续上。
- 轮询到过期：自动新建一次申请再等一轮；第二次仍过期才退出，提示重新运行 `gg login --server S`。
- 新参数 `--code-only`：过期直接报错，不走网页确认。Docker 入口脚本带上它。
- 服务器不认识新接口（404）时回退到原来的报错文案。
- 文案走 `t!`，补 `en.rs`。

### install.md / install.sh

- install.sh：`~/.local/bin/gg` 已存在且 sha256 与服务器一致时跳过下载，重跑不再重装。
- install.md 增加一段：如果输出里出现确认链接和核对码，把它们原样告诉用户，请用户在浏览器里点「允许」，并继续等待；命令超时就重跑同一条命令。去掉「接入码 30 分钟后过期」那句的警告语气，改成「过期也没关系，会改为网页确认」。

### Web

- 新页面 `/link/:id`：未登录先去登录再回来。卡片内容：机器名（大字）、系统 · 架构、Agent、发起 IP、**核对码（大字，等宽）**，一句「只在你本人刚发起接入、且核对码与终端一致时允许」。按钮「允许接入」（主）/「拒绝」。结果态：已允许（有 `createBot` 时等 `machine.onboarded` 后跳到私聊）、已拒绝、已过期、已处理过。
- 绑定新机器对话框：收到 `machine.linkRequested` 时在「发给你的 Agent」下方插入同样内容的内嵌确认卡，直接点「允许」，不用跳页。
- 接入码倒计时去掉。过期后静默换新码，不再把那句话换成「接入码已失效」；说明改为「接入码过期也能接入，届时在这里点一下允许」。
- Docker 一栏保留有效期提示：「接入码 30 分钟内有效，过期请重新生成」。
- 桌面客户端粘贴过期链接：第二切片再做，先保持现有报错。

## B. 走查剩余 6 项（web 小改动，无迁移）

1. **强制改密不再重输初始密码**：登录成功且 `mustChangePassword` 时，把刚输入的密码放在内存（路由 state，不进 storage）传给 `ChangePasswordPage`，隐藏「初始密码」一栏并用它作 `oldPassword`。刷新页面后 state 丢失，这一栏照常显示。服务端不动。
2. **改密页左侧文案**：标题「最后一步，设置只属于你的密码」与下面三步清单矛盾（它是第 2 步）。标题改「先设置只属于你的密码」，第 3 步改「开始使用共工空间」。
3. **账户菜单入口合并**：非搭建者同时看到「搭建自己的 Bot」和「绑定新机器」。非搭建者只留一项「接入我的电脑」（成为搭建者并打开绑定对话框）；搭建者只留「绑定新机器」。
4. **手机登录页**：logo 下加一行标语「在群里 @ 一下，队友的 Bot 就开工。」，不放演示卡。
5. **底部状态条**：用户名下没有 Bot 时不显示「N 个 Bot 在线」，没有机器时不显示「N 台机器在线」；有了才显示（含 0）。
6. **侧栏空列表**：没有任何会话时显示占位：搭建者且有 Bot →「还没有会话」+「发起会话」按钮；其他 →「被拉进群后，会话会出现在这里」。

每项补对应单测；`pnpm check` 全绿后按小改动直接推。
