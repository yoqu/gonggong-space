## M3 E2E 场景（`e2e/m3-governance.spec.ts`）
1. 扇出 + 审批：一条消息 @ 两个 bot，显示「扇出 · 2 个 bot 并行」→ 两张卡都进入「等待审批」→ 另一名成员看到的「批准」按钮不可点，并提示「仅 bot 主人 … 可操作」→ 主人批准 A、拒绝 B → A 完成并回复命令输出，B 自行绕路 → 侧边栏「审批记录」保留该请求 → 再次触发后在等待审批时 `/stop @bot` → 卡片「已中断」，审批显示「运行已停止，请求作废」。
2. 接力链：两个 bot 通过系统提示词互相 @ → 依次出现第 1、2、3 跳（徽标「接力 2/3」「接力 3/3」），第 3 跳回复里的 @ 只作为文本显示，不再产生第 4 跳 → 把 B 的触发范围改为仅本人后，由其他成员发起的接力在 B 这一跳显示「无权触发」（按链的最初发起人鉴权）→ 用量接口按 bot 汇总出这些轮次。
3. 分区模式 /stop：仓库群中 agent 先建文件，再执行需要审批的命令 → 点卡片的 `/stop` 后显示「已停止 · 本轮改动 1 个文件留在工作区」→ 点「丢弃本轮改动」→ 本轮新建的文件被删除，本轮开始前已有的未提交改动保持不动。

## 切片内已验证的边缘场景（摘要）
- 卡片 / 侧边栏：运行中实时计时、用量未上报、新会话原因、过程的保留期到期后只保留摘要（把 `runRetentionDays` 设为 0 实测，审批记录仍保留）；回复中的文件路径可点开本轮该文件的 diff；在 1000px 和 390px 宽度下验证布局；echo 出的 `ghp_…` 在过程和详情中均显示为 `[已脱敏]`，即使 token 被拆在两个流式片段里也能识别。
- 审批：非主人调用返回 403、重复决定返回 409、选项不存在返回 400；超时自动拒绝（真实 agent 收到拒绝后继续跑完）；run 结束或被 /stop 时作废待审请求（作废原因落库为 voidReason：stopped / chain_stopped / ended）；每个决定都有审计和主人通知；daemon 等待决定时不阻塞 ACP 分发。
- 触发范围与用量：all / list / self 三种范围、bot 主人始终放行、full 档位视为 list；中断或失败的轮次不再接力；用量中「未上报」单独计数；非主人按 botId 查询返回 403。
- /stop 与丢弃：未 @ 时停止本群所有未结束轮次，@ 时只停该 bot；排队中和离线等待的轮次立即中断；「终止整条链」后不再有后续跳；保留 / 丢弃仅限触发人、发起人或 bot 主人，丢弃失败时保持待选择并在群里提示；下一轮上下文会告知 agent 上一轮被中断以及文件状态；离线请求按 offlineWaitMin 作废，并通知触发人；接力链结束时通知发起人（同一条链只通知一次）。
- 集成期修复：审批作废原因由「前端从卡片步骤文字推断」改为落库字段；离线倒计时改用群参数；两条靠固定时间等待的不稳定测试改为按条件等待。
