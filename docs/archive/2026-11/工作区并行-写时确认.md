# 工作区并行：写时确认（定稿）

共字君方案 A + gemini 大师评审合并（2026-11-26）。

## 问题
`workspace::occupy` 在每轮开跑前判断：同一真实目录已有其他轮次在跑，就向群里提问「并行开始 / 排队等待」。多数轮次只读（问答、排查、审查），提问纯属打扰。

## 目标
- 只读轮次不提问、不排队。
- 只有「本轮要改文件，且目录里有别的轮次可能在改」才提问，提问写明对方和本轮要改什么。
- 防覆盖能力不降低；只改 daemon，不动协议与服务端。

## 设计
### 1. 占用登记（`workspace.rs`）
`Holder` 增加 `writer`：可以不经确认就改文件的轮次。
- 目录空：直接登记为写者（与现状相同，单 Bot 场景零变化）。
- 目录有人、且本轮能「守护」：登记为非写者（守护中），不提问。能守护 = 只读档 bot（本来就会请求权限），或 agent 有只读档模式可切（Claude/Codex/各插件 agent）。
- 不能守护（pi、DeepSeek、OpenCode、Copilot 等）：目录里有写者才按原流程提问「并行开始 / 排队等待」；只有守护中的轮次则直接进。
- 手动 Git 操作照旧独占。

### 2. 守护模式（`session.rs` `Conversation::guard`）
守护轮次（非只读档）开跑时切到 `mode_for(kind, Tier::ReadOnly)`：Claude `default`、Codex `read-only`、插件的 readonly 模式。**工作区档与完全允许档都守护**（gemini 指出 `acceptEdits` 等模式下编辑不走权限请求）。agent 没有该模式或切换失败：开跑前就按写时冲突处理（有写者才问「并行修改 / 等它结束再改」），不会静默并行。

### 3. 写时门禁（`permission_in` → `Gate`）
- 判定写：`edit/delete/move` 及未知 kind 算写；`read/search/think/fetch/switch_mode` 与 MCP 工具不算；`execute` 用 `local::reads_only`（只读命令、无重定向写，读工作区外也算只读，敏感文件除外），判不出算写。
- 首次写：目录里没有其他写者 → 本轮成为写者，异步 `session/set_mode` 切回本档模式，然后照常走原审批规则（`decide` / 问主人），**门禁不绕过审批**。
- 有其他写者 → 挂起这次请求，向群里提问「{对方} 也在工作区运行，可能正在修改文件；本轮要修改 {工作区内相对路径} / 运行可能改动文件的命令」（不放命令原文，避免主人审批前把参数里的凭据发到群里）：并行修改 / 等它结束再改（推荐）。选并行 → 放行；选等待或无人回答 → 对方都结束后自动撤卡放行；被停止或打断并追加 → 撤卡，挂起请求按取消回答。
- 同一轮并发的写请求只弹一张卡，其余排在 `Gate::held` 里一起放行。
- 打断并追加使当次等待作废（`epoch`），检查、抢写权、发卡在同一把锁内，取回 Git 基线后再校验一次。
- 切回本档模式的请求由下一轮开始前等待完成，不会覆盖下一轮的守护模式。

### 4. 先到的写者不降级
目录空时开跑的轮次就是写者，不中途切到守护模式（避免运行中降级的竞态）。代价：后来者第一次写时会被问一次，即便先到者其实只读。

### 5. 改动归属
守护轮次全程没拿到写权：不认领工作区改动（`files_changed=0`、无 patch），也不记为可「丢弃改动」的轮次，避免把别人的改动算到自己头上或被误丢弃；进行中的「本轮改动」也为空。拿到写权时重新记录 Git 基线，等待期间别人的改动不算本轮。

## 真机验证（2026-11-26，`tests/it/real_gate.rs`，`--ignored`）
- Claude（claude-agent-acp）：守护模式 `default` 下首次写入前发权限请求，冲突卡先于文件落盘；同一轮并发的两个写请求只弹一张卡；运行中 `set_mode` 切回本档模式**立即生效**（第二个文件不再请求）。
- Codex（codex-acp）：`read-only` 下 `apply_patch` 写前发权限请求，门禁生效；运行中 `set_mode` **本 prompt 内不生效**，之后的编辑仍会请求。为此守护轮次的工作区档对工作区内编辑直接放行（本档模式本来也不问），不打扰主人。
- 残留：Codex 拿到写权后本 prompt 内仍在 `read-only` 沙箱，写文件的命令要模型申请提权才会来请求，否则命令失败；只影响共用目录、且本轮要改文件的那一轮。守护模式下「帮我审批」在拿到写权前由共工规则审批。

## 测试
`crates/gonggong/tests/it/engine.rs`：守护轮次只读不提问且处于 `default` 模式；写时有写者才问，选并行/等待/对方结束自动撤卡/被停止；只读档先到者不算写者；只读轮次不认领他人改动。`local::tests`：`reads_only` 判定。真机：`tests/it/real_gate.rs`（Claude、Codex，忽略项，手动跑）。
