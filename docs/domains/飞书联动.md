# 飞书联动 · 现状

> 范围：飞书应用模型、接入流程、群关联与消息同步、飞书登录、卡片与事件、失败与降级、管理后台。只写仍有效的决定，以代码为准，更新于 2026-11-15。

## 应用模型
- 整个系统一个**主应用**（`feishu_apps.kind='main'`，`teamId` 为空，唯一索引 `feishu_apps_one_main`），每个 Bot 最多一个**Bot 应用**（`kind='bot'`，`botId` 唯一）；同一 App ID 不能被两处使用（`apps.ts` `saveApp`）。
- 主应用职责：飞书登录、列出所在飞书群、建群和拉 Bot 应用进群、代发网页消息、成员进出群事件、进群卡片、飞书通知私信。
- Bot 应用职责：收 @ 自己的群消息和单聊、发运行卡片/提问/审批/预览/进度/密钥卡片、收卡片回调与撤回事件。
- Bot 没有自己的应用时，卡片由主应用代发（`mirror.ts` `appOfBot`）。
- 权限、事件、回调的唯一清单在 `feishu/client.ts`：`USER_SCOPES`、`MAIN_TENANT_SCOPES`、`BOT_TENANT_SCOPES`、`MAIN_EVENTS`、`BOT_EVENTS`、`BOT_CALLBACKS`。
- 接收全走长连接（`gateway.ts`，SDK `WSClient` 自动重连），server 无需公网回调；`reloadFeishu` 按 `feishu_apps` 增删连接。
- App Secret、用户 token 用 `lib/seal.ts` 加密存库，Secret 不出 server。
- 没有主应用时飞书联动整体不可用：登录页无飞书按钮，群设置提示「系统管理员尚未接入飞书」。

## 接入流程
- 默认**扫码创建**：设备授权流程出二维码，确认页预填权限、事件、回调（`register.ts`、`client.ts` `addons`）；会话存内存，倒计时到期失效。已接入的应用「更新权限」重新扫码确认（`FeishuRegisterReq.update`），新权限即时生效不需重审。
- 手动填 App ID / Secret 为备选：先调飞书校验凭证再保存（`saveApp`）。
- 保存后用应用自身凭证调「更新应用开发配置」：事件与回调设为长连接，主应用加 OAuth 重定向 URL（`config.ts` `configureApp`）。
- 首个版本审核前配置接口必失败，原因记 `config_error`，后台每 60 秒重试（`startFeishuConfigRetry`），界面可「重试」；非开发者后台创建的应用（飞书码 210021）记 `not_modifiable` 不再重试。
- 审核状态由 `config_error` 推出：`FeishuAppDto.review` 为 approved / pending / unknown（`configReview`）；不申请读应用信息或可用范围的权限。
- 「成员可用」无法读取，只作提醒：新应用默认只有创建者可用，需在飞书管理后台改可用范围（`FeishuAppSteps.tsx`）。
- 对外地址（系统参数 `publicUrl`）是 OAuth 回调、卡片回链、进群卡片按钮的前提；未保存时管理后台禁用扫码并提示「先保存对外地址」，主应用 `config_error` 记 `no_public_url`。
- 扫码成功不关窗，显示同一份「接入进度」清单；已接入后收成状态行 +「更新权限」「更换应用…」「移除」。
- 管理：主应用仅系统管理员（`/api/admin/feishu*`）；Bot 应用为 Bot 主人或系统管理员（`/api/bots/:id/feishu*`，`manageableBot`），入口在 Bot 设置「飞书」页（`BotTab 'feishu'`）。
- 状态统一用 `FeishuAppTag`（未接入 / 连接中 / 等待审核 / 待确认 / 连接失败 / 已接通）。

## 用词
- 应用↔共工叫「接入 / 移除」；共工群↔飞书群叫「关联 / 取消关联」；共工账号↔飞书账号叫「绑定 / 解绑」。
- 成员可见文案不出现「主应用」，称「{name}」机器人或「共工机器人」；「主应用」只在管理后台。

## 群关联
- 一对一：`feishu_chats` 在 `unboundAt` 为空时 `groupId`、`chatId` 各自唯一；取消关联保留历史行和消息映射，关联中的运行继续更新卡片到结束（`unbindChat`）。私聊不能关联飞书群。
- 群管理员在「群设置 › 飞书」从下拉选飞书群关联（`PUT /api/groups/:id/feishu`）；候选只列主应用在、本人也在、未被关联的群（`bindableChats`、`checkBindable`），本人须已绑定飞书。
- 也可「创建飞书群」（`POST /api/groups/:id/feishu/chat`，主应用建群并拉入已绑定成员与 Bot 应用）或「从飞书群创建」共工群（`POST /api/groups/from-feishu`）。「发起会话」建群时可勾选「同时创建飞书群」（默认不勾，需接通飞书且建群人已绑定飞书账号）：先建共工群再调同一建群接口，飞书群失败时共工群保留，提示到群设置 › 飞书重试。
- 进群卡片：主应用被拉进未关联的飞书群时发卡片「接入共工」，打开 `?feishuChat=` 弹窗，二选一「新建共工群 / 关联到已有群」（本人是管理员且未关联的群）；无对外地址时卡片不带按钮（`invite.ts`、`FeishuGroupDialog.tsx`）。
- 关联后自动拉群内 Bot 的应用进群，新加入群的 Bot 同样拉入；拉不进的原因按 Bot 存内存（`issues.ts`），群设置行内显示并可重试（`POST .../feishu/bots/:botId`）。
- 成员镜像：飞书群进人→已绑定且在团队内的账号加入共工群；退群→移出（唯一管理员除外）；共工新成员已绑定时拉进飞书群；新绑定的用户自动加入所在飞书群对应的群；可手动「同步飞书群成员」（`members.ts`）。
- 解散群（`groups/settings.ts`）、归档团队（`teams/members.ts` `archiveTeam`）时自动取消关联。
- 未关联页顺序：绑定你的飞书账号 → 把「{name}」机器人拉进飞书群 → 选择飞书群关联 → 创建飞书群；Bot 未接入时主人见「去接入」（打开 Bot 设置飞书页），他人见「请 Bot 主人接入」（`GroupFeishuTab.tsx`）。

## 消息同步
- 两个开关按方向分组，均默认开：「共工 → 飞书」`syncOutbound`（网页消息发到飞书群），「飞书 → 共工」`syncAll`（只同步 @Bot / 同步全部消息）。
- 飞书 → 共工：Bot 应用收到 @ 自己的消息，按发送者 union_id 映射共工用户，是群成员才写入消息并触发运行（`inbound.ts` `groupTarget`）；附件下载为共工附件；回复已同步的消息显示为引用。
- 同步全部：主应用收关联群全部用户消息，存入不触发 Bot；非成员以飞书昵称作外部作者；与 Bot 应用收到的同一条按 `feishu_message_links` 去重，后到者补 mention 并运行；首条前发一次说明（`syncChatMessage`）。
- Bot 单聊：飞书里和 Bot 应用单聊无需 @，映射到该用户与 Bot 的共工私聊（不存在则创建）；须是 Bot 主人或已共享（`singleChatTarget`）。
- 共工 → 飞书：@Bot 或 @成员的网页消息由主应用发，用户授权过以本人身份发，否则代发「名字：…」；已绑定成员转成真正的飞书 @（`mirrorUserMessage`）。私聊的单聊只有 Bot 应用，以「名字：…」发。
- 撤回双向同步（`mirrorRecall`、`im.message.recalled_v1`）；共工编辑同步到飞书（`mirrorEdit`），排队中替换输入、运行中停止并重跑（`runs/stop.ts` 「消息已编辑，已重新运行」）；飞书没有编辑事件，飞书侧编辑不同步。
- 防回环：`feishu_message_links.feishuMessageId` 唯一，已映射或我方应用发出的事件丢弃；每群一个出站队列，按序执行（`enqueue`）。

## 卡片与事件
- 卡片一律中文（`cards.ts`），长内容截断后挂「查看过程」回链；无对外地址时不带链接。
- 运行卡片：CardKit 流式卡片回复触发消息，文字每 250ms 合并上屏，9 分钟重开流式；有待审批或提问时关流式以接收点击；无 CardKit 权限退回普通卡片 + 2 秒节流整卡更新（`mirror.ts`）。
- 审批、提问并入运行卡片（历史行可折叠），按钮经 `card.action.trigger` 回调，操作人与网页同权限；网页处理后飞书卡片同步更新（`onCardAction`）。
- 回复里的 actions 块渲染为按钮，html_render 页面附截图；预览、进度（`progress_card`）、填写密钥卡片各自镜像，密钥值只在共工页面填写。
- 状态表情：运行创建即在触发消息上加 `Typing`，结束撤掉，完成加 `DONE`（`kind='reaction'` 链接，重启可清理）。
- 无权触发时回提醒卡片（`noticeCard`）：未绑定给「绑定飞书账号」；非群成员且群在团队分区内给「申请加入」，否则请联系群管理员；群未关联、Bot 不在群也各有提示。
- Agent 工具：`list_feishu_messages` 以触发者身份实时读关联群，不入库；`feishu_send_card` 发自定义卡片（JSON 2.0，图片占位上传）；群未关联时两工具不下发，关联时系统提示词追加 `feishuHint`（`runs/scheduler.ts`、`agent-tools/feishu.ts`、`feishu/custom-card.ts`）。
- 飞书通知：个人设置开启 `feishu_identities.notify` 后，推送通知同时发到主应用私信；共享/入群申请卡片带同意/拒绝（`notifications/feishu.ts`）。新手群欢迎卡片发到已绑定新成员的私信（`teams/onboarding.ts`）。

## 飞书登录
- 主应用 OAuth（`auth/feishu.ts`），需主应用与对外地址都已配置（`feishuLoginReady`）；state、ticket 存内存 10 分钟。
- 已绑定直接登录；未绑定进 `/feishu/choose`：「绑定已有账号」（密码验证）或「新建账号」（无密码，按开户规则入默认团队）；停用账号拒绝登录。
- 新建账号受系统参数 `feishuAutoSignup`（默认开）控制，不受 `registrationOpen` 限制；关闭后只能绑定已有账号或凭团队邀请链接新建。
- 回链免登：飞书客户端内未登录自动走 `mode=silent`，按邮箱唯一匹配已有账号绑定，否则按开户规则直接新建，不出选择页（`LoginPage.tsx`）。
- 一个账号只绑一个飞书身份，反之亦然；个人设置可绑定（`mode=link`）、解绑，可用飞书头像；用户 token 临近过期自动刷新，刷新失败清空 token（`identity.ts` `userToken`）。

## 失败与降级
- 飞书调用一律尽力而为：失败只记日志，不影响共工侧（`enqueue`）。
- 飞书错误码映射为「发生了什么 + 怎么办」再附原码（`packages/protocol/src/feishu-errors.ts` `feishuErrorHint`），服务端报错用 `failFeishu`；群内失败发 `FeishuIssueEvent` 事件。
- 主应用调用失败（Secret 失效、飞书不可达）时，已关联群照常返回，带 `GroupFeishuView.feishuError`，顶部横幅提示，同步开关与取消关联仍可用；页面显示原因 +「重试」，系统管理员另有「去管理后台检查飞书」。
- Bot 入群失败原因只存内存，重启后丢失原因但仍显示未在群。

## 管理后台（`/admin/feishu`）
- 仅系统管理员；顺序：接入进度 → 对外地址 → 主应用 → Bot 表 → 飞书群表 → 账号（飞书自动开户）（`FeishuAdminPage.tsx`、`FeishuOverview.tsx`）。
- 接入进度四步：对外地址 → 接入主应用 → 审核通过 → 成员可用（除接入人外至少 1 人绑定飞书，`othersLinked`）；未达成给「复制登录地址」，全部完成收成一行。
- 数据来自 `GET /api/admin/feishu/overview`（`overview.ts`），不调飞书：`botsInChat` 恒为 null，失败原因只有本次启动以来记录的。
- Bot 表默认只列已接入的，「显示全部」展开；行操作接入 / 重试 / 更新权限，本页直接弹扫码窗。
- 飞书群表：共工群、团队、飞书群、关联时间、Bot 入群、最近失败原因；本人是群成员时可「打开群」。
- 应用接入、移除、群关联、同步设置、账号绑定解绑、开户开关都记审计（`admin/audit.ts`）。
