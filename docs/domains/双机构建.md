# 双机构建与测试

两台 Mac（雷电线直连，断开时走局域网）对等使用：坐在哪台前开发，哪台就是本机，另一台是对端（`gg-peer`）。两边环境与命令完全一致。

## 角色

| 角色 | 设置 | 本机跑 | 交给对端 |
|---|---|---|---|
| light（内存小的那台） | `scripts/peer-setup.sh light <对端>.local` | typecheck、lint、web/desktop/protocol 测试 | `cargo test`、server 测试 |
| heavy（内存大的那台） | `scripts/peer-setup.sh heavy <对端>.local` | typecheck、lint、`cargo test`、server 测试 | web/desktop/protocol 测试 |

`peer-setup.sh` 可重复执行：装齐 Node（与 CI 镜像同版本）、pnpm（`packageManager`）、rust-toolchain.toml 的工具链与两个 macOS target、PostgreSQL；写 `~/.config/gonggong/peer.env`（角色、主检出路径、PATH、测试槽位数：heavy 2 个，light 1 个）和 `~/.ssh/config` 里的 `gg-peer`（雷电固定地址 100ms 内能通就走雷电，否则走 `<对端>.local`）。雷电固定地址要各自执行一次脚本最后打印的 `sudo networksetup -setmanual "Thunderbolt Bridge" 10.99.0.x 255.255.255.0`（light 是 .1，heavy 是 .2）。

## 命令

- `pnpm check`：按上表自动分流，两台同时跑；对端不通、未设置时整份在本机跑。`--local` 强制全在本机。
- `scripts/peer.sh <命令>`：TDD 时把单条命令交给对端，输出与退出码原样返回，例如 `scripts/peer.sh pnpm --filter @gonggong/server exec vitest run test/x.test.ts`。对端不可用时退出码 75。
- `scripts/release.sh`：macOS 部分 x86_64 交给对端编译（gg 和 `tauri build --no-bundle`），本机编 aarch64；二进制传回后本机 `tauri bundle`、签名、两个架构并行公证。对端不在线时本机编两个架构。Jenkins 的 Mac 段调用的就是它，流水线不用改。

## 约定

- 对端副本在 `~/gg-peer/<本机名>-<worktree 名>`，是对端主检出的 git worktree，共用对端的 PostgreSQL（`.gonggong-dev/pg`）和 pnpm store；只当缓存，可随时删（删后 `git -C <主检出> worktree prune`）。
- 同步：rsync 发送工作区里未被 gitignore 的文件（含未提交改动），根 `.gitignore` 列出的路径在对端不会被删，对端保留自己的 `node_modules`、`target`；`pnpm-lock.yaml` 变了才在对端重新 `pnpm install`。
- 对端不放任何密钥：SSH 会话里登录钥匙串是锁的（`User interaction is not allowed`），签名、更新签名、公证都在发起构建的那台机器上。
- 重的测试按机器排队（`scripts/check.sh` 的 `serial`，`lockf` 锁在执行的那台机器上，两个方向和多个 Bot 共用）。
- 本地测试库关了落盘（`scripts/pg.sh`：`fsync`、`synchronous_commit`、`full_page_writes` 都是 off），机器断电可能丢本地开发数据。
