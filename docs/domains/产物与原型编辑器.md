# 产物与原型编辑器 · 现状

> 范围：产物托管（版本、同步、预览、分享、作品库）与原型编辑器（画布、直接编辑、批注、原型预览、导出），对标 Google Stitch。只写仍有效的决定，以代码为准，更新于 2026-11-20。

## 核心模型

- 真相源在服务端：每轮开跑前把 head 检出到 Bot 工作区，跑完上传为新版本；画布上的人工修改直接在服务端生成新版本。
- 只托管产物目录 `design/<slug>/`（`ArtifactDir`，同群唯一），不托管整个工作区；创建时预分配 `design/<模板>-<4 位随机>`（`plugins/creations.ts`）。
- 表 `artifacts`：群、插件版本、设计系统、`botId`（默认交给它改）、`headVersionId`、卡片 `messageId`、收藏屏 `favorites`、`checkoutBotIds`、`shareToken`、`visibility`、`archivedAt`（`db/schema.ts`）。
- 表 `artifact_versions` 不可变：产物内递增 `n`，`source` 为 `run | edit | local`，`submitKey` 幂等，`files[{path,hash,size}]`、`digest`、缩略图、每屏截图 `screenThumbs`、`stale`、`issues`。
- `artifacts.kind`（`prototype | site | slides | whiteboard | motion`，创建时由插件清单 `artifact.kind` 决定、托管网页为 `site`，不可改；随 `RunStart.artifacts[].kind` 下发）、`editor_version`（平台编辑器版本，原型/网页为空）。
- 批注统一为表 `artifact_threads` + `artifact_thread_messages`（`0120` 迁移迁入，`threads.ts`）：`anchor` 支持各类型结构化锚点（原型 `{file, ggId, selector, rect, snippet}`、幻灯片 `{slide, path?, point?}`、白板 `{element?, point}`、动效 `{t, point?}`、网页 `{path, point}`）与 open-artifact 编辑器的不透明原样字符串，并带 `label`、`detail`、`location`、`resolved_by`；首条消息即批注正文，可回复、表态（`reactions`）、改/删自己的消息（删首条即删整条）。状态 `open → sent → resolved`，发给 Bot 后记 `sentMessageId`（`commands.ts` `sendThreads`），变更经 `/ws/web` 推 `artifact.threads`。读用 `viewArtifact`（群外只读成员可看），写用 `requireArtifact`。原型画布仍走 `/api/artifacts/:id/annotations` 兼容接口（id 即 thread id）。旧表 `artifact_annotations` 保留一个版本便于回滚，不再读写。
- 统一产物容器 Shell（2026-11-23 S0，`features/artifacts/shell/`）：非原型产物（`site`、`slides`、`whiteboard`、`motion`）走 `ArtifactShell`（顶栏、批注/AI 对话/版本历史侧栏）；托管网页支持舞台坐标批注与版本回退；open-artifact 编辑器作为平台构建资产（`vendor/open-artifact/`，由 `scripts/build-open-artifact.sh` 构建进镜像 `/app/editors`）挂在预览域 `/__oa/<type>[@<ver>]/*`（`/__oa/.../project/*` 映射版本文件，带验证过的 CSP 与 `nosniff`），通过 postMessage 能力代理（`broker.ts`、`chrome.ts`）对接服务端 `POST /api/artifacts/:id/{publish,assets,agent-send}` 与版本历史 `history/files/diff/restore-files`，上传的媒体按 sha256 前 32 位 hex 经 `/_blob/<32hex>` 提供并在发布时并入版本；同一成员连续 `source=edit` 发布在 30s 停顿 / 5min 上限内合并；访客/只读视图仅授予 `user`、`artifact`（读）、`downloads`。
- 文件内容存独立 blob 目录 `<data>/artifacts/<groupId>/`，与强制同步分开，配额 5GB，版本引用的 blob 永久保留（`artifacts/blobs.ts`）。
- 上限：单文件 10MB、单版 200MB、最多 500 个文件；路径不得含点开头的段和 `node_modules`（`protocol/artifacts.ts` `ArtifactFiles`）。
- 结构 L1：`gg-artifact.json`（title、device `miniprogram|mobile|desktop`、entry、screens[id,title,file,statusBar,prompt,x,y]、refs）+ `tokens.css` + `DESIGN.md` + `screens/<id>.html` + `assets/` + `refs/`。
- 没有 `gg-artifact.json` 的按 L0 单页渲染（入口 `index.html`）。
- 外壳（设备框、状态栏、胶囊、跳转、`_gg/gg-kit.css|js`）属于平台，放在插件 `kit/`；AI 不写也不改。
- 可见范围三档 `private | group | team`，普通群默认 `group`，私聊默认 `private`；群外同团队成员（`team`）只读，对外/跨团队统一走分享链接（2026-11-23 方案 A 收口，存量 `all` 经 `0119` 迁移降级为 `team`）。
- 权限入口：只读接口用 `viewArtifact`；写、批注、导出、交给 AI 用 `requireArtifact`（`artifacts/service.ts`）。改可见范围限创建人、Bot 主人、群管理员（`isArtifactManager`）。
- 作品权限（2026-11-25，表 `artifact_members`，迁移 `0124`）：创建人只要还在团队里就始终可编辑，不论是否还在作品所在群；管理者（创建人、Bot 主人、群管理员，`ArtifactDto.canManage`）可在「分享产物」弹窗里给同团队的人单独授权「可看 `view` / 可协作 `edit`」（`GET/PUT/DELETE /api/artifacts/:id/members[/:userId]`，`works.ts`），不必进群，私密作品也对被授权的人可见。判定顺序见 `artifactAccess`：群成员（未被隐藏）→ 创建人 → 授权 → 团队可见只读；`listWorks` 与之一致；实时推送（`artifactAudience`、activity）带上创建人和被授权的人。群外的创建人和「可协作」的人也能用画布 AI 对话（仍是作品所在群里的那条隐藏话题）：`POST /api/artifacts/:id/chat` 对他们多返回群（`readerGroupDto`），发消息只放行到这条话题（`messages/routes.ts` `requireSender`），读话题走 `requireArtifact`；这条话题的消息和其 run 的实时事件额外推给他们（`messages/guests.ts`，按话题根与 run 缓存，授权变化时清空），群里其他内容不推。
- 移动到群（`artifacts/move.ts`）：管理者（同上）且是目标群成员，且禁止跨团队移动；同群、已删除、目标群已有同 `dir`、有进行中的 run 检出时拒绝。所有版本引用的 blob 复制到目标群存储（占目标群配额，源群副本保留），`groupId` 与预览行 `group_id` 原地改，版本、批注、`shareToken` 和分享链接不变；`checkoutBotIds` 清空；`botId` 保留（预览挂在它上面，产物预览读 blob 不经其电脑）；`visibility` 保留。目标群发新卡片、源群发移出通知，旧卡片不再刷新。源群工作区留下的 `design/<slug>/` 不再被强制同步排除，只是普通文件，不会被注册成新产物（产物只由服务端创建）。
- 左侧「作品」按当前团队（`X-GG-Team`）汇总可打开的产物（`works.ts` `listWorks`/`workGroups`，web `features/works/`）；私聊共享给团队时服务端对他人脱敏 `groupTitle`。「新建」可选群（跳到群聊创作）或与某个 Bot 的私聊（`/api/works/groups` 带 `kind`；不用建群，创作面板就在作品页打开，`POST /api/groups/:id/creations` 返回 `artifactId` 后直接进编辑器，web `works/NewWork.tsx`），默认上次所选；私聊里创作插件默认开启（`groupPluginLists`），产物默认仅自己可见。
- 作品点开一律进 `/works/:id`：可编辑的直接是编辑器（`WorkEditor` 复用 `ArtifactTab`，不打开群聊；删除回作品列表、移动后留在原页，见 web `artifacts/host.ts`），只读的是预览。讨论靠「分享到群聊」（`POST /api/artifacts/:id/post`，`works.ts` `postWork`）：能打开它的人发到自己所在的群，留一条带作品卡片的事件；发到作品所在群以外的群须同团队且作品为团队可见（界面上管理者一键改为团队可见），分享出的卡片不随版本刷新。
- 托管网页（`artifacts.site_dir` 非空，`artifacts/sites.ts`）：把 Bot 工作区里的静态构建目录（须含 `index.html`，不托管后端）存成 L0 产物，作品里打开、Bot 电脑离线也能访问。同群同 Bot 同目录只有一个，再次托管即新版本（`source=host`，以当前 head 为父、直接成为 head）。不检出进运行（`runArtifacts` 排除）、不做设计规范检查、不注入桥接；无扩展名的路径回退到 `<path>/index.html` 再到 `index.html`（SPA 路由）。
  - Bot：daemon 工具 `preview_host {dir,title}` → `POST /api/daemon/runs/:runId/sites` 取产物 → 机器级路由 `PUT/POST /api/daemon/artifacts/:id/{blobs/:hash,blobs/missing,versions}`（仅该产物 Bot 所在机器、仅托管网页）上传，随后后台截缩略图。
  - 成员：预览卡片「托管到服务器」（Bot 主人/群管理员，`POST /api/previews/:id/host`）：静态站点发 `site.host` 让 daemon 上传它服务的目录（daemon 需 `siteHost` 能力）；其他网页预览以该成员身份 @Bot 请它构建后用 `preview_host` 托管。

## daemon 与服务端同步

- `RunStart.artifacts`：触发消息引用的产物与 `artifact_checkout` 请求的产物一定下发，其余补本 Bot 的产物，最多 20 个（`RUN_ARTIFACTS_MAX`，`runArtifacts`）；只发给带 `artifacts` 能力的机器。
- `RunStart.artifactExclude` 列出群内全部产物目录，强制同步扫描跳过它们（`crates/gonggong/src/sync.rs`、`replicas.rs` `set_exclude`）。
- 开跑前：本地有未上传改动（离线、上次失败、手改）先以 `source=local` 上传；上传失败则本轮不检出该产物、目录原样保留（`crates/gonggong/src/artifacts.rs`）。
- 检出：digest 不同才拉清单和缺失 blob，先下载到 `.gg-checkout-*` 暂存目录再原子落盘；状态存 `<home>/artifacts/<id>/<folder>/state.json`，不放在工作区。
- 跑完：扫描、提交（带 `submitKey`），并按清单逐屏截图，入口屏截图兼作缩略图；上传失败不阻塞，下一轮开跑前用同一幂等键重试。
- daemon 路由只认本轮下发的产物（`runs.artifacts`）：`/api/daemon/runs/:runId/artifacts/:id/{blobs,versions}`；GET blob 只能取该产物版本引用的哈希（`routes.ts` `requireRunArtifact`/`referenced`）。
- 提交在 `submitVersion` 里锁产物行：父版本是 head → 成为新 head；同一 `submitKey` 重试 → 返回已有版本。
- 父版本是旧版本：按文件三方合并（`mergeFiles`）。run/local 的上传先留下 Bot 原稿作 stale 候选，合并结果另存为新 head。
- 不变量：返回给 daemon 的版本内容必须等于它本地的文件，否则下一轮会悄悄回退人工改动。
- 人工编辑（`onlyHead`）：不冲突就直接合并成 head；冲突返回 409「产物已有新版本」。
- AI 运行期间画布不锁：`ArtifactDto.running` 只表示有运行检出了它。
- 设为当前版本、采用候选、Undo/Redo 都走 `restoreVersion`：只移动 head，被采用的候选清掉 `stale`，不新建版本。
- 人工编辑或恢复版本后没有截图的，服务端发 `artifact.snapshot` 让 Bot 机器补拍；机器离线就等上线再拍（`snapshots.ts`）。没有截图时显示最近祖先版本的截图并标 stale。
- 旧 daemon（无 `artifacts` 能力）：创作指令回退为写 `design/<slug>/`、复制 kit 并用 `preview_static` 发布，不建产物。

## 渲染与桥接

- 产物预览是 `previews.kind='artifact'`：从服务端 blob 读，Bot 离线也能看；可以跟随 head，也可以固定到某个版本（`serve.ts`、`share.ts` `openArtifactPreview`）。
- L1 的 `/` 用插件**最新已审核版本**的外壳（`kit.ts` `currentShell`）；`_gg/*` 取产物自己插件版本的 kit；其余文件从版本 blob 读，并加 `nosniff`。
- 成员打开的屏幕 HTML 会被注入 `data-gg-id`（起始标签偏移，parse5 定位）和 `/__gg/bridge.js`（`html.ts` `injectBridge`），不改存储内容。
- 分享链接不注入桥接，访客访问 `/__gg/bridge.js` 返回 404。
- 桥接消息定义在 `BridgeToShell` / `BridgeFromShell`。主站只接受来自预览精确 origin、且 `source` 是对应屏幕 iframe 的消息（web `bridge.ts`）。
- 桥接消息只作界面提示；真正的修改都以 `(versionId, file, ggId)` 走服务端，由服务端重新定位和转义。
- 画布直接平铺各屏 iframe，不套外壳；外壳只用于新标签页、分享页和 Bot 本机截图。离开视口的屏换成截图（`Canvas.tsx` `nearView`）。

## 编辑器能力

- 工作台标签 `{kind:'artifact'}`（`app/workbench.ts`）→ `ArtifactTab`：画布（`Canvas.tsx`），以及原型预览/编辑（`PrototypeEditor.tsx`）。
- 画布节点：屏幕、设计系统、DESIGN.md、原型、参考文件；支持框选、右键菜单、⌘K、快捷键和屏间连线（`Links.tsx`）。
- 屏幕可以自由摆放，位置存在清单的 `x/y`（`screen-move`）。
- `POST /api/artifacts/:id/edits` 的 op：`text`、`attr`（`src/href/alt/data-gg-link/data-gg-transition`）、`style`（白名单 `STYLE_PROPS`）、`token`、`delete`、`asset`。
- 页面列表（左侧栏）：文件夹 `groups` 最多 7 级；页面可挂在另一个页面下当子页面（屏幕的 `parent`，最多 7 级，子页面不再单独属于文件夹，跟随顶层页面所在的文件夹；删除页面时其子页面顶到它的位置），拖到页面中部即挂到其下、拖到上下边缘为同级排序，菜单有「设为上一页的子页面 / 移出子页面」（`pages` op，`pageTree.ts`）。点文件夹画布只显示该文件夹的页面（含子页面），点某个页面画布只显示这一页，其余页面在「全部页面」里看；只看一页时交给 AI 新建的屏幕放在它旁边（`ArtifactCommandReq.page` 可为文件夹或页面 id）。
- 其余 op：`file`（整体替换 DESIGN.md / tokens.css）、`design-system`、`manifest`（rename/duplicate/delete/reorder）、`screen-move`、`ref*`。
- 一次保存最多 50 个 op，生成一版（source=edit）。同一文件内从后往前拼接，同一元素的 op 先合并，范围重叠的拒绝（`html.ts` `editHtml`）。
- 颜色只能取令牌（`styleValueOk` 对颜色属性只认 `var(--…)`）；改全局颜色走设计系统面板（`DesignSystemPanel.tsx`，预设来自插件 `designSystems`）。
- JS 生成或解析器自动补出的元素没有 `data-gg-id`，只能批注或交给 AI 修改。
- 交给 AI 都转成以当前用户身份发出的 @Bot 消息（画布上发的进产物的 AI 对话，不进群），正文给 agent 看、不翻译：批注发送、`ArtifactCommand` 指令、插件 `contributes.commands`、群输入框的画布上下文芯片 `ArtifactContext`（`commands.ts`、`ContextChips.tsx`）。
- 原型：外壳和编辑器都支持 `data-gg-link` 跳转与转场（`ArtifactTransition`）、连接/移除连接、扫码、新标签页；独立页的视图叫「总览 / 预览」。
- 热点默认关闭，点到非热点时闪现 0.8 秒。
- 导出（`export.ts`、`ExportPanel.tsx`）：zip（内嵌清单，双击 index.html 即可打开，不含未引用的 assets）、复制代码、实现提示词、项目简报（让 Bot 写 brief.md）、分享链接。
- 分享：只能由人在界面上开启，默认 7 天；可固定到某版本或跟随 head，可加 4 位密码（`share.ts`）。
- 规范校验 `lint.ts` 只提示不拦截，检查项：清单无效、屏文件缺失、写死色值、外部资源（含 img/srcset/url()）、改了外壳等。下一轮上下文最多附 20 条问题。
- 刻意不做：第三方导出（Figma、AI Studio 等）、Live 语音、Predictive Heatmap、六种配色方案自动推导、首页项目列表、.fig 导入、MCP/API（用实现提示词替代）、⌘S（修改即成版本）。
- 刻意不做：一个产物多个设计系统、版本对比。（独立 AI 对话已做，见「画布左侧栏」。）
- 产物内容约定（插件 SKILL.md 硬规则）：只用令牌；内容写成静态 HTML；不引入框架、CDN 和网络字体；图片下载到 `assets/`，不外链；顶层区块加 `data-section`；不改 `index.html` 和 `_gg/`。

## 屏内状态（2026-11-18）

- 同一屏的不同状态（订单阶段、空/失败、角色）做成屏内状态，不复制成多屏；版式不同或会被单独跳转的才新建屏。不做通用 tweak 参数面板。
- 模型在 `gg-artifact.json`（`protocol/artifact-states.ts`）：全局维度 `dims`（≤3，跨屏有效）+ 屏的 `uses`（用到哪些全局维度，没列的即「不适用」）+ 屏内维度 `screens[].dims`（≤2）；每个维度 2–8 个固定取值，第一个即默认。
- 屏里只写静态 DOM：`data-gg-when="order=unpaid|paid role=member"`（空格且、`|` 或）控制显隐，`data-gg-set` 切状态，与 `data-gg-link` 同在时带状态跳转；`data-gg-link` 的值保持纯屏幕 id（9 处按 id 读它）。
- 运行时 gg-kit.js 从页面 query 取状态，缺的维度同步读 `../gg-artifact.json` 取默认，用 `data-gg-off` 隐藏（桥接从 snippet 去掉、热区跳过）。外壳 `#play:<id>?k=v` 打开即该状态，工具栏下拉切换；画布节点标题与原型编辑器顶栏有状态菜单；截图与缩略图只拍默认状态。
- `gg-kit.js` 与外壳一样取插件最新上架版（只增不改），`gg-kit.css` 仍用产物自己的版本（`kit.ts` `LATEST_KIT_FILES`）。
- lint：条件写法错、维度/取值不存在、声明了没用到的维度。二期再做：状态矩阵、命名场景、评论/规则绑定状态、覆盖率视图。

## 页面业务规则与链接卡片

- 规则像原型备注一样跟页面走：每屏一份 `rules/<屏id>.md`，跨页规则一份 `rules/shared.md`（`## S1 标题` 分节，页面规则写「见 S1」引用）；随版本走，不进数据库（`protocol/artifact-rules.ts`）。
- 单条规则：`1. **元素名** \`#anchor\` [待确认]：一句话`；无锚点即整页。解析宽松（agent 也写），保存时规范化、编号按顺序。
- 规则挂在元素的稳定标记 `data-gg-anchor`（不是偏移 `data-gg-id`），重新生成页面不丢；桥接在 `ready/size` 上报 `anchors` 供画布画编号角标，`select` 带 `anchor`。
- 编辑：`file` op 整份写规则文件（空内容即删除），`attr data-gg-anchor` 打锚点，两者同一次保存只生成一版；删屏/复制屏同步规则文件。
- 画布：屏幕标题旁「规则 N · 待确认 M」，元素编号角标（蓝已定、黄待确认），「显示角标」开关存本地；「页面规则」侧栏列表/Markdown、选取元素添加规则、「AI 补全」（`complete-rules` 命令）；「共享规则.md」节点按普通 Markdown 渲染，引用关系计算得出不写回文件。
- 原型预览「标注」（`previewMarks.tsx`、`previewNotes.tsx`）：顶栏开关/`N`，状态存本地 `gg.art.previewMarks`（默认关）；元素角标画在设备外壳之上（不被胶囊遮挡、点角标不触发热点跳转、同位置自动错开），整页规则排在设备上方；锚点不可见（`anchors[].hidden`）不画角标、选中时滚过去，锚点缺失在侧栏标「元素已不存在」；侧栏列当前屏规则（Markdown、「见 S1」原地展开），窄舞台改为底部抽屉；角标/侧栏/页面元素三向联动，高亮按角标色（`highlight.tone`）；[ / ] 切换（←/→ 仅在焦点位于角标或侧栏时切换，否则 ← 仍返回上一屏）、Esc 先取消选中再关侧栏；焦点在屏内时桥接转发按键（`key`）；编辑模式不显示。
- 角标定位与避让在 `markLayout.ts`：角标中心离自身元素包围盒 ≤12px；大元素放右上角，矮元素（<32px）放元素外上方不盖文字；露出 <24px 视为不可见；被胶囊挡时换元素另一角；最多沿元素挪三次，仍冲突合成一组（编号升序，如 `3·4`，气泡里列出可选）；角标在屏幕上固定 18px、数字 11px，挤不下时只有同一元素或嵌套元素的规则成组（标签「5+2」），其余沿元素边缘避让。预览可缩放（适应 / 适应宽度 / 100%，无修饰键 0 / 2 / 1），放大后舞台可滚动（点击屏内不会带动舞台横跳，选中规则时舞台跟随到元素，整页规则胶囊固定在舞台左上，编辑菜单随舞台滚动）；桌面原型默认「适应宽度」（以侧栏左缘为界，不出现横向滚动），打开侧栏时自动收起屏幕列表；描边按缩放加粗，屏幕上保持 2px。同一元素的规则一律合成一个角标，嵌套元素在角标相撞时合并，其余元素靠避让（沿边、再向元素内阶梯），实在放不下才与相邻元素合并；角标最终夹在屏内且互不重叠，小元素内的角标缩为 14px。Esc 不抢已打开菜单/列表的按键，Shift 组合键不作快捷键。气泡为非模态弹层（role=dialog aria-modal=false），内容为纯文本，只含「在侧栏查看」或成组的规则列表。悬停或聚焦角标弹规则气泡（role=tooltip，Tab 可进入「在侧栏查看」，点击穿透到下方角标），空屏引导回画布并打开该屏「页面规则」（`CanvasRequest` `rules`）。画布不画 `hidden` 锚点，规则高亮同样按 tone 区分。
- 桥接 `ready` 带当前滚动位置，重新加载（含按 R）与返回上一屏都用 `scroll-position` 恢复离开时的位置，恢复完成前隐藏 iframe 并显示骨架；`scroll` 每帧最多一次；`scroll-to` 只滚屏内滚动容器和页面（不用 scrollIntoView），已完整可见不滚、否则就近滚动，fixed 元素不滚；锚点在 fixed/sticky 内时带 `fixed`、坐标为视口坐标；带色调的高亮画在独立覆盖层（`.gg-mark-box`，按滚动容器裁剪、fixed 元素用 fixed 定位）；按键只转发单字符、Esc、←/→（从不转发 Home），并跳过页面已处理的键、可交互控件和横滚容器内的 ←/→。桥接上报 `covers`（fixed/sticky 遮挡层，视口坐标），被遮住的元素不画角标；容器滚动时每帧重画描边并重新上报锚点；描边框挂在 documentElement 上、fixed 定位。
- 预览转场两层：离开的屏保留原 iframe（按 nav step 作 key，不重载、保留滚动位置）滑出，新屏加载完成前垫服务端截图（`protoParts.tsx` `useScreenSwap`）；减少动效时不做。
- 消费：画布指令、批注、画布上下文给 agent 的说明附选中屏的规则与引用的共享规则，待确认单列「未定」；实现提示词同样带上。lint 提示 `rule-anchor-missing`、`rule-shared-missing`。
- 链接卡片存在清单 `links`（url、title、display `embed|card`、ratio `16:9|4:3|3:4|1:1|free`、w/h、x/y），op `link`/`link-update`/`link-move`/`link-delete`。
- 嵌入卡片用 iframe 直接加载，只在选中时可交互；固定比例拖右下角只改宽，自由比例宽高都改。
- `POST /api/artifacts/:id/link-meta` 读标题并判断能否嵌入（X-Frame-Options / CSP frame-ancestors），复用群标签的 SSRF 防护抓取；飞书/Lark 域名不抓取、直接视为可嵌入，用浏览器里的飞书登录态加载，无权限时卡片里是飞书登录页。

## 画布左侧栏（2026-11-19，蒋庆提）

- 画布左侧固定栏（`PageRail.tsx`）：上方页面列表、下方「AI 对话 / 命令记录」两个标签（默认 AI 对话，记住选择 `gg.art.railLog`），默认 2:1、分隔条可拖（`gg.art.railSplit`）；默认展开、可收起（`gg.art.rail`），标签页宽度 <720px 时改为浮在画布上的抽屉、默认收起。原型编辑器不显示。
- 多级分类存在清单：`groups[{id,title,parent?}]`（≤50 个、最多 7 级，与墨刀一致，`pageGroupIssues` 校验）+ 屏幕 `group`；`screens` 的顺序即列表顺序，也是原型预览顺序。AI 改写清单时要保留（插件 SKILL.md）。
- 列表操作都走一个 `pages` op（整份分组 + 全部屏幕的新顺序与归属，屏幕集合必须与清单一致），一次一版；屏幕重命名/复制/删除仍用 `manifest` op。删除分类时子分类与页面上移一级。拖拽：页面拖到页面前插入、拖到分类行即移入；分类拖到分类即成为子分类，拖到空白处回顶层。
- 「分类」即「文件夹」（2026-11-19 蒋庆定，先叫「画布」，同日按墨刀改名「文件夹」）：列表顶部「全部页面」显示所有节点；点某个画布，画布只显示归属它的屏幕（不含设计系统、DESIGN.md、原型、参考、链接节点，自己的子画布的屏幕也不显示），当前画布按产物存在前端（`page.ts`），不持久化。画布菜单：添加子画布 / 上方添加画布 / 下方添加画布、上移 / 下移、移到顶层、重命名、删除；新建的画布为空并立即切过去。拖画布到另一画布行的上/下 1/4 处即放到它旁边，中间即成为子画布。焦点请求（点屏幕、运行卡片等）指向当前画布外的屏幕时先回到「全部页面」；点列表里的屏幕切到它所在的画布。
- 在某个画布里发的画布指令与带画布上下文的群消息带 `page`（分组 id），服务端在给 agent 的上下文里写明「新建的屏幕写 `"group": "<id>"`」；分组不存在时 400。
- 画布 AI 对话（蒋庆 2026-11-19 定，推翻「复用群聊、不做独立 AI 面板」）：每个产物一个隐藏对话，根是一条「自己是自己话题回复」的 event 消息（`meta.artifactChat`，`artifacts/chat.ts`，`POST /api/artifacts/:id/chat` 首次使用时建）。因此所有「只看主时间线」的过滤（时间线、未读、群上下文、飞书同步、话题列表）天然排除它；`threadRoot`/`requireRoot` 认 `isArtifactChat`，不加关注者、不同步飞书、不许 alsoSent，没 @ 时默认发给产物的 Bot。运行在对话里回复，用独立的话题会话。
- 画布与群聊严格分开（蒋庆 2026-11-19 定，不论是否全屏，画布是独立的设计软件）：画布下方有自己的输入框（`CanvasComposer`，标签页在前台且可编辑时，`useFrontCanvasChat`），只发到该对话；画布选区、⌘L、变体、`/` 产物命令都归它。群输入框始终发到群，画布在前台时不带画布选区；全屏时群输入框不再浮在画布上，要发群消息先展开聊天。画布指令、批注发送（`postAsMember`）也一律进对话。
- 画布输入框（蒋庆 2026-11-25 定）：左上角只列这条消息要改的页面名称（画布选区逐个列出、可移除；没有选区时取左侧列表里点开的那一页），不再显示「发给 @Bot」、变体、正在编辑；「设计系统」挪到输入框下方工具栏，最右侧（发送键左边）是模型选择，只显示模型名，可下拉换本条用的模型。带选区或单页发出的消息，服务端告诉 agent 只改这些屏幕、不动其他已有屏幕和 tokens.css 等全局文件（`contextLines` `scoped`，只对成员消息生效，画布指令不受影响）。
- 命令记录 `GET /api/artifacts/:id/history`（`history.ts`）：本群指向该产物的消息（`artifactRefs`、引用产物卡片、或触发的运行产出过它的版本），附运行状态、摘要与产出版本，最新 50 条；仅群成员（访客 403，栏里不显示）。点版本看该版本、点「执行过程」开运行标签、「定位消息」跳回群聊；head 或运行状态变化时刷新。

## 关键约束

- 安全：路径越界、非法资源、转义失败、越权一律 400/403 硬拒绝；只有设计规范类问题放行。
- 安全：`text` 做 HTML 转义；`href` 只接受相对路径或 http(s)，`src` 只接受相对路径或 https；整份 tokens.css 用 `tokensCssOk` 校验。
- 安全：上传的图片校验魔数和结构，拒绝 SVG（`edits.ts`、`images.ts`）。
- 预览域与主站隔离；源码查看接口 `/api/artifacts/:id/files/*` 固定返回 `text/plain` 并带 `CSP: sandbox`。
- 兼容：daemon 消息变化要同步 fixture 和 `crates/gonggong/src/protocol/`；截图依赖 Bot 机器上的 Chrome 系浏览器（`artifactSnapshot` 能力）。
- 已知遗留：清单 `gg-artifact.json` 两边都改时整文件冲突，后续可改为按字段合并。
