# 共工 快速开始

共工 让团队在一个网页群聊里指挥 AI 干活。你在群里 `@` 一个 bot 说需求，它会在**某位成员的电脑**上调用 Claude Code 或 Codex 真正动手（读代码、改文件、跑命令），过程和结果实时回到群里。

先认识三个词：

| 名词 | 是什么 | 打个比方 |
| --- | --- | --- |
| **daemon（gonggong）** | 装在你电脑上的小程序，负责接活、调用本机 AI | 你电脑上的「接单员」 |
| **bot** | 群里可以 `@` 的 AI 成员，固定跑在某台电脑上 | 一个 AI 同事 |
| **群** | 大家和 bot 一起聊天干活的地方，可绑定一个 git 仓库 | 项目群 |

整体流程：**登录网页 → 绑定电脑 → 建 bot → 建群拉 bot → @bot 干活**。

## 一、管理员：把服务跑起来（只做一次）

> 普通成员跳过本节，向管理员要「网址 + 账号 + 初始密码」即可。

需要先安装：

- **Node.js 22 或更高** 和 **pnpm**（`corepack enable` 即可，版本由 `package.json` 锁定）
- **PostgreSQL**（推荐 17）。`pnpm db:up` 直接调用本机的 `initdb` / `pg_ctl` / `psql`，**不用 Docker，也不需要启动系统里的 PostgreSQL 服务**：
  - macOS：推荐 [Postgres.app](https://postgresapp.com/downloads.html)（下载 dmg，把 Postgres.app 拖进「应用程序」即可，不用打开它）；或 `brew install postgresql@17`。两者都不需要手动加 PATH，脚本会自动找到
  - Debian/Ubuntu：`sudo apt install postgresql`，再把 `/usr/lib/postgresql/<版本>/bin` 加入 PATH

数据库建在仓库内的 `.gonggong-dev/pg`，监听 54329 端口，自动创建 `gonggong` 与 `gonggong_test` 两个库；停止用 `pnpm db:down`。服务器启动时会自动建表，无需手动迁移。

```bash
pnpm install
pnpm db:up                                   # 启动数据库
GONGGONG_ADMIN_PASSWORD=初始密码 pnpm dev:server   # 启动服务器（默认 8787 端口）
pnpm dev:web                                 # 启动网页（默认 http://127.0.0.1:5173）
```

1. 浏览器打开网页，用账号 `admin` + 上面的初始密码登录，按提示**修改密码**。
2. 进入「管理 → 账号与角色」，给每位成员建账号，把网址、账号、初始密码发给他们。

**局域网内其他电脑加入**：daemon 只允许通过 https 连接非本机服务器，所以要带证书启动（服务器与网页共用同一份证书）：

```bash
bash scripts/dev-cert.sh                     # 生成含本机局域网 IP 的自签证书，打印两个环境变量和指纹
export GONGGONG_TLS_CERT=… GONGGONG_TLS_KEY=…         # 粘贴上一步打印的值
GONGGONG_ADMIN_PASSWORD=初始密码 pnpm dev:server
WEB_HOST=0.0.0.0 pnpm dev:web                # 对局域网开放，网址为 https://<本机局域网 IP>:5173
```

成员用这个网址登录（浏览器会提示证书不受信任，确认继续即可），「绑定新机器」里复制的命令会自动带上该地址；把上面打印的指纹公布给成员核对。服务器本身仍只监听本机，由网页端口统一转发。

**Bot 发布的预览（网页、服务）**：局域网内每个预览占用服务器的一个端口（默认 41000-41099，可用 `GONGGONG_PREVIEW_PORTS` 调整），需要让预览端口对局域网开放：启动服务器时加上 `GONGGONG_PREVIEW_HOST=0.0.0.0`。正式部署建议改用泛域名：设置 `GONGGONG_PREVIEW_DOMAIN`（**必须是与主站不同的独立域名**，如主站 `gg.example.com`、预览 `example-preview.com`，并配置 `*.example-preview.com` 的 DNS 与证书）和 `GONGGONG_PUBLIC_URL`（主站地址），详见 `docs/plan/结果预览-开发计划.md`。

正式部署（HTTPS、密钥、备份）见 `docs/plan/安全说明.md`、`docs/plan/发布与平台说明.md`。

## 三、安装 gonggong

gonggong 就是**一个可执行文件**，没有安装向导，放到命令行能找到的目录即可。按你的情况选一种：

| 你的情况 | 选哪种 |
| --- | --- |
| 管理员已经给了安装包 | **方式 A** |
| 手上有源码，想自己编译 | **方式 B** |
| 用 Mac，不想开终端窗口 | **方式 C**（桌面端） |

> 网页「绑定新机器」里的「下载」按钮暂未开放，目前只能用下面三种方式。

### 方式 A：用管理员给的安装包

文件名形如 `gonggong-0.1.0-<系统>-<架构>`，按电脑选：

| 电脑 | 文件 |
| --- | --- |
| Apple 芯片的 Mac（M1/M2/M3…） | `gonggong-<版本>-macos-aarch64` |
| Intel 芯片的 Mac | `gonggong-<版本>-macos-x86_64` |
| Linux（x86 服务器/PC） | `gonggong-<版本>-linux-x86_64` |
| Linux（ARM） | `gonggong-<版本>-linux-aarch64` |
| Windows | `gonggong-<版本>-windows-x86_64.exe` |

不确定芯片：Mac 点左上角  →「关于本机」；Linux 执行 `uname -m`。

**macOS / Linux：**

```bash
mkdir -p ~/.local/bin
mv ~/Downloads/gonggong-0.1.0-macos-aarch64 ~/.local/bin/gg   # 换成你拿到的文件名
chmod +x ~/.local/bin/gg
xattr -d com.apple.quarantine ~/.local/bin/gg 2>/dev/null  # 仅 macOS：去掉“来自互联网”标记，否则会被系统拦截
```

如果 `~/.local/bin` 还不在 PATH 里，把它加进去（zsh 为例，bash 改成 `~/.bashrc`）：

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc && source ~/.zshrc
```

**Windows：** 新建文件夹如 `C:\Users\<你>\gonggong\`，把 exe 改名为 `gg.exe` 放进去，并把该文件夹加入「系统环境变量 → Path」。它是命令行程序，双击不会启动，请在 PowerShell 或命令提示符里运行下文的 `gg login`、`gg run`。（已在 Windows 11 真机上验证绑定与 Claude Code 运行，遇到问题请反馈。）

> 请放在**自己有写权限的目录**（如 `~/.local/bin`），不要放 `/usr/local/bin` 这类需要 sudo 的地方：有新版本时 gonggong 会自动下载并替换自己（优先用服务器发布的版本；服务器没发布时每 6 小时查一次 GitHub Releases，`GONGGONG_UPDATE=off` 可关闭），没有写权限就无法升级。

可选：核对文件完整性（管理员会一并给出 `SHA256SUMS`）：

```bash
shasum -a 256 ~/.local/bin/gg   # 结果应与 SHA256SUMS 中对应一行一致
```

### 方式 B：从源码自己编译

**1. 装 Rust**（只需一次）：

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source ~/.cargo/env
rustc --version    # 需要 1.95 或更高；已装过 Rust 的执行 rustup update stable 升级
```

另外需要 C 编译器（加密库要用）：macOS 执行 `xcode-select --install`；Ubuntu/Debian 执行 `sudo apt install build-essential`。

**2. 编译并安装：**

```bash
cd ai-chat-master                        # 项目源码根目录
cargo build --release --locked -p gonggong   # 首次约几分钟
mkdir -p ~/.local/bin
cp target/release/gg ~/.local/bin/gg
```

PATH 设置同方式 A。本机编译的文件不会被 macOS 拦截，不需要 `xattr` 那一步。

**管理员批量打包（给全员分发）**：在 Mac 上执行

```bash
bash scripts/release.sh                                  # 全部平台 + 桌面端
bash scripts/release.sh --only macos-aarch64,desktop     # 只打部分
```

产物在 `dist/<版本>/`：各平台 `gonggong-*` 文件、`SHA256SUMS`、`manifest.json`、macOS 桌面端 `.dmg` 与更新包，以及 GitHub 发布用的 `github/` 目录。打桌面端需要更新签名密钥（见 `docs/plan/发布与平台说明.md`）。Linux / Windows 版在 Docker 里交叉编译，需要本机装好 Docker；macOS 版需要 `rustup target add aarch64-apple-darwin x86_64-apple-darwin`。把对应文件发给成员即可（发布到服务器、让已装的 gonggong 自动升级见 `docs/plan/发布与平台说明.md`）。

### 方式 C：macOS 桌面端

桌面端自带 gonggong，**不需要**再装命令行版本，也不用一直开着终端窗口。

- 从 [GitHub Releases](https://github.com/yoqu/gonggong-space/releases/latest) 下载 `Gonggong_<版本>_<架构>.dmg`（或由管理员用 `bash scripts/release.sh --only desktop` 打包），双击后把 **共工空间** 拖进「应用程序」。
- 之后的版本由桌面端自己更新：启动时和每 6 小时检查一次，后台下载完提示「立即重启」；也可在「设置 → 版本」手动「检查更新」。v0.1.0 不会自动检查，需要手动下载一次 v0.2.0。
- GitHub 上的安装包已签名公证；自己打包且没有 Developer ID 证书时，第一次打开 macOS 会提示「无法打开」：在「系统设置 → 隐私与安全性」底部点「仍要打开」（或在「应用程序」里右键图标 → 打开）。
- 打开后按引导粘贴绑定命令即可（见第五节）。关掉窗口后程序仍在菜单栏运行，要停止请在菜单栏图标里选「退出」。

### 装好后检查

```bash
gg --version   # 能打印版本号说明装好了
gg agents      # 能列出 Claude Code / Codex 说明 AI 工具也就绪
gg doctor      # 绑定后再跑一次，检查连接、git 凭据、磁盘等
```

提示 `command not found` 说明 PATH 没配好，重新打开终端或检查上面的 PATH 设置。

如果 `gg` 打开的是 git 图形界面，说明 oh-my-zsh 的 git 插件把 `gg` 设成了 `git gui citool` 的别名：在 `~/.zshrc` 末尾加一行 `unalias gg 2>/dev/null` 后重开终端（临时绕过可用 `command gg …`）。

> 首次运行时 gonggong 会用 npm 自动下载 AI 适配器到 `~/.gonggong/adapters/`，所以要能访问 npm 源。gonggong 的所有本地数据都在 `~/.gonggong/` 目录。

## 五、绑定你的电脑

1. 网页右上角点**头像 → 绑定新机器 → 生成绑定码**。
2. 点「复制命令」，在你电脑的终端里粘贴执行，形如：
   ```bash
   gg login --server https://服务器地址 --code 绑定码
   ```
   看到「绑定成功」即可。（用桌面端的话，直接把命令粘贴进桌面端。）
3. 启动接单：
   ```bash
   gg run
   ```
   **这个窗口要一直开着**，关掉后你的 bot 就「离线」了（消息会排队，最多等 30 分钟）。桌面端用户跳过这一步，App 在运行就行。

> 绑定码只能用一次、会过期；失效了重新生成即可。
> 首次绑定会打印一个证书指纹，请与管理员公布的对一下，不一致就执行 `gg logout` 并联系管理员。

## 六、创建你的 bot

1. 头像 → **我的 bot 与用量 → 新建 bot**。
2. 填写：
   - **名称**：群里 `@` 它用的名字，如 `后端助手`
   - **执行机器**：选你刚绑定的电脑
   - **Agent**：Claude Code 或 Codex
   - **系统提示词**（同时作为群内简介）：告诉它角色，如「后端接口开发，只改 server/ 目录」
3. 点「创建并绑定」。

创建后可在 bot 详情里调整：

| 设置 | 含义 | 建议 |
| --- | --- | --- |
| 触发范围 | 谁能 `@` 它干活：任何群成员 / 指定名单 / 仅本人 | 刚开始用「仅本人」最安全 |
| 默认权限档位 | 它能动多大范围；`full` 档强制只能指定名单触发 | 保持默认 |
| 并发上限 | 同时最多跑几个任务 | 保持默认 |

## 七、建群并开始干活

1. 左侧栏点 **新建群**（只想自己用就点 **新建私聊**）。
2. 填群名；如果要改代码，填 **git 仓库地址**并点校验；拉入你的 bot。
3. 在输入框里 `@bot名 你的需求`，例如：
   ```
   @后端助手 看一下登录接口为什么偶尔 500，找到原因后修复并跑测试
   ```
4. 回车后群里会出现**运行卡片**，点开右侧栏能看到：
   - **过程**：它每一步在想什么、做了什么
   - **diff**：改了哪些代码
   - **审批**：需要你批准的操作

没有 `@` 的消息不会触发 bot，只作为上下文补给它。可以发图片和附件（单个 ≤ 50 MB，每条 ≤ 10 个）。

### 多个 bot 改同一份代码：强制同步

默认是**分区模式**：每个 bot 在自己的工作区里干活，代码靠 git 交换。想让群里几个 bot 始终看到同一份文件，可以切到**强制同步**（群必须绑了仓库）：

1. 群管理员打开 **群设置 → 同步模式 → 切换为强制同步**，选一个**基准 Bot**（它当前的工作区生成第一个版本），看一眼每个 bot 的处理方式后点 **确认切换**。工作区干净的 bot 会对齐到这个版本（被覆盖的文件先备份）；有未提交改动或用了 `/cd` 的 bot 暂不参与。
2. 之后照常 `@bot` 干活，可以同时 @ 多个。每轮结束后改动自动提交为新版本并分发给其他 bot；改的是不同文件，或同一文件的不同位置，都会自动合入。
3. 群顶部状态栏如 `强制同步 · v17 · 4/5 一致`：v17 是最新版本，4/5 是已经和它一致的 bot 数；后面的 `1 冲突`、`1 本地有改动`、`1 落后` 等提示有 bot 需要关注。点状态栏打开**同步面板**，可看每个 bot 的状态和版本历史。
4. **本地有改动**：你在电脑上直接改了某个 bot 的工作区，它会暂停接收新版本并通知 bot 主人。在同步面板里选 **提交本地改动**（作为一个新版本发给大家）或 **丢弃本地改动**（先备份，再回到最新版本）。
5. **冲突**：两个 bot 改了同一文件的同一处，后提交的一方会挂起，群里出现冲突卡片。bot 主人或群管理员点 **处理**，逐个文件选「保留我的 / 采用最新 / 交给 Bot 合并」，或整版丢弃。处理完之前，这个 bot 在本群的新任务会排队。
6. `/stop` 打断一轮时，改动先不提交，由发起人在运行卡片上选「保留」（提交为一版）或「丢弃」（备份后回滚）。

不需要时，群管理员在同一处点 **切回分区模式**，各 bot 保留当前文件各自干活。备份都在本机，桌面端「工作区」页可以找到。

## 八、要你拍板的时候

- **权限请求**：bot 想执行命令、写文件、访问网络等超出权限的操作时，会弹出卡片，**只有 bot 主人**能点「批准 / 拒绝」。超时未处理会自动拒绝，bot 会自己想别的办法。
- **向群成员提问**：bot 拿不准时会出选择题，发起人或 bot 主人作答即可。
- 右上角的**通知中心**会提醒你待处理的事。

## 九、常用指令

在输入框输入 `/` 会弹出候选：

| 指令 | 作用 |
| --- | --- |
| `/stop` | 停止运行；`/stop @bot` 只停某个 bot，不带 @ 则停本群全部 |
| `/new` | 开一个新会话（让 bot 忘掉之前的上下文） |
| `/cd` | 让 bot 直接在你本机某个目录里干活（仅分区模式；`--reset` 恢复） |

另外：运行中再发一条消息可以**打断并追加**要求；引用某条消息回复可以让 bot 针对它继续。

## 十、常见问题

| 现象 | 处理 |
| --- | --- |
| bot 显示离线 / 消息一直排队 | 确认电脑上 `gg run` 还在运行 |
| 绑定时报证书错误 | 核对管理员公布的指纹，或按管理员给的 `--fingerprint` 参数绑定 |
| 新建 bot 时看不到 Claude Code / Codex | 先在终端装好并登录，然后重启 `gg run` |
| 不知道哪里出问题 | 运行 `gg doctor` 自检；`gg logs --export` 导出诊断包发给管理员 |
| 想查本机绑定状态 | `gg status` |
| 换电脑 / 不用了 | `gg logout` 解除本机绑定 |
