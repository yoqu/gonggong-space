# v0.4.14

本次把共工托管的工作区从隐藏目录搬到可见的 `~/gonggong/workspaces`，按群名与 Bot 名命名；Docker 机器也可以在网页上一键升级。

This release moves managed workspaces out of the hidden directory into a visible `~/gonggong/workspaces`, named after the group and Bot, and lets Docker machines be upgraded from the web.

## 工作区 / Workspaces

- 托管工作区改放在 `~/gonggong/workspaces/<群名>/<Bot名>/<仓库名>`（Docker 里是 `/home/gg/gonggong/...`），名字在创建时确定，之后群或 Bot 改名不搬目录；同名的自动加 `-2`。
  Managed workspaces now live in `~/gonggong/workspaces/<group>/<bot>/<repo>` (`/home/gg/gonggong/...` in Docker). Names are fixed when created, so renaming a group or Bot later moves nothing; duplicates get a `-2` suffix.
- 已有的克隆在该 Bot 下一次运行或绑定、且没有任务在用时原地搬过去，未提交的改动、分支与 stash 都保留；搬不动（如跨盘）时留在原处继续使用。搬迁后的第一次运行会开新会话。
  Existing clones move on the Bot's next run or bind when nothing is using them, keeping uncommitted changes, branches and stashes; if a move isn't possible (e.g. across disks) the clone stays where it is. The first run after a move starts a new session.
- 目录选择器左侧新增「隐藏文件夹」快捷入口，并且不能再选共工托管的工作区（原群删除 Bot 或清理空间时会被删掉），提示把仓库克隆到 `~/code` 等目录。
  The directory picker adds a Hidden folders shortcut and no longer lets you pick managed workspaces (they are deleted when the original group removes its Bot or storage is cleaned up); clone the repository to a folder such as `~/code` instead.

## 机器 / Machines

- Docker 机器的 `gg` 放在数据卷里运行，可以在网页「立即升级」，重建容器后升级结果仍在；用旧镜像建的容器需要按部署文档手动重建一次。
  Docker machines run `gg` from the data volume, so they can be upgraded from the web and keep the upgrade across container rebuilds; containers built from older images need one manual rebuild following the deployment docs.

## 画布 / Canvas

- 画布可以拖动屏幕自由摆放，工具栏新增刷新按钮。
  Screens can be dragged to place them freely on the canvas, and the toolbar adds a refresh button.
