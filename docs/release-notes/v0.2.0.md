多台机器上的 Bot 现在可以在同一个群里共用一份工作区：强制同步让大家改同一个仓库而不互相覆盖。另有定时任务、飞书联动、演示模式，以及从这个版本开始的自动更新。

Bots on different machines can now share one workspace per group: force sync lets everyone change the same repository without overwriting each other. Also new: scheduled tasks, Feishu (Lark) integration, demo mode, and auto update from this version on.

## 亮点 / Highlights

- **强制同步 / Force sync** —— 乐观并发替代群锁：每轮开跑前补齐到最新版本，结束后逐路径提交；别人先改了同一文件就自动三方合并，合并不了的交给管理员或 Bot 主人逐文件选「保留我的」「采用最新」或交给 Bot 合并。群顶部状态栏与同步面板显示版本与各副本状态；离线机器上线后补齐，本地手改可提交或丢弃，疑似密钥文件不会被同步。已在两台机器间跨机验证（含 10 万文件仓库）。
  Optimistic concurrency instead of a group lock: each run catches up first and commits per path when done; concurrent edits are merged three-way automatically, and what cannot be merged goes to the admin or Bot owner to resolve file by file. Status bar and sync panel in the group; offline catch-up, local edits kept or discarded, likely secret files never synced. Tested across two machines, including a 100k-file repository.
- **定时任务 / Scheduled tasks** —— 群与私聊可挂定时任务，到点 @ 候选 Bot 中最合适的一个执行；Agent 也能通过内置 MCP 创建。
  Groups and DMs run tasks on a schedule, handed to the best-suited Bot; agents can create them through the built-in MCP.
- **团队层级 / Teams** —— 多团队切换，Bot 归团队、机器归个人。
  Switch between teams; Bots belong to a team, machines to a person.
- **飞书联动 / Feishu (Lark)** —— 扫码一键创建应用、飞书登录与群绑定；运行卡片流式打字机上屏，Bot 接手即加表情、结束留 DONE；预览卡片同步到飞书。
  One-scan app setup, Feishu login and group binding; streaming run cards, status reactions, preview cards in Feishu.
- **演示模式 / Demo mode** —— 后台一键开启，限制公开链接、远程操作、完全访问档位与改密码，适合公开演示。
  One switch in the admin console limits public links, remote control, full access and password changes for public demos.
- **自动更新 / Auto update** —— `gg` 在服务器没有发布版本时每 6 小时检查 GitHub Releases，空闲时自升级（`GONGGONG_UPDATE=off` 关闭）；macOS 桌面端后台下载新版本，提示「立即重启」，也可在「设置 → 版本」手动检查。
  `gg` checks GitHub Releases every 6 hours when the server publishes no build and upgrades itself when idle (`GONGGONG_UPDATE=off` to disable); the macOS app downloads updates in the background and offers a restart, or check by hand in Settings → Version.

## 升级须知 / Upgrade notes

- **v0.1.0 需要手动更新一次**：v0.1.0 的 `gg` 与桌面端不会检查 GitHub，请手动下载本版本替换；从 v0.2.0 起会自动更新。自托管服务器在后台「客户端发布」上传过版本的，成员的 `gg` 照旧从服务器升级。
  **Update v0.1.0 by hand once**: v0.1.0 `gg` and the desktop app do not check GitHub, so download this release manually; from v0.2.0 on updates are automatic. If your server publishes builds (Admin → Client releases), `gg` keeps upgrading from it.
- **强制同步要求 v0.2.0**：群切换到强制同步前，参与的成员都要把 daemon / 桌面端升级到 v0.2.0，旧版本无法加入同步。
  **Force sync needs v0.2.0**: every member taking part must run daemon / desktop v0.2.0 before a group switches to force sync; older versions cannot join.
- 服务端升级后会自动执行数据库迁移。/ The server applies database migrations automatically on start.
