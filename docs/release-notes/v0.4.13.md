# v0.4.13

本次修复自建 GitLab 使用 `http://` 克隆地址时的令牌认证问题，并改进多屏画布性能与数据库备份保留策略。

This release fixes token authentication for self-hosted GitLab repositories using `http://` clone URLs, and improves multi-screen canvas performance and database backup retention.

## Git 访问 / Git access

- 机器「Git 访问」中保存的 HTTPS 令牌现在也用于同一主机的 `http://` 仓库地址，修复自建 GitLab 克隆时报 `could not read Username`。
  HTTPS tokens saved in a machine's Git access settings now also work for `http://` repository URLs on the same host, fixing `could not read Username` when cloning from self-hosted GitLab.
- 升级后请重新保存一次该主机的令牌，让 daemon 同时保存 HTTP 与 HTTPS 两份凭据。
  After upgrading, save the host's token once more so the daemon stores credentials for both HTTP and HTTPS.

## 画布与服务端 / Canvas and server

- 多屏画布只绘制可视区域内的屏幕，拖动与缩放时临时使用截图，停止交互后恢复页面。
  Multi-screen canvases render only visible screens and temporarily use screenshots while panning or zooming, restoring live pages when interaction stops.
- 画布跳转连线默认隐藏，可按需开启并记住选择。
  Canvas jump links are hidden by default and can be enabled when needed; the preference is remembered.
- 数据库备份保留最新 7 份及最近 7 天每天最新一份，发版前备份不再挤掉当天的历史备份。
  Database backups retain the newest seven plus the newest backup from each of the last seven days, so pre-release backups no longer remove that day's history.

## 升级 / Upgrade

- 服务君CC 等需要访问自建 GitLab 的机器，请先升级 daemon，再到「机器管理 → Git 访问」重新保存 `gitlab.crm.luxelakes.com` 的令牌，然后重新绑定仓库。令牌需要 `read_repository` 权限；如需推送，还需 `write_repository`。
  For machines such as 服务君CC that access self-hosted GitLab, upgrade the daemon first, then save the `gitlab.crm.luxelakes.com` token again in Machines → Git access and rebind the repository. The token needs `read_repository`; add `write_repository` for pushes.
- HTTP 会以明文传输令牌；GitLab 支持 HTTPS 时，建议仓库地址统一使用 HTTPS。
  HTTP transmits tokens in plaintext. Use HTTPS repository URLs whenever GitLab supports HTTPS.
