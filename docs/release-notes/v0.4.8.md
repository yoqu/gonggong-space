# v0.4.8

本次增强 Claude Code 的本机配置复用与官方登录设置。

This release improves local configuration reuse and official-login settings for Claude Code.

## 本机配置目录 / Local configuration directory

- 新增 Claude Code 自定义供应商时，可选择使用本机 Claude 配置目录，沿用该目录已有的登录和 `settings.json`，并可选指定 Claude 可执行文件。
  Custom Claude Code providers can use a local Claude config directory, reusing its existing login and settings.json, with an optional Claude executable.
- 共工保存目录路径而不复制其中的密钥；已有会话继续使用原供应商，新会话才使用新配置。
  Gonggong stores the path without copying its secrets. Existing sessions keep their provider; new sessions use the new configuration.

## 官方登录参数 / Official-login arguments

- 「官方登录 → 设置…」新增「命令行参数」，每行一个，支持 `--flag 值`、`--flag=值` 或不带值的 `--flag`；参数内容不写入日志。
  Official login settings now accept CLI arguments, one per line, in `--flag value`, `--flag=value` or value-less `--flag` form. Argument contents are not logged.
- `--settings` 不会重复传给 CLI；daemon 读取文件或内联 JSON，并合并进共工生成的设置，冲突时共工管理项优先。
  --settings is not passed to the CLI twice; the daemon reads the file or inline JSON and merges it into Gonggong-generated settings, with Gonggong-managed values taking precedence.
- 共工自己管理的权限、模型、会话、MCP、插件、附加目录、提示词、输入输出格式和工具开关参数不能在此设置。
  Arguments managed by Gonggong cannot be set here, including permissions, models, sessions, MCP, plugins, additional directories, prompts, input/output formats and tool switches.

## 升级 / Upgrade

- 请先部署最新服务端，再升级桌面端与 daemon；上述功能需要新版 daemon，旧 daemon 保存相关设置时会提示升级。
  Deploy the latest server before upgrading desktop clients and daemons. These features require the new daemon; older daemons will ask for an upgrade when saving these settings.
