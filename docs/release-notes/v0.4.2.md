# v0.4.2

本次主要减少只读操作反复申请权限，并让审批原因更清楚。

This release reduces repeated permission prompts for read-only work and explains why remaining approvals are required.

## 审批优化 / Approval improvements

- Codex 的「工作区写入」档现在使用 `workspace-write`：工作区内常规读写和命令不再因错误映射为只读模式而反复审批；越界写入和网络访问仍由主人确认。「只读」和「全部权限」档保持原有边界。
  Codex workspace mode now uses `workspace-write`, avoiding repeated prompts caused by the former read-only mapping. Out-of-scope writes and network access still require owner approval; read-only and full-access tiers retain their boundaries.
- `rg`、读取用的 `sed`、不删除或执行命令的 `find`，以及 `ps`、`jq`、`diff`、`stat`、`du`、`which` 等常见只读命令可自动放行。写入文件、执行命令、命令替换和复杂脚本仍保守审批。
  Common read-only commands including `rg`, non-writing `sed`, non-destructive `find`, `ps`, `jq`, `diff`, `stat`, `du` and `which` can be approved automatically. File writes, command execution, substitutions and complex scripts still require approval.
- 读取/搜索工具仅在工作区及附加目录内免审；目录外路径和软链接逃逸仍需审批。
  Read/search tools are exempt only inside the workspace and its additional directories. External paths and symlink escapes still require approval.
- 审批卡显示网络、写入、高危命令、基准分支或无法解析等原因。
  Approval cards now identify network access, writes, dangerous commands, protected branches or unparsed commands as the reason.

## 升级 / Upgrade

- daemon 需要升级到 v0.4.2 才会使用新的审批规则。Codex ACP 适配器升级为 2.2.2；使用 Codex 需要 CLI ≥ 0.160.1。
  Upgrade daemons to v0.4.2 for the new approval rules. The Codex ACP adapter is now 2.2.2 and Codex CLI 0.160.1 or later is required.
- 服务端部署时自动执行迁移 `0081`，给 `approvals` 新增 `reason` 列，只新增带默认值的列，不改写旧数据。
  Server deployment automatically runs migration `0081`, adding `approvals.reason` with a default and without rewriting existing data.
- 已安装 v0.2.0 及以上客户端可自动更新。
  Clients on v0.2.0 and later can update automatically.
